# Repository Instructions

## Commit Convention

Follow repository rules first. If no narrower rule applies, write Git commit messages in this format:

```text
type: short imperative subject
```

Use common types such as `feat`, `fix`, `docs`, `chore`, `refactor`, `test`, `build`, `ci`, and `perf`.

Before committing, inspect the real diff, stage only relevant files, run available validation, and avoid committing unrelated user changes.
