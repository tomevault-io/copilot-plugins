# Base for Start 작업 지침

## 프로젝트 목적

- 이 저장소는 코딩 초보자가 자신의 첫 웹페이지를 수정하고 배포하는 연습용 베이스다.
- 사용자가 직접 문법을 배우기보다 원하는 내용을 말하고 결과를 확인하는 흐름을 우선한다.
- 첫 완료 경험은 `화면 수정 → GitHub push → Vercel 자동 배포 → URL 공유`다.

## 작업 전 확인

- 모든 작업 전에 `PROJECT_BRIEF.md`를 확인한다.
- 프로젝트 시작 인터뷰는 `guides/project-start-flow.md`를 따른다.
- 오늘의 주문 인터뷰는 `guides/order-flow.md`를 따른다.
- 날짜별 주문 기록은 `orders/`에서 확인한다.

## 범위 통제

- 한 번에 한 가지 작은 작업만 처리한다.
- 요청하지 않은 기능과 관련 없는 리팩터링을 추가하지 않는다.
- 기존에 동작하는 화면과 배포 흐름을 유지한다.
- 새로운 production dependency가 필요하면 설치 전에 이유를 설명하고 확인받는다.
- 복잡한 상태 관리, 조기 추상화, UI 라이브러리를 추가하지 않는다.
- 사용자의 요청이 크면 첫 번째 완료 단위만 제안한다.

## 기술 원칙

- Next.js 16 App Router, React, TypeScript, npm을 유지한다.
- 이 단계에서는 Supabase, 데이터베이스, 인증, 환경변수, Server Actions, `proxy.ts`를 추가하지 않는다.
- 입력 폼이 실제로 저장되는 것처럼 보이는 가짜 기능을 만들지 않는다.
- 모바일에서도 읽기 편한 접근 가능한 HTML과 단순한 CSS를 사용한다.
- 초보자가 파일 역할을 찾기 쉬운 짧고 명시적인 구조를 유지한다.

## 문서와 대화 원칙

- 대화는 기본적으로 한국어로 진행하고 질문은 한 번에 하나씩 한다.
- 사용자가 이미 말한 내용은 다시 질문하지 않는다.
- 코드 작업 전 주문 내용을 문서로 정리해 확인받는다.
- 설명은 짧고 구체적으로 작성한다.
- 작업 후 변경 파일, 확인 방법, 실행 결과만 간단히 보고한다.

## 완료 조건

- 관련 lint와 build를 실행하고 가능한 경우 실제 화면을 확인한다.
- 오류가 있으면 숨기지 않고 원인을 설명한다.
- 작업 결과를 해당 주문서에 기록한다.
- 완료 범위를 넘어 다음 기능을 시작하지 않는다.
