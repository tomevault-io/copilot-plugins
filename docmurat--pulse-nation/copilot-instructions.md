# CLAUDE.md — инструкция для Claude по проекту «Пульс Нации»

Этот файл читается автоматически в начале работы. Следуй ему всегда.

## Кто со мной работает
- Основатель проекта, **не программист**. Объясняй просто, по шагам, по-русски.
- Формат работы: «ты говоришь — я делаю». Никогда не вываливай десять действий сразу.
  Давай один логический шаг, жди результат, потом следующий.
- Всегда объясняй *зачем* делаем шаг, а не только *что* нажать.
- Термины поясняй бытовой аналогией при первом появлении.
- Все команды — для **встроенного терминала VS Code** на **Windows** (PowerShell).
- Ошибки просим присылать целиком; по ним диагностируем, не гадаем.

## Что за проект
Генеалогическая платформа карачаевского народа. Единый живой граф нации:
люди — частицы, родство — нити. Полное описание — в `PROJECT.md`.
Дизайн-эталон — в `/design/prototype.html` (не менять облик без согласия основателя).

## Технологический стек (согласован, не менять без обсуждения)
- Фронтенд: **React + Vite**, чистый JavaScript (не TypeScript, чтобы не усложнять новичку).
- Визуализация графа: **d3-force** на Canvas (позже возможен переход на WebGL при росте).
- Бэкенд: **Node.js** (Express/Fastify) — тот же язык, что и фронт.
- База данных: **Yandex Managed PostgreSQL**.
- Хостинг: **Yandex Cloud** (ВМ + Object Storage).
- Версии и код: **GitHub**, репозиторий приватный.
- Линтер: **ESLint**.

## Железные правила данных (обсуждались с основателем)
1. **Один человек — одна карточка.** Дубликаты сливаются, не сосуществуют.
2. **Открытость по умолчанию + аварийный рубильник**: у каждой записи есть флаг
   «подтверждено владельцем»; админ может одним действием скрыть все неподтверждённые
   данные, оставив в карточках только имена.
3. **Право правки — по близости родства**: сам человек → родня 1-й степени
   (с уведомлением автора записи) → дальше через заявку и модератора →
   конфликт равных решает независимый модератор.
4. **Полная дата рождения — приватна**, публично только год/возраст.
5. Данные умерших — открыты; живые могут скрыться.

## ПРАВИЛО «НОВЫЙ ЧАТ НА ВЕХАХ» (для Claude — выполнять самому)
Чат имеет предел объёма (контекстное окно); скриншоты и большие куски кода
заполняют его быстро. Чтобы не упереться в переполнение посреди важного шага:
- Claude сам считает пройденные ВЕХИ с начала текущего чата (веха = заработала
  функция, подключён сервис, крупный кусок кода перенесён/переписан, принято
  архитектурное решение, пройден этап дорожной карты).
- Достигнув 3-й серьёзной вехи в одном чате, Claude ПО СВОЕЙ ИНИЦИАТИВЕ:
  1. Сообщает основателю, что пора перейти в новый чат (объясняет: ради запаса
     места, чтобы не прерваться на середине).
  2. Убеждается, что прогресс сохранён: напоминает про git add/commit/push и про
     обновление PROJECT.md / CLAUDE.md.
  3. Формирует готовый СТАРТОВЫЙ ТЕКСT для нового чата (актуальный, с учётом того,
     где сейчас остановились) и отдаёт основателю, чтобы тот вставил его первым
     сообщением в новый чат вместе с PROJECT.md и CLAUDE.md.
- Основатель не обязан переходить сразу, но Claude обязан предложить и подготовить.
