# Repository Guidelines

## Project Structure & Module Organization
- `src/` contains the TypeScript source. `src/index.ts` is the plugin entry point, `src/config.ts` holds defaults, and `src/types.ts` defines shared types.
- `src/api/` wraps SaucerSwap HTTP calls, `src/tools/` implements agent tools, and `src/utils/` hosts helpers (quotes, units, transactions, tokens, AMM math).
- `tests/` contains Vitest suites such as `tests/quote.test.ts` and `tests/utils.test.ts`.
- `scripts/` includes executable helpers like `scripts/dry-run-swap.mjs` and `scripts/integration-test.mjs`.
- `dist/` is generated by `tsup` from `src/index.ts`; do not edit by hand.
- Root configs live in `tsconfig.json`, `tsup.config.ts`, `biome.json`, and `package.json`.

## Build, Test, and Development Commands
- `npm run dev` runs `tsup --watch` for local iteration.
- `npm run build` emits `dist/` bundles and types.
- `npm run typecheck` runs `tsc --noEmit` against `src/` and `tests/`.
- `npm run lint` runs Biome checks; `npm run format` applies formatting.
- `npm run test` runs Vitest once; `npm run test:watch` keeps it in watch mode.
- `npm run test:integration` hits the SaucerSwap API; set `SAUCERSWAP_BASE_URL`, `SAUCERSWAP_TEST_FROM_TOKEN`, and `SAUCERSWAP_TEST_TO_TOKEN` as needed.
- `npm run dry-run:swap` builds a swap transaction using `HEDERA_*` and `SAUCERSWAP_*` env vars (see `README.md`).

## Coding Style & Naming Conventions
- TypeScript with ESM (`"type": "module"`). Biome enforces 2-space indentation and 100-char lines.
- Use `camelCase` for variables/functions, `PascalCase` for types/classes, and `UPPER_SNAKE_CASE` for constants.
- File names are lower-case; scripts use `kebab-case` (example: `scripts/dry-run-swap.mjs`).
- When adding tools, mirror the existing pattern in `src/tools/` and export them from `src/index.ts`.

## Testing Guidelines
- Vitest is the test runner. Place new tests in `tests/` as `*.test.ts`.
- Keep unit tests offline-friendly; integration tests should remain in `scripts/` and be opt-in.
- Add regression coverage for swap, liquidity, and quoting changes.

## Commit & Pull Request Guidelines
- Git history is not available in this checkout. Use Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`) and add scopes when useful (`feat(tools): ...`).
- PRs should include a summary, test commands/results, linked issues, and any API/config changes. Update `README.md` when tool behavior or environment variables change.

## Security & Configuration Tips
- Never commit secrets. Use environment variables (`HEDERA_*`, `SAUCERSWAP_*`) for local runs and document new keys in `README.md`.
