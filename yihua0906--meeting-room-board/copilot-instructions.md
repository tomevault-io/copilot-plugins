## 專案現況

本儲存庫目前僅有 `spec.md`（需求規格書）與本檔案，尚未有任何程式碼。開始實作後，請務必更新本檔案，補上實際的建置／執行／測試指令與架構說明。

## 這是什麼專案

一個單頁式「會議室預約看板」：可查看並新增 3 間固定會議室的預約，採單日檢視，並在前端自動檢查時段衝突以避免同一會議室重複預約。完整需求與驗收標準請見 `spec.md`——實作或調整行為前務必先讀過，下方列出的限制很容易在不注意的情況下被違反。

## 開發規範（強制）

- **固定三檔**：整個專案僅能有 `index.html` + `app.js` + `test.html` 三個檔案，禁止再拆分成其他 HTML／CSS／JS 檔案。樣式仍內嵌於 `index.html`，`app.js` 以一般 `<script src="app.js"></script>` 載入（非 ES module）。
- **禁止外部框架／函式庫**：不得引入 React、Vue、jQuery 等任何外部前端框架或函式庫，也不得使用 CDN 引入的第三方套件。純原生 HTML + CSS + JavaScript。
- **語言**：所有使用者可見的介面文字（按鈕、標籤、提示訊息、錯誤訊息等）與程式碼註解，一律使用**繁體中文**。
- **每次修改後回報**：完成任何一次程式修改，都要用**一句話**說明這次改了什麼，讓使用者能快速掌握變更內容。

## 技術限制（來自 spec.md 第 5 節）

- 純前端實作：HTML + CSS + 原生 JavaScript，**不使用任何前端框架**。
- 不需要後端伺服器、不需要資料庫。
- 資料儲存使用瀏覽器 `localStorage`。
- 不需要 build／打包流程，直接用現代瀏覽器（Chrome／Edge）開啟 `index.html` 即可執行。
- 檔案結構固定為 `index.html` + `app.js` + `test.html` 三檔，禁止再拆分其他檔案、禁止外部框架。

## 明確排除項（來自 spec.md 第 4 節）

除非使用者明確要求變更需求，否則不要加入以下功能——這些是需求訪談過程中被明確排除的範圍：

- 不做登入／帳號／密碼機制，不做多使用者權限管理（僅單一使用者）。
- 不支援編輯或取消／刪除已建立的預約——預約一旦建立即永久存在。
- 不支援週檢視／月檢視——僅單日檢視，可切換前一天／後一天。
- 不支援會議室新增／刪除／重新命名——固定為 3 間會議室。
- 不支援跨裝置／跨瀏覽器資料同步——資料僅存在於建立當下瀏覽器的 localStorage。
- 不支援半點或任意分鐘的預約時間——開始／結束時間僅支援整點（如 09:00、10:00）。
- 不支援通知、提醒、Email 或行事曆整合（Google Calendar／Outlook）。
- 不做牆面／門口螢幕看板模式的最佳化——當作一般網頁使用即可。

## 需保留的核心邏輯

- **時段衝突檢查**：新增預約時，只需比對**同一會議室、同一日期**的既有預約。兩筆預約重疊的條件為 `新開始時間 < 既有結束時間 && 新結束時間 > 既有開始時間`。不同會議室、或同會議室但時段不重疊者，一律允許建立成功。
- **資料持久化**：所有預約資料存於 `localStorage`；重新整理頁面或關閉後再開啟瀏覽器，先前建立的預約仍須存在。
- **會議室**：固定 3 間，預設名稱為「會議室 A / B / C」（依 spec.md 的「待確認假設」，若需變更名稱或數量，請先與使用者確認）。
