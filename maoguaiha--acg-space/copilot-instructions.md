## acg-space

> - **后端**：Java 17 + Spring Boot 3 + MyBatis-Plus。

### 1. 技术栈约束 (不得偏离)

- **后端**：Java 17 + Spring Boot 3 + MyBatis-Plus。
- **JSON**：必须用 **Fastjson2**。
- **管理端**：Vue 3 (Setup 语法) + Element Plus + Pinia。
- **用户端**：Nuxt 3 + Tailwind CSS。

### 2. 开发底线 (强制执行)

- **Bean 安全**：定义 Bean（尤其是 Redis 配置）必须显式命名，严禁出现 `BeanDefinitionOverrideException` 冲突。
- **异步幂等**：所有 RocketMQ 消费者必须包含**幂等性校验**逻辑。
- **并发与锁安全**：使用 Redisson 分布式锁时，必须确保依赖完整且初始化正常（严防 `NoClassDefFoundError` 等类加载异常阻断应用启动），加锁逻辑必须配合 `finally` 块确保释放。
- **校验先行**：接口入参必须用 `@Validated`，严禁裸奔。
- **环境隔离**：密钥、密码禁止硬编码，统一写在 `.env` 或 `yml` 配置文件中。
- **前端路径防错**：重构或移动 Vue/Nuxt 组件目录时，必须全局检查并修正引用路径，杜绝因路径错误导致的 `Cannot find module` 报错。
- **非必要不修改**：尽量不动跟本模块不强相关的代码。如果不确定是否"强相关"，先问。
- **UI设计**：本次项目的用户端有浅色、深色、粉色三种主题，你设计的每个页面都要能够分别适配不同主题。
- **代码规范**：代码必须遵循 [阿里巴巴 Java 开发手册](https://github.com/alibaba/p3c)。
- **代码审查**：代码必须经过至少 2 人审查。
- **代码风格**：代码风格必须遵循 [Prettier](https://prettier.io/) 规范。
- **代码注释**：代码必须包含必要的注释，尤其是复杂逻辑和业务逻辑。
- **代码提交**：代码必须经过 `git commit` 提交，严禁直接 `git push`。
- **代码合并**：代码必须经过 `git merge` 合并，严禁直接 `git pull`。
- **代码发布**：代码必须经过 `git tag` 打标签，严禁直接 `git push`。
- **代码部署**：代码必须经过 `git push` 部署，严禁直接 `git pull`。
- **代码回滚**：代码必须经过 `git revert` 回滚，严禁直接 `git push`。
- **代码备份**：代码必须经过 `git push` 备份，严禁直接 `git pull`。
- **自我审查**：完成一项功能的时候要自己打开浏览器实操一遍，如果不可用要读取报错信息、分析原因并修复。
- **自我测试**：完成一项功能的时候要自己写测试用例，如果不可用要读取报错信息、分析原因并修复。
- **自我优化**：完成一项功能的时候要自己优化代码，如果不可用要读取报错信息、分析原因并修复。
- **防护手段**：符合架构Linter、要有Pre-commitHooks、垃圾回收、git检查点。

### 3. AI 协作逻辑

- **不懂就问**：面对需求不明显的地方要问我。但不是什么都问我，在确保新增加依赖或修改接口签名不影响其他功能正常使用的前提下，自己解决。
- **先计划后动手**：修改 **5 个文件以上**或进行核心架构调整时，必须先列出计划（Plan）并等我确认。
- **TypeScript 强约束**：前端代码必须强制使用 TypeScript，禁止使用 `any`。
- **有自由度**：单一模块的实现确定计划后，在不影响最后成效的情况下自己决定实现顺序。
- **自动化测试和修改**：实现功能以后，自己打开前后端进行功能的测试，如果有bug，自己修改。
- **数据库迁移**：要生成一个sql文件，以便保存
- **自动生成**：根据原定计划，阅读


### 4. 文档更新与自我进化

- **及时更新文档**：完成一系列功能后，如果我直奔下一个主题，你要主动询问是否需要更新 `document/develop/V2` 目录下的需求和功能迭代文档。
- **自我学习 (Study 机制)**：将犯过的错和疏忽导致的 bug 记录在 `document/study/study.md` 中。必须使用严格格式追加：`- [YYYY-MM-DD] 错误：xxx | 原因：xxx | 防范：xxx`
- **制定计划 **：回复完要把 `document/develop/V2` 中的plan.md文档更新，没有就自己建一个，根据项目生成计划。
- **上下文收敛 (Point 机制)**：每次回复前，必须先静默读取 `document/point/point.md`。严格以该文件内容为当前认知基准（Source of Truth），忽略历史聊天记录中已废弃的方案或冲突信息。每次完成阶段性任务，需将最新状态覆写更新至该文件。
