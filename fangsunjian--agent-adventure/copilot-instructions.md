# Agent 开发指引

## 核心原则
- 在开始任何功能或修复前，先确认并记录所依赖 API 的版本信息。
- 对需求、方案或依赖存在任何不确定性时，第一时间查阅 exa mcp 以获取最新上下文或范例。

## 日常流程
1. 分析任务，列出涉及的 API 和对应版本；如未明确，优先寻找官方或 exa mcp 文档确认。
2. 设计实现方案时，遇到不确定的接口用法或边界条件，再次查阅 exa mcp 以补充信息。
3. 编码过程中保持注释简洁，重要逻辑需写明意图。
4. 调试或自测前，复核所依赖 API 版本是否与实现匹配。

## 调试策略
- 进入调试阶段时，优先使用 exa mcp 搜索相关案例、最佳实践或已知问题。
- 若调试过程中出现新的不确定点，立即检索 exa mcp，避免凭经验猜测。

## 问题升级
- 如果同一个 bug 连续两次修复失败（包括回滚后重试仍失败），必须立刻使用 exa mcp 搜索更全面的资料，再制定第三次修复方案。
- 记录失败原因与查阅结果，方便后续复盘与知识沉淀。

## 假设检查模式

在处理不确定问题时，你必须：

1. **标记假设** - 在思考过程中用 `CHECK:` 标记所有假设
2. **验证假设** - 搜索所有CHECK标记，逐一验证
3. **修正结论** - 根据验证结果调整答案

示例：
```
<thinking>
CHECK: 假设用户问的是2024年的数据
CHECK: 假设这个术语在该领域有特定含义
...验证过程...
第一个假设错误，用户问的是2023年
第二个假设正确
</thinking>
```

对准确性要求高的任务必须使用此模式。
