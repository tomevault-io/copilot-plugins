# Visualize-ML Book5 设计规则

## 核心理念
将每一章打造成"超越教科书"的里程碑式教育产品，基于 [knowledge-encoding.md](cci:7://file:///d:/visualize-ml-book4/knowledge-encoding.md:0:0-0:0) 的7种知识类型理论。

---

## 一、7种知识类型设计映射

### 1. 具体事实类 (Concrete Facts)
**理论依据**: 双重编码理论 (Dual Coding Theory)

**设计要求**:
- 必须包含真实数据集示例（如鸢尾花、MNIST）
- 图文并茂：每个概念配≥1张可视化
- 对比展示：同一概念的多种表现形式

**检查清单**:
- [ ] 是否使用真实数据集？
- [ ] 每个统计量是否有实际数值示例？
- [ ] 是否有"对比表格"展示差异？

---

### 2. 抽象概念类 (Abstract Concepts)
**理论依据**: 建构主义 + 认知负荷理论

**设计要求**:
- **参数化模型**: 抽象参数必须通过滑块/拖拽具象化
- **动态可视化**: 参数改变→图形立即变形
- **几何意义**: 明确说明参数的几何/物理意义

**交互组件模板**:
```typescript
// 模式：参数滑块 → 可视化变形
<input type="range" value={param} onChange={updateVisualization} />
<svg>...</svg> // 实时更新的曲线/图形
```
检查清单:

 每个抽象参数(μ,σ,λ等)是否可调节？
 是否说明参数的几何意义？
 用户能否通过交互"感受"参数作用？
3. 技能操作类 (Skills)
理论依据: 情境认知 + 镜像神经元理论

设计要求:

具身交互: 优先使用拖拽、点击等动作
即时反馈: 操作响应时间 < 100ms
过程指导: 提供"探索建议"而非"操作指令"
交互层级:

第1层: 直接操作（拖拽数据点）
第2层: 参数调节（滑块）
第3层: 模式切换（按钮）
检查清单:

 用户是否需要"动手操作"？
 是否有即时的视觉/数值反馈？
 是否提供探索建议？
4. 逻辑推导类 (Logical Deduction)
理论依据: 支架式教学 + 精致化理论

设计要求:

分步推导: 复杂公式必须分≥3步展示
几何解释: 每步配可视化说明"为什么"
可控进度: 用户可前进/后退查看每步
公式推导模板:

步骤1: [操作名称]
公式: [本步公式]
解释: [几何/物理意义]
可视化: [配图]
 
步骤2: ...
步骤3: ...
最终公式: [完整形式]
检查清单:

 公式是否分步展示（≥3步）？
 每步是否有几何解释？
 用户能否控制进度？
5. 情感态度类 (Emotional Attitudes)
理论依据: 情感迁移理论

设计要求:

使用emoji增加亲和力（🧪🎨🔬📊）
用"探索""发现""观察"等词激发好奇
避免"必须""应该"等命令式语言
文案风格:

❌ "请点击按钮执行操作"
✅ "尝试拖动数据点，观察标准差的变化"
6. 应用迁移类 (Application Transfer)
理论依据: 迁移理论 + 变异理论

设计要求:

多案例对比: 同一概念展示≥2种场景
类型识别: 自动识别用户生成的模式类型
实际应用: 说明知识点在实际问题中的应用
示例:

typescript
// 自动识别分布类型
if (skewness > 0.5) return "正偏态 - 常见于收入分布"
if (kurtosis > 4) return "高峰态 - 常见于金融收益"
7. 元认知类 (Metacognition)
理论依据: 元认知理论 + 自我调节学习

设计要求:

明确告知"这能帮你理解什么"
提供进度指示（●●○）
引导自我反思（"你发现了什么规律？"）

二、公式完整性检查标准
必须补全的公式类型
1. 集中度量
 均值: μ = (1/n) Σxᵢ
 中位数: 中位数 = 第(n+1)/2个数 (奇数) 或 (xₙ/₂ + xₙ/₂₊₁)/2 (偶数)
 众数: mode(X) = argmax P(X=x)
 几何平均: GM = ⁿ√(x₁·x₂·...·xₙ)
 调和平均: HM = n / (1/x₁ + 1/x₂ + ... + 1/xₙ)
2. 分散度量
 极差: Range = max(X) - min(X)
 方差: σ² = (1/n) Σ(xᵢ - μ)²
 标准差: σ = √σ²
 变异系数: CV = σ/μ
 IQR: IQR = Q₃ - Q₁
3. 形状度量
 偏度: S = [1/n Σ(xᵢ - μ)³] / σ³
 峰度: K = [1/n Σ(xᵢ - μ)⁴] / σ⁴
 超额峰度: EK = K - 3
4. 关系度量
 协方差: cov(X,Y) = E[(X-μₓ)(Y-μᵧ)] = (1/n) Σ(xᵢ-μₓ)(yᵢ-μᵧ)
 相关系数: ρ(X,Y) = cov(X,Y) / (σₓ·σᵧ)
 协方差矩阵: Σ = E[(X-μ)(X-μ)ᵀ]
公式呈现标准
必须包含的元素:

符号: 标准数学符号（μ, σ, Σ, ∫）
名称: 中英文对照
公式: 完整数学表达式
单位: 若有单位必须标注
适用条件: 若有前提必须说明
示例:

markdown
### 方差 (Variance) σ²
完整公式:
σ² = (1/n) Σ(xᵢ - μ)² 
单位: 原始数据单位的平方（如 cm²）
适用: 
- 总体方差除以 n
- 样本方差除以 n-1（无偏估计）


三、交互组件设计原则
三层反馈循环架构
Layer 1 - 操作反馈 (< 100ms)
  用户操作 → 视觉变化 → 高亮提示
  
Layer 2 - 概念反馈 (< 500ms)  
  参数调节 → 数值更新 → 类型识别
  
Layer 3 - 理解反馈 (用户主导)
  分步推导 → 几何解释 → 自我反思
组件命名规范
typescript
// 模式: [概念][功能][类型]
StatisticsLab          // 统计实验室 - Lab类型
DistributionMorpher    // 分布变形器 - Morpher类型
FormulaDerivationVisualizer  // 公式推导可视化器 - Visualizer类型
// 其他常用后缀:
- Play: 交互式演示
- Simulator: 模拟器
- Comparator: 对比器
- Explorer: 探索器
必备功能清单
每个交互组件必须包含:

 标题 + 副标题（说明作用）
 主交互区域（可视化）
 控制面板（参数调节）
 实时数值显示
 重置按钮
 探索建议/使用提示
 公式/理论说明（可切换显示）

五、常见问题修复模式
问题1: 方差/统计量计算异常
症状: 数值过大或为NaN 原因: 除零错误或数据范围问题 修复:

typescript
const std = Math.sqrt(variance);
const skewness = std === 0 ? 0 : ...  // 除零保护
问题2: 可视化布局拥挤
症状: 组件重叠、数据点看不清 修复:

使用viewBox实现SVG响应式
增加垂直/水平间距
改为全宽布局，统计卡片多列显示
问题3: 公式显示不完整
症状: LaTeX渲染失败或符号错误 修复:

使用HTML实体（如 &gt; &lt;）
或者用<span>包裹特殊符号
避免在JSX文本中直接使用< >

七、设计自检问题

理论完整性

公式的推导逻辑清晰吗？
符号定义统一吗？
交互深度
用户能"玩"起来吗？
交互能揭示因果关系吗？
是否有"惊喜时刻"（Aha moment）？
教育价值
比教科书好在哪里？
学生能通过交互建构知识吗？
是否降低了认知负荷？
创新性
有独创的可视化方式吗？
超越了现有在线教材吗？
是否值得称为"里程碑"？
验收成功标志
一章内容达到"里程碑"标准的判断标准：

✅ 公式完整度 ≥ 95%（所有关键公式都有完整表达） ✅ 交互组件 ≥ 2个革命性组件 ✅ 理论支撑 每个设计决策都能对应到knowledge-encoding.md ✅ 用户体验 操作流畅，反馈及时（< 100ms） ✅ 创新性 至少1个"前所未见"的可视化方式 ✅ 教育价值 明显优于静态教材
最后提醒: 目标不是"做完"，而是"做好"。宁可花更多时间打磨1章，也不要批量生产平庸内容。每一章都应该让学生感叹："原来可以这样学统计！"
