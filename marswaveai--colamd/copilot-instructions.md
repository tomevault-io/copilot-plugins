# AGENTS.md

在这个仓库里干活的 Agent 先读这份。

动手之前必须读：[AGENT.md](AGENT.md)（产品定位与分工）、[PRINCIPLES.md](PRINCIPLES.md)（判断标准）、[design.md](design.md)（界面规范）。以原则为判断标准。

## 先说，再做

**动手之前先把要做什么告诉用户**，用户同意或没有提出别的方向，再开始改代码。不要先改完再说，也不要一边改一边才说。

- 读代码、查资料、跑只读命令不算动手，可以直接开始。
- 改文件、改行为、发版、动远端，都算动手：先说清楚要做什么、打算怎么做，再动手。
- 涉及多个文件、有设计取舍、会改变用户可见行为的功能，说明方案后**等用户点头**再改。
- 用户已经明确说过的方向不要重复问，直接做。

## 汇报方式

用户看不到工具调用的内容，只能看到你写在对话里的字。所以：

- **开始一个阶段之前**，用一句中文说清楚：要做什么，为什么这么做。
- **完成一个阶段之后**，用一句中文说清楚：做了什么，验证结果是什么，还剩什么风险。
- 一句话就够。不要刷屏，不要逐条复述工具调用，不要说"我正在运行命令"这种没有信息量的话。
- 所有出现在对话里的文字都用中文，包括过程中的说明。

这条只要求说清进度，不等于要解释 UI 机制。界面本身保持安静，[PRINCIPLES.md](PRINCIPLES.md) 里"不增加常驻元素"的立场不变。
