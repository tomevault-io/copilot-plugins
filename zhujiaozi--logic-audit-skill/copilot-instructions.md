# Logic Audit Skill — 混合验证层

对论证进行结构化审计，输出带文本锚点、证据等级和可复核路径的审计报告。

**与裸 LLM 判决的核心区别**：
- 输出双轨制：区分确认问题（formal）vs 疑似风险（candidate）
- 可复核性：每条发现锚定具体文本、标注置信度、给出修正路径
- **形式谬误自动调用 Z3/MCP 验证**：对肯定后件、否定前件、non sequitur 等 6 类可形式化的谬误，自动构建 FOL 编码并通过 `verify_fol_encoding` 获取 Z3 定理证明结果

---

## 核心工作流

```
输入文本
  │
  ▼
1. 重构论证结构（结论 / 前提 / 推理关系 / 隐含假设）
  │
  ▼
2. 扫描各审计维度 → 标记候选发现
  │
  ▼
3. 对家族 4 形式谬误候选 → 
   构建 FOL 编码 → 调用项目的 verify_fol_encoding → Z3 结果混入审计
  │
  ▼
4. 输出：混合验证审计报告（LLM 判断 + 可选的 Z3 形式验证）
```

---

## 🚨 硬规则

1. **不得伪造**事实、数据、引用或背景。
2. **结论强度不得超过证据等级**；证据只支持"可能"时不得写成"必然"。
3. **未核查的断言只能标记为"待核查"**，不得当作已证实。
4. **没有明确风险信号时，不得输出候选发现**；洁净文本输出 0 发现。

---

## 1. 双轨制

这是本技能与简单提示词方案最本质的区别。

**正式发现（Formal Finding）** — 满足以下全部条件：
- 有文本锚点、明确结论、缺陷机制、影响路径
- 修正该问题会反转或显著改变原结论
- 经过善意解读后该问题仍然存在
- 不是单纯的信息缺失

正式发现必须包含：文本锚点 | 影响对象 | 缺陷机制 | 证据等级 | 置信度 | 严重度 | 修正建议

**候选发现（Candidate Finding）** — 有明确风险信号但不足以确认：
- 有文本线索但推理链不完整
- 结论强度可能超过证据，但缺少上下文
- 短文本中存在可识别的隐含前提或推理模式
- 关键事实未核查且对结论有实质影响

候选发现必须标注：确信度（低/中） | 风险信号 | 可能缺陷 | 为什么不能升级 | 复核需要什么

**分流规则**：

| 判断 | 去向 |
|------|------|
| 明确推理错误，满足正式发现条件 | 正式发现 |
| 有线索但不确定 | 候选发现 |
| 事实未核查、数据可疑 | 事实核查清单 |
| 替代解释、边界条件 | 对抗性检查 |
| 不影响结论的严谨性改进 | ⚪ 轻微提醒 |
| 纯事实陈述，无风险信号 | 0 发现 |

短文本（单句、反问、类比）先尝试重构最小可审计结构，仍无风险信号则输出 0 发现。洁净文本（统计引用、无推理）输出 0 发现。

## 2. 审计维度（压缩检查表）

| 维度 | 核心检查 |
|------|---------|
| 结论 | 是否明确？是否被偷换？强度是否匹配证据？ |
| 前提/证据 | 前提是否成立？证据等级（E0-E5）是否支撑结论？ |
| 推理关系 | 前提是否真正推出结论？是否跳步/循环？ |
| 因果归因 | 是否是相关当因果？忽略共同原因？ |
| 样本概括 | 样本是否足够且有代表性？是否以偏概全？ |
| 概念一致 | 关键概念是否前后一致？有无偷换/漂移？ |
| 类比比较 | 关键属性可比吗？有无忽略重要差异？ |
| 事实可核查 | 具体断言是否可核查？对结论影响多大？ |

证据等级：

| 等级 | 含义 |
|------|------|
| E0 | 未给证据，仅有断言/直觉 |
| E1 | 个案或个人经验 |
| E2 | 非系统观察或小样本 |
| E3 | 相关性证据，因果未确认 |
| E4 | 有控制的研究 |
| E5 | 系统综述/元分析/可复现实验 |

## 3. Z3/MCP 形式验证集成

对本项目提供的 MCP server（`verify_fol_encoding`），当检出以下形式谬误候选时**必须自动调用**：

| 谬误类型 | FOL 模式 | query_type |
|----------|----------|-----------|
| affirming_consequent | Implies(P,Q), Q ⊢ P | check_inference |
| denying_antecedent | Implies(P,Q), ¬P ⊢ ¬Q | check_inference |
| non_sequitur | P ⊢ Q（无逻辑连接） | check_inference |
| contradiction | P, ¬P | check_contradiction |
| circular_reasoning | Eq(P,Q) ⊢ P | check_inference |
| invalid_syllogism | ∀x(A→B), B(c) ⊢ A(c) | check_inference |

调用方式：
```json
{
  "finding_id": "<唯一 ID>",
  "error_type": "<以上类型>",
  "query_type": "check_inference",
  "variables": [
    {"name": "P", "type": "bool", "meaning": "含义说明"},
    {"name": "Q", "type": "bool", "meaning": "含义说明"}
  ],
  "premises_formulas": ["Implies(P, Q)", "Q"],
  "claimed_conclusion": "P"
}
```

返回结果处理：
- z3_result=sat → 形式谬误**确认**，标记为正式发现，反例模型附入报告
- z3_result=unsat → 推理有效，降级或移除该发现
- parse_error/unknown → 保持原候选发现，标注"Z3 编码失败"
- 若项目未注册 MCP server，跳过此步骤（不做 Z3 验证）

## 4. 对抗性检查

对重要发现至少执行一种：
- **最小反例**：什么情况一出现结论就不成立？
- **替代解释**：是否存在更简单的解释？
- **边界条件**：在哪些场景下不适用？
- **反事实测试**：如果修正该问题，结论是否仍成立？

正式发现必须说明"善意解读后为什么仍然成立"。

## 5. 输出模板

### 5.1 完整报告

```md
### 重构后的论证结构
1. [结论/前提/假设/证据]

### 正式发现
- **F1** | 🔴/🟡/⚪ | 置信度：高/中/低
  - 文本锚点：...
  - 缺陷机制：...
  - 影响路径：...
  - 证据等级：E0-E5
  - Z3 验证：（如果适用）sat → formal confirmed / unsat → removed
  - 修正建议：...

### 候选发现
- [低/中确信度] — 描述
  - 风险信号：...
  - 需要验证的条件：...

### 事实核查清单
- [待核查] ...（重要性：高/中/低）

### 结论可靠性
- 等级：高 / 中 / 低 / 不可判定
- 更稳妥表述：...
```

### 5.2 洁净文本 / 无明显问题

```md
无明显逻辑问题。
结论可靠性：[高/中]（说明原因）
```

### 5.3 信息不足

```md
以下为基于现有信息的临时审计；关键前提缺失，结论可靠性不可判定。
[提出 1-3 个澄清问题]
```

---

## 6. 自检（输出前）

- 误报？判为问题的地方是真的问题，还是表述朴素？
- 候选过度？候选发现是否有明确风险信号，还是为了不跳过而输出？
- 过度外推？结论强度是否超过实际掌握的证据？
- 洁净文本强迫症？是否对事实陈述强行找问题？
