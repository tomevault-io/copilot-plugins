This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Nature du dépôt
Ce dépôt n'est **pas un projet applicatif** : c'est une **collection de plugins Claude Code** formant une "Factory IA" (fabrique logicielle à forte assistance IA). Les livrables sont des **skills Markdown** + un `plugin.json` par plugin. **Ni build, ni lint, ni tests** - la seule "compilation" est la validité JSON des manifestes.

- Dépôt : `github.com/NASSWIEL/Factory-IA` (**privé depuis 2026-06-26**), branche `main`. Documents de conception dans le parent (`../context-complet.txt`, `../architecture.md`).
- Distribution : marketplace **`git-subdir`** (`.claude-plugin/marketplace.json`) -> **Shapsha-Factory**. Le repo pro CGI (`CGI-Shapsha-Factory/CGI-Factory-AI`) reçoit les évolutions par **fast-forward direct sur `cgi/main`** (commit -> branche `optimisation` -> `git push cgi optimisation` -> `git push cgi optimisation:main`, jamais de force-push). **Poussé par le compte `NASSWIEL`** (owner de l'org ; l'ancien compte `asswiel` a été retiré de l'org le 2026-07-06). Détails (remotes, token, identité) en **mémoire projet interne**, pas dans l'arbre versionné. Côté utilisateur : `/plugin marketplace update Shapsha-Factory`.
- Installation : **uniquement via la marketplace** (`.claude-plugin/marketplace.json` -> Shapsha-Factory). Côté utilisateur : `/plugin marketplace add` puis `/plugin install <plugin>@Shapsha-Factory`. La marketplace expose aussi `category`/`tags` par plugin (groupement par rôle dans `/plugin` Discover). *(L'ancien installeur façon BMAD - `install.py` / wrapper npx / `INSTALL.md` - a été retiré : la marketplace suffit.)*
- Git : branche `main`, email `naifsaleem20@gmail.com`, compte GitHub `NASSWIEL` (origin **et** cgi). Commit/push uniquement sur demande.

## Principe transverse
- **L'IA propose, l'humain tranche.** Aucune gate structurante n'est franchie par l'IA.
- **Figer les contrats en amont**, automatiser l'hygiène en aval par des hooks déterministes (socle à venir).
- Les sorties de cadrage + architecte + designer convergent dans l'**assembleur** ; il produit un **paquet de handoff** dans `assembleur-out/` - dont une **pré-constitution** (au format `constitution.md`, dérivée des 3 contrats) et des **graines spec** par feature - que **l'équipe** donne à SpecKit. L'assembleur **n'écrit jamais** dans le repo cible. Il n'y a plus de skill handoff côté cadrage.

## Conventions communes
- Skills : `<plugin>/skills/<nom>/SKILL.md`, frontmatter `name:` + `description:` (une phrase courte anglaise). Corps des skills en **français** (instructions).
- Langue : **tout en français** (skills, templates, artefacts, interaction) ; seuls les identifiants/valeurs machine du manifeste et noms d'outils/formats restent tels quels.
- **Typographie humaine** (anti "style IA") : rien de ce que la Factory produit (artefacts `-out/`, prompts, rapports, sorties chat) n'emploie de tiret cadratin (em dash), de points de suspension unicode, de flèches unicode, de guillemets à chevrons, ni de coche/croix. On utilise les équivalents clavier (tiret simple, `...`, `->`, guillemets droits, `Oui`/`Non`). Règle détaillée dans la section Typographie de chaque `<plugin>/references/ux-conventions.md`.
- Workspace runtime d'un projet client : le **manifeste committé** `manifest.json` (contrat machine partagé, **versionné**, voyage avec le repo) + `.factory/<plugin>/` pour les **gabarits** (mécanique cachée, **git-ignorée**, régénérable) + un dossier de sortie par plugin à la racine (`cadrage-out/`, `architecte-out/`, `designer-out/`, `assembleur-out/`, `validation-out/<feature>/`). Prompts Claude Design : `cadrage-out/prompts/` (cadrage) et `designer-out/prompts/` (designer - consolidé sous son `-out/`), en fichiers plats. Le designer reçoit aussi l'export du design system dans `designer-out/maquette-de-claude-design/`.
- **Handoff = `-out/` committés (exécution indépendante).** Chaque phase peut être exécutée par une autre personne, sur une autre machine, dans une autre session : elle ne s'appuie **que** sur les dossiers `-out/` committés de la phase précédente, jamais sur l'historique de chat. **Le manifeste est committé** dans `manifest.json` : il **voyage avec le repo**, donc les **verdicts de porte** et l'état de découverte **sont transportés** vers la phase suivante / une autre machine (fin de la contradiction "contrat vs ignoré"). **`.factory/` reste local et git-ignoré**, mais **seulement pour les gabarits** (`.factory/<plugin>/`) **et le journal des coûts** (`.factory/couts/`) - régénérables via les `-init`, **plus le manifeste**. Les garde-fous ne doivent échouer que sur un **fichier réellement manquant**, en le nommant.
- **Bootstrap `.factory/` par chaque `-init` + ownership du `.gitignore`.** Comme `.factory/` est git-ignoré et absent d'un clone frais, **chaque `-init`** (cadrage, architecte, designer, assembleur) **repose ses gabarits dans `.factory/<plugin>/`** (git-ignorés) **et son bloc de manifeste dans `manifest.json`** (committé, créé s'il manque) - aucun ne présuppose un `.factory/` préexistant. Le **`.gitignore`, lui, est committé** (il voyage avec le repo) : sa **première version est générée par le cadrage** (`cadrage-init`) ; **toutes les phases aval ne font que le compléter** - elles **ajoutent** les lignes manquantes (`.factory/`, puis `.env`/`.env.*.local` côté architecte), sans jamais le **réécrire ni l'écraser**, et ne le **créent que s'il est absent** (clone où le cadrage n'a pas tourné dans ce dossier). **Invariant : `.claude/` n'est JAMAIS ignoré** (il voyage avec le repo - CLAUDE.md, mémoire, hooks déployés par la Factory ; seule `.claude/settings.local.json` peut l'être) ; toute ligne `.claude/` trouvée dans un `.gitignore` est retirée chirurgicalement en le signalant.
- **Identité des features (clé de jointure inter-plugins)** : le **use case** du cadrage (ex. `UC2`) est l'identifiant fonctionnel **stable**. L'architecte **propose** la séquence `architecture.feature_sequence` = objets `{id, ucs, name}` où `ucs` est une **liste** (l'`id` `001...` = ordre de fabrication ; une feature peut **bundler plusieurs use cases** en cas de fusion ; **aucune notion de MVP** nulle part - l'ordre est purement technique) ; l'**assembleur** en a l'**autorité finale** : il arbitre le découpage (découper/fusionner), **réécrit** `architecture.feature_sequence`, et le registre est **figé à l'init Linear** (`premier-alimente-linear`) - immuable ensuite. L'assembleur joint les faces **fonctionnelle** (briefs cadrage) et **technique** (composants/ADR architecte) **par use case**. La **face design est globale** (pas de jointure par feature) : le designer produit un **handoff** (réf. de l'export du design system committé dans `designer-out/maquette-de-claude-design/` + guidelines) appliqué à tous les écrans. Composants : services **+ application front-end** = `composants.md` (architecture technique, architecte) ; le **design system visuel** naît dans Claude Design et son export est committé dans `designer-out/maquette-de-claude-design/`.
- Marketplace : ajouter un plugin = une entrée `git-subdir` dans le `marketplace.json` de la marketplace Shapsha-Factory (`url` = ce dépôt Factory-IA, `path` = dossier du plugin).

## Flux d'artefacts (contrat I/O explicite, déterministe)
Le **manifeste** (contrat machine partagé) est **committé** dans `manifest.json`, créé par `cadrage-init` ; les **gabarits** vivent dans `.factory/<plugin>/` (caché, **git-ignoré**, régénérable). Les **documents générés** vont dans un dossier de sortie **par plugin** à la racine : `cadrage-out/`, `architecte-out/`, `designer-out/`, `assembleur-out/`, `validation-out/<feature>/` (+ `<plugin>-out/prompts/` pour les prompts, en **fichiers plats numérotés** `prompt-<N>.md`). Le **manifeste** est le contrat machine ; chaque plugin **écrit dans son `-out/`** et **lit directement** ceux de l'amont (pas d'hypothèse implicite). Contrat de consommation strict : **architecte ⊂ cadrage** ; **designer ⊂ cadrage + architecte** ; **assembleur ⊂ les trois**. **Plus de skill handoff** côté cadrage : la convergence est le rôle de l'**assembleur**, qui produit un **paquet** (il n'écrit jamais dans le repo cible).
