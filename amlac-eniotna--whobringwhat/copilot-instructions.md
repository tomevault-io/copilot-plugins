## Commands
- Dev server: `npm run dev`
- Build: `npm run build` (runs `prisma generate && prisma migrate deploy && next build`)
- Start: `npm run start`
- Lint: `npm run lint`
- `coolify-build` is an alias of `build` kept for legacy Coolify deploys.

There is no test suite configured in this repository.

## Deployment
- **Hosting**: Vercel (see [vercel.json](vercel.json)).
- **Vercel Cron**: [/api/cron/purge](app/api/cron/purge/route.ts) runs daily at 03:00 UTC and deletes lists (and their items) whose `updateAt` is older than 2 years. The route requires `Authorization: Bearer ${CRON_SECRET}` and is `runtime = "nodejs"`, `dynamic = "force-dynamic"`.
- **Required env vars**: one of `DATABASE_URL` / `POSTGRES_URL` / `PRISMA_DATABASE_URL` (resolved in this order in both [lib/prisma.ts](lib/prisma.ts) and [prisma.config.ts](prisma.config.ts)), plus `CRON_SECRET` and optionally `NEXT_PUBLIC_APP_URL` (defaults to `https://quiramenequoi.fr`).
- [next.config.ts](next.config.ts) sets `output: "standalone"` and applies global security headers (HSTS preload, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, restrictive `Permissions-Policy`, `Referrer-Policy: strict-origin-when-cross-origin`).

## Project Architecture

**QuiRamèneQuoi** is a French list-sharing app (Next.js 16 App Router, React 19, PostgreSQL via Prisma 7). Anyone with the URL of a list can read and edit it — there is no auth or ownership model. Discoverability is prevented by the unguessable `crypto.randomBytes(12).toString("base64url")` ID and `noindex, nofollow` metadata on `/[id]`.

### Database (Prisma → PostgreSQL)
- Provider is `postgresql`. The Prisma client is generated to [lib/generated/prisma/](lib/generated/prisma/) (gitignored from ESLint, never edit it).
- Connection uses the `driverAdapters` preview feature with `@prisma/adapter-pg` and a `pg` Pool — see [lib/prisma.ts](lib/prisma.ts). Use the exported `prisma` singleton everywhere; do not instantiate `PrismaClient` directly.
- Schema in [prisma/schema.prisma](prisma/schema.prisma):
  - `List`: `id` (string, unique, generated by collision-retry loop in [actions/create-list.ts](actions/create-list.ts)), `title`, `item[]`, timestamps.
  - `Item`: auto-incrementing `id`, `listId`, `title`, `who` (optional — the person bringing the item, **not** a quantity).

### App Router structure
- `/` → landing page with a `StartButton` that calls `redirectList()` to create an empty list and redirects to `/[id]`.
- `/[id]` → server-rendered list view; renders `<E404 />` if the ID is not found. Marked `noindex, nofollow`.
- `/about`, `/guide`, `/faq`, `/privacy`, `/terms` → static pages linked from the global footer in [app/layout.tsx](app/layout.tsx).
- SEO/PWA assets generated dynamically: [app/sitemap.ts](app/sitemap.ts), [app/robots.ts](app/robots.ts), [app/manifest.ts](app/manifest.ts), [app/opengraph-image.tsx](app/opengraph-image.tsx), [app/icon.tsx](app/icon.tsx), [app/apple-icon.tsx](app/apple-icon.tsx). The layout injects `Organization` + `SoftwareApplication` JSON-LD.

### Server Actions ([actions/](actions/))
All mutations are server actions ("use server"); the app has no other API routes besides the cron.
- Every action is **rate-limited by IP** via the in-memory bucket in [lib/rate-limit.ts](lib/rate-limit.ts). Limits are per-action (e.g. `create-list`: 5/min, `add-item`: 30/min). The bucket is process-local — it resets on cold starts and is not shared across Vercel instances.
- Inputs are validated with **Zod** schemas defined inline in each action; actions accept either `FormData` or the inferred input type and return `{ success, data?, error? }`.
- After mutating, actions call `revalidatePath('/${listId}')`.
- Hard cap: `MAX_ITEMS_PER_LIST = 500` enforced in [actions/add-item.ts](actions/add-item.ts).
- `create-list` retries on Prisma `P2002` (unique-constraint collision on `id`) with a fresh random ID.

### UI conventions
- Radix UI primitives wrapped in [components/ui/](components/ui/) (button, dropdown-menu, toast). Toaster mounted globally in [app/layout.tsx](app/layout.tsx).
- Theme via `next-themes` with `attribute="class"`, system default — see [components/theme/](components/theme/).
- Tailwind v4 with `@tailwindcss/postcss`. Custom fonts loaded via `next/font/google`: Nunito (`--font-nunito`), Nunito Sans (`--font-nunito-sans`, body), Syne (`--font-syne`, wordmark).
- Path alias: `@/*` → repo root (see [tsconfig.json](tsconfig.json)).

## Conventions
- All UI strings are hardcoded in **French**. There is no i18n layer — match the existing tone when adding copy.
- TypeScript is `strict`. Prettier is configured with `prettier-plugin-tailwindcss` (see [.prettierrc](.prettierrc)) — class ordering is automatic.
- ESLint extends `next/core-web-vitals` + `next/typescript` and **must** keep `lib/generated/**/*` ignored.
- When adding a new mutation, follow the existing pattern: server action + Zod schema + IP rate-limit + `revalidatePath` + `{ success, error }` return shape. Don't introduce REST/tRPC endpoints.
