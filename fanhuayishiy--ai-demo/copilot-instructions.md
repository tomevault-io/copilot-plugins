## 1. 核心需求

用 Three.js 制作**白天晴暖氛围的日式乡村车站街角便利店微缩三维景观**。

| 维度 | 要求 |
| --- | --- |
| 视角 | 第三人称自由观景视角；无 UI、无弹窗、无标注、无控件、无水印、无多余文字干扰（2026-09-20 两次修订：装配期加了一条会在首帧后摘除的加载状态；成品画面除底部一条天气控件外无任何浮层、文字与水印，见 §8） |
| 交互 | 鼠标/触摸拖拽平移、360° 旋转、无极（连续对数）缩放；阻尼平滑（2026-09-20 追加：天气可切五档；先只做键盘与 `?weather=`，同日再追加「切换增加ui」，故底部有一条常驻天气控件） |
| 渲染 | 三渲二卡通渲染（Toon），所有物体带动漫风格轮廓描边；明暗分明；电影级打光 |
| 承载 | 整个场景放置在一块**规整正方形纯色底座**上（diorama 微缩模型质感） |
| 风格 | 纯正日式二次元三渲二；画面通透、轮廓锐利干净、色彩柔和治愈、自然饱和度、白日漫射日光（2026-09-20 修订：美术方向改为低多边形**平涂哑光**，`?style=flat` 为默认、`?style=toon` 保留为退路。平涂会剥掉非内容材质的 `map`/`normalMap`，由此得出一条**长期约束**：任何"轮廓"都必须靠几何而不是靠贴图 —— 点字ブロック的黄色、manhole 的同心圆、招牌的形状皆如此。同时 `MAT.paint` 是逐字段白名单转发，历史上漏了 `graphic` 一项，导致所有"白底＋内容贴图"的牌子在平涂下被刷成无字白板；现在 `core/textures.js` 的 `memo()` 会在唯一收口处给内容贴图打 `userData.graphic`，新增内容贴图只需登记 memo 前缀，见 `docs/ASSET_CHECKLIST.md` 阶段 25） |
| 氛围 | 安静治愈，春日樱花街头感，微缩收藏模型质感，空间层次与景深分明 |
| 生命 | 场景内**不放置人物、不放动物**，保持静谧 |

## 2. 最高优先级原则

1. **质量优先**，不计时间、token、渲染开销。
2. **禁止批量粗制合成**：不允许用一个循环把差异很大的物件糊成同一形状；每个物件独立建模。
3. **每个物件独立建模、独立渲染**：不简化细节、不压缩精度，**建模层**不合并网格
   （`src/assets/**` 每件仍是独立文件、独立几何、独立变换，近景三角形一个不少）。
   2026-09-21 修订（用户实测「很多电脑承受不住」，本场景是 draw-call bound：单次提交 ≈ 8.8–10.7 µs，
   而分辨率从 1600×900 降到 400×300 只省 15% 帧时）：允许**提交层按组批处理**，装配末尾统一做，
   建模代码一行不改 ——
   ① 形状原型归一 `core/canonical-shapes.js`：只差一个逐轴缩放的几何（box / plane / cyl / cone / circ / sph）
   换成共享原型 + 对象缩放，**逐数组内容校验**通过才换，故 retile 过的铺面与改动过顶点的零件自动落选，渲染等价；
   ② 静止 + 同材质 + 不透明的零件按资产成组烘进少量 buffer `core/merge-static.js`
   （这里才用 `BufferGeometryUtils.merge`，三角形原样搬运、不减面、不降精度）；
   ③ 摆动件合并 `core/sway-gpu.js`（2026-09-21 阶段 34）：枝条组仍由 CPU 逐帧转动，
   但花瓣 / 叶片实例被抽出按「树 × 几何 × 材质」合成世界空间批次，
   组的世界矩阵增量 `B = W_动·W_静⁻¹` 经一张 DataTexture 送进顶点着色器应用 ——
   恒等式，与摆动链深度无关（每实例只需一个骨骼号），逐像素复测误差 1.9e-15 m；
   ④ 动画件中的呼吸 / 信号灯 / 玻璃流光、透明件、贴花、描边壳一律不参与，toon 档整条不走。
   透明件合并试过又撤（严格守卫后只剩 −75 次提交，却要为此多花 1.2 s 装配），判据在 merge-static.js 注释里。
   代价如实记录：合并后单个零件不能再独立隐藏，**LOD 粒度从「件」变成「尺寸带」**
   （合并体带 `userData.lodSize =` 成员里最大那个零件的尺寸，只有全员该剔时整块才剔，
   所以远景只会多画一点屏幕上本来就小于阈值的微小件，不会少东西）。
   消融开关：`?shape=off` 关归一、`?merge=off` 关整条提交层批处理。
   **不做**跨资产的实例并批（实测过：合并体跨过视锥边界后，原本逐个被剔掉的批次
   反而每帧都要提交，cell=8 m 时 interior 视口 +656 次调用 —— 省下的被剔除粒度吃回去）。
4. 打磨材质纹理、结构、光影物理质感，追求顶级画面写实还原（在卡通风格下的写实）。
5. 所有道具增加**现实经年磨损、轻微破损**细节：掉漆、锈斑、划痕、褪色贴纸、胶痕、凹陷、青苔、污渍流挂。
6. 每个资产必须是**独立文件**；便利店内部物品同样逐件独立建模并独立成文件。

## 3. 工程硬性架构约束

- **禁止**把全部模型逻辑塞进单个 HTML。`index.html` 仅作为入口主框架（canvas + 一个 `<script type="module">`）。
- 地图（地面/路面/站台/轨道）与**每一个模型资产**全部拆分为独立模块文件，用 ES Module 导入组装。
- 目录约定：
  ```
  index.html                 入口（只挂 canvas）
  src/main.js                启动装配（引擎 + 世界组装）
  src/core/                  引擎层：渲染器 / 相机 / 灯光 / 材质库 / 纹理库 / 描边 / 后期 / 工具
  src/world/                 地图层：底座、地面、路网、站台、轨道、地形层次
  src/assets/<分类>/<名>.js  资产层：一个资产一个文件
  src/motion/                动态层：落樱、摇曳、玻璃反光浮动、灯光呼吸、信号灯渐变
  tools/                     校验脚本（离线资产 smoke test）
  docs/                      布局方案 / 资产清单 / 接口契约
  ```
- 资产文件契约见 `docs/CONTRACT.md`：每个文件 `export function build(options)` 返回 `THREE.Group`，
  并 `export const meta`；禁止资产文件之间相互 import 业务资产（共享只能来自 `src/core/`）。
- 世界组装层（`src/world/street-corner.js`）负责按 `docs/LAYOUT.md` 的坐标表摆放资产。

## 4. 场景布局要求

小型社区电车站 + 电车 + 临街便利店的街角组合，包含电车轨道、站台，标准日式街角转折（L 形路口），
动线合理（乘客从站台→道口→便利店），尺度紧凑，内容填充饱满、疏密得当，还原日本春日街头风貌。

**坐标约定**：单位米；X 向东、Z 向南、Y 向上；原点位于底座中心。详细分区与摆放表见 `docs/LAYOUT.md`（不得随意改动主尺度）。

### 4.1 户外资产（全部独立建模）
- 多株盛放**染井吉野樱**、**晚樱（八重红）**：精细树干树皮、花瓣团簇
- **动态樱花**：花瓣飘落、空中飞舞、地面堆积
- 便利店建筑、玻璃幕墙、自动门、雨棚、门口地垫
- 自动贩卖机、雨伞架（内含多把伞）、分类垃圾桶
- 复古路灯、电线杆、架空电线（**电线只存在于两根电线杆之间，两端必须锚定在杆上**）
- 路牌、护栏、停车位、排水沟、柏油路面、斑马线、小巷入口
- 空调外机、公告海报栏
- 自行车停放区与多辆日式通勤自行车（前货架、链罩、 Dynamo 灯、车筐）
- 车站侧：站台、无障碍坡道、站名牌、候车长椅、时刻表看板、票箱/简易闸机、站台黄盲道、道口信号机、遮断杆
- 电车：通勤型两节车厢（车头灯/尾灯、转向架、受电弓、车门、雨刷、目的地显示）
- 道路件：manhole 井盖、锥形路障、防撞柱、消防栓、路缘石、电线杆变压器、限速标示等
- 便利店外部（硬性点名）：侧面**空调外机**；正面**雨伞架（多把伞）**、**并排多个垃圾桶**、**花盆**、**一辆自行车**、
  **自动贩卖机**；贩卖机需有**真实玻璃门**，能看清内部**每层饮料**
- 两根电线杆之间有电线相连

### 4.2 便利店内部（透过大面积玻璃窗完整可见）
多层货架、饮料冷柜（带玻璃门与每层饮料）、便当/饭团寿司陈列、零食区、收银台、咖啡机、杂志架、
海报灯箱、立式冰柜、关东煮柜台、地面导视、储物柜、后场门。
- **商品陈设丰富饱满，无空白死角**；金属/玻璃/塑料材质写实。
- 室内柔光与室外日光形成光影层次（室内略暖、略暗于日光，玻璃上有反光与光带浮动）。
- 内部**所有物品都是独立模型，各自独立文件**，高精度。

## 5. 渲染标准

- 电影级三渲二卡通写实，多边形精度高。
- 明确区分：金属、玻璃、木材、塑胶、沥青、花瓣、树皮、纸张、织物、瓷砖、混凝土。
- 白日柔和漫射光照；樱花透光、路面反光、玻璃折射、物体阴影过渡自然。
- 无模糊、无锯齿、**无穿模**、无细节丢失。
- 后期：轮廓描边（inverted hull + 屏幕空间描边）、柔和 bloom、微DOF/移轴感、色调分级、极轻胶片颗粒与暗角。

## 6. 动态效果（柔和不杂乱）

樱花持续飘落、花枝微风微动、地面花瓣随风移动、玻璃光影浮动、路灯与店铺灯光微弱呼吸明暗、
交通信号灯缓慢渐变、春日柔和空气光晕；整体帧率稳定流畅。

## 7. 开发顺序（必须按阶段推进）

0. 读取本文件 + `docs/LAYOUT.md` + `docs/CONTRACT.md`。
1. **布局规划先行**：输出布局方案（`docs/LAYOUT.md`，含 ASCII 顶视图、分区、坐标摆放表）。
2. 引擎层与共享层（材质 / 纹理 / 几何工具 / 描边 / 灯光 / 后期 / 相机）。
3. 地图层（底座、地面、路网、站台、轨道）。
4. **逐个资产**依次建模开发（`docs/ASSET_CHECKLIST.md` 按序执行，每完成一项打勾并跑 `npm run check`）。
5. 世界组装 + 动效系统接入。
6. 浏览器实拍校验（多机位截图）、修复穿模/漏光/描边错误，直至完成。

  （投影像素阈值，不动 dpr/阴影/描边）：26 → 46 px 实测 +7%、→ 90 px +30%、→ 260 px +37%。
  **跨会话读 fps 一律不作数**（阶段 37 实测：同一份代码、同一拖拽脚本，dev 与构建产物都读 23.5–24.2，
  而阶段 34 记的是 19.5–19.9，两次的 draw calls 几乎相同）—— 差的是机器热状态与后台负载。
  跨会话比较只用 **draw calls / 三角形数**，fps 只在同一次 A-B-A-B 成对测量内部比。
  基线自阶段 34 起改为**钉住动画时间**拍摄（`shoot.mjs --time=3.4`）：UV 流光与摆动都是墙钟驱动的，
  不钉时间的逐像素对比等于在比两次运行各自跑了多久 —— 阶段 34 就把它误判成过一次「合并翻面」。
