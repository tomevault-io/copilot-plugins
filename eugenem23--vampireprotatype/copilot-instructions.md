## Project Overview

Unity 6 (2023 LTS+) C# project — a card-based combat prototype with a slot machine mechanic (Vampire Survivors-inspired). Early stage: no game scripts yet, only architecture docs and Zenject plugin.

## Tech Stack

- **Engine:** Unity 6 with URP (Universal Render Pipeline)
- **DI Framework:** Zenject (in `Assets/Plugins/Zenject/`)
- **Input:** Unity Input System (`com.unity.inputsystem`)
- **Audio:** AudioEngine plugin (in `Assets/Plugins/AudioEngine/`) — custom SFX, music, UI sounds
- **Language:** C# — game code goes in `Assets/Game/Scripts/`

## Build & Run

This is a Unity project — open in Unity Editor. No CLI build pipeline is configured. The `.sln` and `.csproj` files are auto-generated by Unity; do not edit them manually.

## Architecture

### Pattern: Model-View-Ult (simplified MVC)

- **Model** — pure C# classes with data + business logic (no Unity dependencies)
- **View** — MonoBehaviour that reads from Model and handles Unity visuals
- **Controller** (optional) — orchestrates flow, knows Model and View

Models communicate state changes via events; Views subscribe and react. Models never reference Views.

### Zenject Container Hierarchy

```
ProjectContext (AppContextInstaller — ScriptableObjectInstaller)
  └── SceneContext (MonoInstaller per scene)
       └── GameObjectContext (MonoInstaller per entity, e.g. per-player)
```

- **ProjectContext**: app-lifetime services (scene navigation, app service)
- **SceneContext**: game session services (game cycle, pools, factories, catalogs)
- **GameObjectContext**: per-entity services (input, camera, character components)

### Planned Scripts Folder Structure (`Assets/Game/Scripts/`)

```
Scripts/
├── App/               # App-level services & installers
├── Extensions/        # Utility extension methods
├── Gameplay/
│   ├── Common/        # Shared configs, enums (TeamConfig, InputMap)
│   ├── GameContext/    # Game session: combat, bullets, currency, players
│   ├── GameObjects/   # Per-entity: Model + View + Config (Character, Bullet, Weapon)
│   ├── LevelContext/  # Level-specific: spawn points, world container
│   └── PlayerContext/ # Per-player: input, camera, character creation
└── UI/
    ├── App/           # Main menu UI
    └── Gameplay/      # In-game HUD, currency views, adapters
```

### File Placement Rules

1. **Model** → `GameObjects/<Entity>/` or `GameContext/<System>/`
2. **View** → next to its Model
3. **Controller** → `PlayerContext/` or `GameContext/`
4. **Installer** → in the context folder it belongs to
5. **Service/Manager** → `App/` (global) or relevant context folder
6. **Config/SO** → `Common/` (shared) or next to entity in `GameObjects/`
7. **Interface** → next to implementation
8. **UI** → `UI/App/` (menu) or `UI/Gameplay/` (HUD)

## Conventions

- Prefer composition over inheritance (Unity component model)
- ScriptableObjects for configs and data definitions
- Zenject installers are named `<System>Installer` and placed in their context folder
- Debug components (Inspector buttons) for testing — no UI views in prototype phase
- Documentation in `Assets/AI/` is in Russian
