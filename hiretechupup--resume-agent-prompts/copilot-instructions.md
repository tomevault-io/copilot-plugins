## prompt-format

> 提示词文件需要包含完整的元数据、使用说明和公开发布边界


# 提示词文件规范

所有位于 `prompts/` 目录下的提示词文件必须包含以下格式：

```markdown
---
title: 提示词标题
version: 1.0.0
category: 分类（如 cv-assistant, code-review, etc.）
tags: [标签1, 标签2]
author: 作者
created: YYYY-MM-DD
updated: YYYY-MM-DD
model_compatibility: [gpt-4, claude-3, etc.]
---

# 提示词标题

## 📋 概述
简短描述提示词的用途和适用场景

## 🎯 使用场景
- 场景1
- 场景2

## 📝 提示词内容

\```
你是一个专业的 [角色描述]。

## 你的任务
[详细描述任务目标]

## 任务边界
- 你负责：[应完成的内容]
- 你不负责：[不应扩展的内容]

## 信息与真实性
- 以用户提供的信息为准，不编造事实或数据
- 需要外部信息时说明可核验的公开来源
- 无法确认时标注不确定性并向用户追问

## 用户可见流程
1. [步骤1]
2. [步骤2]
3. [步骤3]

## 用户确认
- 在覆盖、替换或明显改变用户原内容前，先获得明确确认

## 输出要求
- 使用清晰、通用、人类可读的格式
- [其他输出要求]

## 完成前自检
- 是否在任务边界内完成了需求？
- 是否存在编造或未说明的不确定内容？
- 必要的用户确认是否已经完成？
- 输出是否清晰、完整且便于人阅读？
\```

## 💡 使用建议
- 建议1
- 建议2

## 📊 效果示例
（可选）展示使用此提示词的效果
```

## 必须包含的部分

1. **YAML Front Matter**: 包含标题、版本、分类、标签等元数据
2. **概述**: 一句话说明提示词用途
3. **使用场景**: 列出适用场景
4. **提示词内容**: 实际的提示词文本
5. **使用建议**: 如何更好地使用此提示词

## 提示词内容要求

提示词本身必须覆盖：

1. **任务边界**：说明负责和不负责的范围
2. **真实性与来源**：不编造信息，外部事实可核验，不确定时明确说明
3. **用户确认**：在覆盖、替换或重要改变用户原内容前先确认
4. **通用输出**：使用人类可读、不依赖特定产品运行时的格式
5. **完成前自检**：检查边界、真实性、来源、用户确认和输出质量

## 公开发布边界

可以发布角色定位、任务目标、用户可见流程、专业原则、质量标准和通用的人类可读输出。示例必须使用明确的虚构数据。

不得发布：

- 内部工具或函数名、调用顺序、调用 JSON、参数或返回 payload
- schema、DTO、数据库字段、内部 ID 规则、事件名、卡片名、service code 或 action code
- 会员、授权、销售线索、运营转化等私有业务编排
- 内部 API、类名、文件路径、环境配置或本地绝对路径
- 真实用户数据、聊天记录、数据库导出、密钥、Token、Cookie、密码或连接串

“内部实现（不公开）”标题、折叠区域或注释不会使内容变成私密。这类内容必须在提交前删除；无法确认是否可公开时，默认不发布。

## 原因

- 方便用户快速理解提示词用途
- 便于分类和检索
- 记录版本变更历史
