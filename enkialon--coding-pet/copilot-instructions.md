# Agent 指南

CodingPet 是常驻桌面的轻量小工具：空闲时几乎不占 CPU，内存也应尽量克制。改代码或提优化时，先问「用户会不会感知到」，再决定要不要缓存、预加载或常驻数据结构。

## 内存与性能

- **不要什么都缓存。** 只有热路径、高频调用、且 profiling 证明有瓶颈时才考虑 `OnceLock`、全局静态缓存、进程级预加载等。
- **低频操作直接做。** 例如设置窗偶尔打开一次，读盘加载 CJK 字体可以接受；不必为省一次 I/O 把数 MB 字体常驻内存。
- **优先释放。** 窗口关闭、功能不用时，应能 drop 相关资源（GPU 纹理、字体字节、临时缓冲），不要默认泄漏到进程结束。
- **已有设计目标：** 事件驱动、空闲低占用。优化不要破坏这一点（例如后台轮询、无界缓存、常驻大缓冲）。

## 何时值得优化

| 场景 | 倾向 |
|------|------|
| 每帧 / 主循环 / 指针轮询 | 值得省分配、少锁、少读盘 |
| 托盘菜单、设置窗、一次性初始化 | 简单实现优先，可读性优先 |
| 大对象（字体、图集、解码缓冲） | 用时加载，不用可释放；慎做全局缓存 |

## 代码风格（简要）

- 改动范围尽量小，匹配现有模块边界与命名。
- 注释只解释非显而易见的逻辑，不写废话。
- 不主动加测试、文档、抽象，除非任务明确要求或行为确实需要。
