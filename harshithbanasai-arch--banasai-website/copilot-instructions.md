## Commands

- `npm run dev` — dev server on http://localhost:3000
- `npm run build` — production build (also runs type-checking + lint; this is the primary correctness gate)
- `npm run start` — serve the production build
- `npm run lint` — `next lint`

No test framework is configured.

## Architecture

Next.js 14 **App Router** site (React 18, TypeScript, Tailwind 3.4). It is a static marketing site — no backend, no database, no auth in this repo.

**Routes**
- `/` — `app/page.tsx`, the homepage
- `/banas-intel` — permanently redirects (HTTP 308) to the external Banas Intelligence app. For now that is the Cloud Run deployment `https://banas-intel-api-1007077428197.asia-south1.run.app/`; switch to `https://intel.banas-ai.com/` once that subdomain is live. The page file (`app/banas-intel/page.tsx`) is a `permanentRedirect` stub marked `force-dynamic` (a statically-prerendered stub renders a 500).
- `/contact` — `app/contact/page.tsx`, contact / register-interest form (client component; its metadata lives in `app/contact/layout.tsx`)
- `/robots.txt`, `/sitemap.xml` — SEO metadata routes generated by `app/robots.ts` and `app/sitemap.ts`. The production origin is hardcoded to `https://www.banas-ai.com` as `SITE_URL` in `app/layout.tsx` and in those two files — update all three if the domain changes.

**How the homepage is assembled.** `app/page.tsx` is a vertical stack of section components imported from `components/`. To add, remove, or reorder a section, edit this single file — each `<Section>`/block corresponds to one component. The reusable `Section` component (`components/Section.tsx`) renders a two-column `leftHalf`/`rightHalf` row used for the alternating text + image blocks.

**Server vs Client components.** Components are React Server Components by default. `"use client"` is used only where local state is needed — currently `components/Accordion.tsx` (expand/collapse) and the contact form. Don't sprinkle `"use client"` on presentational components.

**Path aliases** (see `tsconfig.json`): `components/*` and `styles/*` — imports look like `import Header from "components/Header"`, not relative.

### Design system — two files must agree

Styling tokens live in **`tailwind.config.js`** (color names `primary`, `surface`, `background`, `green-accent`, `green-secondary`, `green-light`, `body-text`, `muted-text`, `border`; fonts `sora` / `inter` / `dm-mono`; radii `card` / `button`) and **`styles/globals.css`** (reusable component classes).

The `@layer components` classes in `globals.css` are the shared vocabulary — use them instead of restyling from scratch:
- `.btn-primary` / `.btn-secondary` — buttons
- `.card` — surface panel
- `.section-padding` — standard vertical rhythm (`py-[80px]`)
- `.label-text` — the small uppercase DM-Mono eyebrow above headings
- `.icon-circle` — the green circle holding a `react-icons` glyph
- `.hero-bg` — the hero radial gradient

Note: several `globals.css` classes hardcode hex values (e.g. `.btn-primary` uses `#1B2A6B`) rather than referencing the Tailwind token. Match the surrounding convention when editing.

**Fonts** are loaded twice — via `<link>` in `app/layout.tsx` and via `@import` in `globals.css`. The `font-sora` / `font-inter` / `font-dm-mono` classes map to these.

### Images & icons

- Local images live in `public/` (logo, product images). `public/products/` holds product imagery.
- `next.config.js` allows only `images.unsplash.com` as a remote `next/image` host. Add a hostname there before using other remote images with `next/image`.
- Icons come from `react-icons` — `fa` and `ai` subsets are in use.

## Content conventions

The site markets two pillars for **Banas AI**:
- **Banas Intelligence** — an agentic system that forecasts the real world by reading many sources at once (weather, water, market arrivals, news, policy, trade flows, price trends, seasonal cycles) and turns them into decisions. First domain is agriculture intelligence: live for arecanut, expanding to more commodities. The live product is currently the Cloud Run deployment `https://banas-intel-api-1007077428197.asia-south1.run.app/` (use `https://intel.banas-ai.com/` once that subdomain is live); this site only links out to it. That URL is duplicated across `components/Hero.tsx`, `Products.tsx`, `Download.tsx`, `Accordion.tsx`, `Header.tsx`, `Footer.tsx`, and the `/banas-intel` stub — update all of them when switching.
- **Physical AI** — ground-truth data contracts (collected and delivered), physical AI models being trained now, and physical devices on the future roadmap.

The detailed Banas Intelligence product page (pipeline, model figures, honest-limits section, etc.) lives on the separate Banas Intelligence app, **not in this repo**. This marketing site intentionally stays high-level and sale-driven — keep technical detail off the homepage and link out to the live app instead.

Links to Banas Intelligence open the Cloud Run URL in a new tab via `<a target="_blank" rel="noopener noreferrer">`, not an internal `<Link>`.

Contact email across the site: `contact@banas-ai.com`. Primary CTA language is "Register Your Interest" / "Contact Us", funneling to `/contact`.

The contact form (`app/contact/page.tsx`) posts JSON to `FORM_ENDPOINT`, which defaults to FormSubmit's AJAX endpoint (`https://formsubmit.co/ajax/contact@banas-ai.com`) — it works with no signup/backend, but the **first** submission triggers a one-time confirmation email to `contact@banas-ai.com` that must be clicked before messages are delivered. Override with any JSON-accepting endpoint (e.g. Formspree) via the `NEXT_PUBLIC_FORM_ENDPOINT` env var. If the POST fails (e.g. offline), it falls back to a `mailto:` that pre-fills the user's email client.
