# 论文论证图谱 · Agent 操作说明

你的任务：把一篇论文拆成一张**可以走进去的论证结构图**，产出一个自包含的 HTML 文件。

这份文件是给 agent 看的完整指令，不依赖任何特定平台的技能触发机制。把它（或它的关键段落）放进 system prompt，或者在任务开始时读一遍。

## 什么时候该用

用户提出以下任一诉求时：梳理／拆解／精读一篇论文的逻辑结构、论证结构、理论框架；把论文做成图谱／知识图谱／结构可视化；想知道"每段的论点和论据是什么"、"这几个理论之间是什么关系"；上传 PDF 并说"帮我看看这篇在讲什么逻辑"。综述写作时需要把多篇论文的论证骨架摆在一起对比也适用。

不适用：只要一段散文摘要、只要翻译、只要提取参考文献。

## 为什么不是普通思维导图

普通摘要给的是**话题层级**（第二章讲了三个理论）。这里要的是**论证层级**：每个节点必须是一句可以被反驳的主张，必须挂着支撑它的原文，节点之间必须标明是支持、中介、否证还是理论拓展。

差别在于——读完普通导图你知道论文说了什么，读完这张图你知道论文的论证**在哪里最脆弱**。如果抽出来的东西只是章节标题的复述，这次抽取就失败了。

## 流程

### 1. 读全文

PDF 超过 10 页就分段读完，不要只读摘要和结论就动手。只拿到二手总结时，**明确告诉用户「原文原句」那一栏会是空的**，因为你没有原文可引——不要编造引文。

读完先写一句话：**这篇论文在跟谁争什么。** 这句话决定后面所有取舍。

### 2. 先用文字把逻辑讲一遍（导读）

**不能跳过，也不能最后补。** 目标读者是没读过这篇论文的人：他打开图谱应该先读到一段能从头读到尾的文字，然后才用图去查细节。图是地图，不是入口。

写 6–8 节，每节一个小标题加两三段话，顺序固定：① 这篇论文在跟谁争（领域的默认前提是什么，它要推翻哪一条）② 它要补的缺口 ③ 它调用了哪些理论、怎么接起来（并点出搬运理论时哪个前提被悄悄改了）④ 它怎么检验 ⑤ 它发现了什么（不显著的也要讲）⑥ 所以它主张什么 ⑦ 哪里站不住。

用大白话，术语第一次出现就地解释。写完自己读一遍：没读过论文的人能顺下来吗？顺不下来说明你还没读懂——**这时候去画图，画出来的一定是乱的**。

写进 `meta.brief_zh`（结构见 `docs/schema.md`），会渲染成图谱左侧的「导读」面板，首次打开自动展开，每节的节点引用可点着跳到图上。

### 3. 抽取成 graph.json

**以导读为骨架**：导读里讲到的每一步，图上都要找得到；**导读里说不清的关系，不要画成边**。

规范在 `docs/schema.md`（字段定义、关系词表、校验规则）和 `docs/extraction.md`（颗粒度怎么定、论点论据怎么分、逻辑关系怎么找、双语怎么写）。这两份是操作手册，别凭印象填字段——字段名对渲染模板是硬约定。

`docs/graph.schema.json` 是同一套规则的 JSON Schema，可用于程序化校验。

`prompts/extract.md` 是一份可以直接投给任意 LLM 的抽取提示词，内含压缩版规范；上下文紧张、或者要批量跑的时候用它。

按泳道推进，但**每抽完一层就回头补边**：发现要连回假设，贡献要连回发现，局限要连回它威胁的那条结论。这三类边最容易漏，也最能暴露论文的空档。

### 4. 出图

```bash
python3 build_viewer.py graph.json -o out/paper.html
```

只需要 Python 3.8+ 标准库，不装任何依赖。校验不通过不会出图，错误信息会指名是哪个节点的哪个字段。告警（缺 locator、空泳道、没有跨泳道的边）不阻断，但每条都值得回去看一眼。

只想校验不出图：`python3 build_viewer.py graph.json --check`

如果你的运行环境不能执行命令，见 `integrations/inject_minimal.py`：模板里只有一个 `__GRAPH_DATA__` 占位符，字符串替换即可。

### 5. 交付

把 HTML 交给用户，附一句话：抽了多少节点、多少条原文、**哪些地方你认为论文本身是弱的**。最后半句才是用户真正想要的东西。

同时交付 `graph.json`——它是可增量修改的源，改一个节点不必重跑整篇。

## 图谱里有什么（可以直接讲给用户听）

- 导读面板：一段能从头读到尾的文字，讲清这篇论文在跟谁争、怎么检验、结论站不站得住；节点引用可点着跳到图上
- 八条泳道：问题 / 研究缺口 / 理论机制 / 假设与研究问题 / 方法 / 发现 / 贡献 / 局限
- 大包小：点卡片左边的 ▸ 展开，子论点嵌在父卡片里，一层层套下去
- 连线：默认只画主干（论文有直接证据的强关系），其余关系停在卡片上时才出现
- 悬浮显示路线：停在任一卡片上，只打亮它直接的来路与去向（去向实色、来路压淡），按住 Shift 展开到 3 跳；底部给出主干路线
- 拖动：卡片任意位置都能拖，位置会被记住
- 点开看原文：右侧滑出论点、逐条论据（原句 + 中译 + 批注）、进出的逻辑关系、下级论点
- 只看这一支：把任一节点变成新的根
- 中文 / 双语 / EN 三档切换
- 问 Claude：任一节点就地提问，自动带上该节点的位置、论点、原文和关系；页面探测不到对话运行时就退回复制模式

## 常见失败模式

- **抽成了章节目录**：节点标题是「2.1 心理模型」而不是「用户对 AI 的心理模型分三种视角」。判据是能不能对它问"凭什么"。
- **理论只是并排放着**：理论层有五个节点但彼此之间一条边都没有。论文的贡献往往正是这些边。
- **原文被改写了**：`text_en` 必须逐字照抄，用户要靠它回原文搜索。概括写在 `claim_zh` 里。
- **平均用力**：相关工作的礼节性罗列抽了 20 个节点，真正的机制链条只有 3 个。跟着论证走，不要跟着页码走。
- **没有批判**：所有 `note_zh` 都是空的。图谱如果只是复述，用户自己读论文更快。
- **只给图不给文字**：没读过论文的人面对一张 60 个节点的图会不知道从哪看起。导读不是附赠品，是入口。
- **什么都标 strong**：`strength` 决定默认视图画不画这条线，全是 strong 等于没有主干，通常强关系占三到四成。
