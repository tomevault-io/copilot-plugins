# Vintage Animations

MC 1.21.1, Java 21. **Architectury multiloader** (`common/` + `fabric/` + `neoforge/`), Cloth Config, publishes to CurseForge **and** Modrinth.

Structurally unlike the Valor mods, which are single-project Fabric-only with no config layer — don't copy conventions between them without checking. Its toolchain is also older (Architectury Loom 1.10, Gradle 8.12.1); that pairing works, so it was left alone when the Valor mods moved to Loom 1.17 / Gradle 9.6.1.

**This is a client-side mod** (`"environment": "client"`), which is why CurseForge uploads are tagged `client = true, server = false`.

## Commits

`changelog.md` is generated by git-cliff from commit messages (`cliff.toml`). **A commit without a conventional prefix is silently dropped from it.**

- `feat:` → Added, `fix:` → Fixed — both published **verbatim** to CurseForge and Modrinth, so write them for players, not developers
- `chore:` `build:` `ci:` `docs:` `style:` `test:` → hidden from the changelog

## Releasing

Publishing is configured **per loader subproject** (`fabric/build.gradle` and `neoforge/build.gradle`), so a root `publishMods` runs both.

1. Bump `mod_version` in the root `gradle.properties`
2. `git-cliff --unreleased --tag v<version> -o changelog.md` — the whole file is uploaded, so it must contain only this release
3. `git tag v<version>`
4. `./gradlew publishMods -PpublishDryRun` stages locally without contacting either host; `./gradlew publishMods` publishes (needs `CURSEFORGE_TOKEN` and `MODRINTH_TOKEN`)

Preserve project IDs: CurseForge `1134994`, Modrinth `yY9ix3J0`.
