# Roomly — プロジェクト横断ルール

## 概要

賃貸管理会社向けSaaS + 入居者向け物件ポータル。
- **kanri**: 管理会社向けSaaS。物件・入居者・契約・家賃・修繕・オーナー送金を一元管理
- **portal**: 入居者向け物件検索サイト。kanriの空室データをリアルタイム掲載。おとり物件ゼロ

月額: フリーミアム（〜10区画 無料）→ 区画数ベース段階課金（〜50区画 ¥5,000 / 〜100区画 ¥10,000 / 〜300区画 ¥15,000 / 〜500区画 ¥20,000 / 〜1,000区画 ¥25,000 / 〜2,000区画 ¥30,000 / 2,001区画〜 1,000区画ごとに+¥5,000）（全て税込/月）

## 共通ルール

- **言語**: 日本語で作業・出力（コード内コメントも日本語可）
- **金額**: 全て税込で記載し、表示時は「（税込）」を必ず付記する
- **日付**: YYYY-MM-DD 形式
- **コミットメッセージ**: 日本語、簡潔に
- **秘密情報**: `.env`, credentials, API keyは絶対にコミットしない
- **DB変更**: 必ず `supabase/migrations/` にマイグレーションファイルを作成。直接DB操作しない
- **「リリースして」= push まで含む**: コミット → push まで一気にやる
- **記事リリース**: draft から `hp/content/{date}/` に MDX 変換して配置 → リリース後draftファイルは削除 → コミット → push（contentが唯一の正）

## UIデバッグ時のルール

- **Playwright MCP（`.mcp.json`）が使える**: スクリーンショット取得・DOM検査・ページ操作を自分で実行できる。UI変更後はまず自分でスクリーンショットを撮って確認すること
- **変更が反映されない場合の切り分け手順**:
  1. Playwright MCPでスクリーンショットを撮って確認（最優先）
  2. コンテナ内のソースファイルに変更が反映されているか確認（`docker exec ... grep`）
  3. `.next` キャッシュを削除してコンテナ再起動（`docker exec ... rm -rf /app/.next && docker restart`）
  4. ブラウザでハードリロード（Cmd+Shift+R）を依頼
  5. それでも反映されない場合、DevToolsで対象要素を選択し **Stylesパネルのスクリーンショット** を依頼する
- **CSSが効かない場合**: DevToolsの `:hov` ボタンで `:hover` を強制有効にしたスクリーンショットを依頼し、CSSルールが実際に適用されているか確認する
- **「大丈夫なはず」で進めない**: 反映未確認のまま次の変更をしない。必ずブラウザで実際の表示を確認してから進む
- **kanriはDocker上で動作**: Turbopackのファイルウォッチングが効かないことがある。変更後は必ず `.next` 削除 + コンテナ再起動で反映を確認
