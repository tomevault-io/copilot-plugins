This repo is Fullstaq Ruby (Server Edition), a Ruby distribution optimized for use in Linux servers. The project is about packaging Ruby in Debian/RPM packages for various distributions+architectures. Building and publishing packages happens in Github Workflows.

CRITICALLY IMPORTANT: read @./dev-handbook/README.md first to familiarize yourself with this repo's structure and design principles. MUST FOLLOW: read any docs referenced from dev-handbook/README.md (except for the "References & recommended reading" section) when they're relevant to the task at hand.

## Github Workflows core design principle

Many workflows are autogenerated from .erb files. Autogeneration parameter sources (matrix generation):
- config.yml: defines the Ruby versions we package
- environments/*: each subdir represents a supported distribution

For these workflows, only edit the source .erb files, then run `./internal-scripts/generate-ci-cd-yaml.rb`.

More about this design principle: @./dev-handbook/build-workflow-management.md

## General coding guidelines

- Keep code simple and direct, avoid abstractions unless architecturally they clearly add value

## Github Workflows guidelines

- Actions MUST pin to commit SHAs. Ensure inclusion of human-readble version number comment. Example: `uses: actions/checkout@11d59... # v4.3.1`

### Workflows review instructions (ALWAYS FOLLOW)

Review not only for correctness, but also security (VERY IMPORTANT):

- Consult security checklists:
  https://aquilax.ai/blog/github-actions-security-hardening
  https://www.wiz.io/blog/github-actions-security-guide
- Learn insights from the Tanstack postmortem: https://snyk.io/blog/tanstack-npm-packages-compromised/
- Beware of cache poisoning opportunities.
- Review transitive Github Actions dependencies too.

## Shell scripting guidelines

- CRITICALLY IMPORTANT: familiarize yourself with @./lib/library.sh first. Use helpers in `library.sh` instead of writing your own versions.
- Ensure proper error handling. Use `set -e`, and if relevant also `-o pipefail`.
- Put any cleanup code in a `_cleanup` function (auto-called by exit hook defined in library.sh).
