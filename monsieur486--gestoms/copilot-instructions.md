## Commands

```bash
# Build
mvn clean package

# Run the generator
java -jar target/*.jar

# Run all tests
mvn test

# Run a single test class
mvn test -Dtest=CrossCuttingConfigProcessorTest

# Inspect generated output without a running server
unzip -p target/*.jar BOOT-INF/classes/templates/ms-platform/<path/to/file>

# Generate a platform (server must be running on :8080)
curl -X POST http://localhost:8080/api/generate/platform \
  -H "Content-Type: application/json" -d '{}' --output ms-platform.zip
```

> **Zombie-server gotcha:** old `java -jar` processes on :8080 silently serve the previous build. Kill them before verifying changes: `pkill -f springboot-platform-generator` or use `--server.port=8077`.

## Architecture

This is a **Spring Boot code-generator** that streams a complete microservices platform as a ZIP. There is no database; the entire state is in-memory per request.

### Core flow

```
POST /api/generate/platform
  → PlatformGeneratorController
  → PlatformGeneratorService.generate()
      1. TemplateLoader.load()          — reads templates/ms-platform/** from classpath
      2. FileProcessor pipeline (ordered beans):
           @Order(10) RootRenameProcessor       — renames ms-platform/ prefix
           @Order(20) FeatureFilterProcessor    — drops files for disabled features
           @Order(30) PackagePlaceholderProcessor — substitutes groupId/basePackage/javaVersion
           @Order(40) BatchConfigProcessor      — injects BatchOptions values
           @Order(50) ResourceExpandProcessor   — clones service-a/ per resources[] entry
           @Order(60) CrossCuttingConfigProcessor — rewrites root pom, docker-compose, gateway routes, Keycloak realm, test-all.sh, AggregateController
           @Order(70) VersionInjectionProcessor — injects Docker image versions from PlatformVersions
      3. ZipService — packs GeneratedFile list into a ZIP byte[]
```

### Key design points

**Template storage:** The template is a *decompressed directory tree* at `src/main/resources/templates/ms-platform/`. This makes Git diffs readable. Dotfiles (`.gitignore`, `.env`) are stored with a `dot-` prefix (`dot-gitignore`, `dot-env`) to survive Maven's default plexus excludes at both the `maven-resources-plugin` and `maven-jar-plugin` layers. `TemplateLoader` strips the prefix on load.

**`FileProcessor` interface:** Each processor is a stateless Spring bean. It receives the full file list + immutable `GenerationContext`, returns a new list (never mutates input). Adding a feature = adding a new `@Order(N)` `@Component`.

**`CrossCuttingConfigProcessor` (@Order 60):** The most complex processor. It runs *after* `ResourceExpandProcessor` so it sees the final resource list. It rewrites five cross-cutting files structurally rather than by path matching: root `pom.xml` module list, `docker-compose.yml` service blocks (line-based removal, not regex), `ms-gateway` `application.yml` routes, the Keycloak realm JSON (Jackson tree for variable-arity arrays), and `test-all.sh`.

**`test-all.sh` dual-source trap:** The file exists in two places — the static template (used verbatim when `resources[]` is empty) *and* regenerated by `CrossCuttingConfigProcessor.rewriteTestAll()` (used whenever `resources[]` is non-empty, which is the normal case). Behavioral changes must be applied in **both** places and verified with a non-empty `resources[]` payload.

**`PlatformVersions`:** Bound to `platform.versions` in `application.yml`. The Java field defaults must equal the literal values in the template files — `VersionInjectionProcessor` uses a fresh (default) instance as the search string and the injected bean as the replacement.

**Feature flags:** `keycloak`, `redis`, `rabbitmq`, `websocket` are always-on (no toggle). Only `springbootAdmin` and `webUI` are optional. Legacy flag names in requests are silently ignored (`FAIL_ON_UNKNOWN_PROPERTIES=false`).

**Extending with a new feature flag:** Update 5 places — `FeatureFilterProcessor` (path filter), `CrossCuttingConfigProcessor.desiredModules` (root pom), `.blocksToRemove` (compose), `.volumesToRemove`, and `.rewriteGatewayYml`.

### Template modules

Permanent (always generated): `ms-eureka`, `ms-gateway`, `ms-auth`, `keycloak`, `common-lib`, `service-consumer`, `admin-application`  
Conditional: `ms-admin` (`springbootAdmin`), `ms-webui` (`webUI`), `observability/` (`batch.grafana`)  
Default services (replaced by `resources[]`): `service-a`, `service-b`, `service-c`  
Always included: `service-batch` (unless `batch.enabled=false`)

## Memory

Project design decisions are documented in `docs/claude-memory/` (index: `docs/claude-memory/MEMORY.md`). Key entries:

- `cross_cutting_config_pattern.md` — line-based YAML removal, dual-source test-all.sh, docker-compose volumes overload, substring-match bugs
- `ms_auth_design.md` — opaque refresh tokens, Redis JTI blacklist, gateway JWT parsing without a JWT lib
- `resource_expand_db_variants.md` — Mongo/UUID/H2 per-file substitutions in `ResourceExpandProcessor`
- `keycloak_hostname_iss_match.md` — `KC_HOSTNAME` must include the port
- `template_decompressed_dotfiles.md` — why dotfiles use the `dot-` prefix
- `sync_memory_to_repo.md` — after any memory write, mirror to `docs/claude-memory/` and commit+push (durably authorized, no confirmation needed)
