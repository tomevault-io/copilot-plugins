## Overview

This repository is a reusable Node.js library template. It provides build, test, lint, and documentation scaffolding,
and is intended to be copied and customized for a specific library implementation.

## Current Structure

```text
src/                    Source files for the target library
  index.ts              Main entry point (exports all public APIs)
test/                   Jest test files (*.spec.ts pattern)
  index.spec.ts         Template example tests
lib/                    Build outputs (generated by Rollup)
  index.min.js          CommonJS bundle
  index.min.mjs         ESM bundle
  index.min.umd.js      UMD bundle
  index.d.ts            TypeScript type definitions
docs/                   Documentation and release history
  changes-log/          Date-based change entries
  release-notes/        Version-based release notes
README.md               Project overview and setup
CHANGELOG.md            Top-level release history
```

## Module Format & Package Configuration

- **Type**: ESM-first (see `package.json`: `"type": "module"`)
- **Outputs**: Rollup generates three formats: CommonJS, ESM, and UMD (all with source maps)
- **Main entry**: `lib/index.min.js` (CommonJS)
- **Module entry**: `lib/index.min.mjs` (ESM)
- **Types entry**: `lib/index.d.ts` (auto-generated by Rollup using rollup-plugin-dts)
- **Registry**: GitHub npm registry (not public npm)

## Developer Workflows

```bash
npm install
npm run build          # Rollup: builds all formats to lib/
npm run test:run       # Jest: runs tests matching *.spec.ts
npm run test           # Runs lint + test:run in parallel
npm run lint:run       # ESLint check (ts, tsx files)
npm run lint:fix       # ESLint auto-fix (ts, tsx files)
npm run build:docs     # TypeDoc: generates API docs to dist/docs/
npm run dev            # Miniflare dev server (lib/index.min.mjs at localhost:8080)
```

## Code Style & Linting

**ESLint + Prettier** (see `.eslintrc.json`, `.prettierrc.json`):
- No semicolons (semi: false)
- Single quotes (singleQuote: true)
- Trailing commas except in function args
- 120 character print width
- 2-space indentation
- Test files (*.spec.ts, *.test.ts) are linted but excluded from ESLint rules

**TypeScript** (see `tsconfig.json`, `tsconfig.test.json`):
- Target: ES2020
- Module: ES2020 (ESM)
- Strict mode: enabled in tsconfig.base.json, disabled in tsconfig.json for flexibility
- Baseurl: `src` for module resolution
- Output: CommonJS, ESM, UMD via Rollup, not via tsc

## Testing & Type Definitions

- **Test framework**: Jest (configured in `jest.config.json`)
- **Test pattern**: Files matching `*.spec.ts` only
- **Coverage**: Collected from all `.ts/.tsx` files except `.config.ts` files
- **Transform**: ts-jest with `tsconfig.test.json` (stricter type checking for tests)
- **Types generation**: `rollup-plugin-dts` merges all `.d.ts` during build

## Documentation

- **TypeDoc output**: Runs on `src/index.ts` entry point, outputs to `dist/docs/`
- **Release notes**: Per-version files in `docs/release-notes/`
- **Changes log**: Per-date entries in `docs/changes-log/`

## Deployment

- **Azure Static Web Apps**: GitHub Actions workflow in `.github/workflows/azure-static-web-app.yml`
- **Configuration**: `staticwebapp.config.json` manages routing and MIME types
- **Documentation**: See [DEPLOYMENT.md](DEPLOYMENT.md) for setup and deployment instructions
- **Build output**: Deploys `dist/docs/` (TypeDoc-generated API documentation)

## Public API Pattern

See `src/index.ts` for template. All exports from this file become the public API:
- Export interfaces (e.g., `LibraryMetadata`, `HealthStatus`)
- Export utility functions (e.g., `getHealthStatus()`, `createLibraryMetadata()`)
- JSDoc comments on exports are picked up by TypeDoc

## Conventions

- Keep this repository framework-agnostic for broad reuse.
- Treat `src/` as the single place for implementation code.
- Keep `CHANGELOG.md`, `docs/release-notes/`, and `docs/changes-log/` updated for each release.
- Prefer TypeScript-first implementations and maintain strict lint/test discipline.
- Update README and docs whenever the public API or setup behavior changes.
- All tests must have `.spec.ts` extension and be in `test/` directory.
- Rollup handles bundling, minification, and type definition generation — do not commit `lib/` changes.
