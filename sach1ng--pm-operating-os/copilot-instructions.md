# PM-OS Workflows

PM-OS supports the same high-level workflows across both runtimes, but the packaging differs:

- **Cursor** uses generated agents under `~/.cursor/agents/`
- **Codex** uses repo or user skills under `.agents/skills/` and `~/.agents/skills/`

---

## Bootstrap workflows

These are available before you finish setup.

| Workflow | Cursor surface | Codex surface | What it does |
|----------|----------------|---------------|--------------|
| Onboarding | `.cursor/agents/onboarding.md` | `.agents/skills/pm-os-onboarding/` | Collects PM context, writes config, runs setup |
| Company Researcher | `.cursor/agents/company-researcher.md` | `.agents/skills/company-researcher/` | Merges company strategy and product-signal research |
| Company Strategy | `.cursor/agents/company-strategy.md` | `.agents/skills/company-strategy/` | Researches company overview and strategy |
| Company Product Signals | `.cursor/agents/company-product-signals.md` | `.agents/skills/company-product-signals/` | Infers product areas and goals from public signals |

## Generated workflows

These are generated by setup and personalized from `config/pm-os-config.yaml`.

### Feedback Analyzer

- **Trigger examples:** "analyze feedback", "customer feedback", "Slack feedback analysis"
- **Requires:** Slack MCP
- **Behavior:** analyzes feedback themes, compares to PM-OS memory, writes to `memory/feedback/`

### Weekly Planner

- **Trigger examples:** "plan my week", "daily focus", "plan my day"
- **Requires:** Slack MCP + Google Drive MCP
- **Behavior:** reads planning context, creates a prioritized plan, writes to `memory/weekly-plans/`

### Strategy Reviewer

- **Trigger examples:** "strategy review", "check strategic fit", "does this align with our goals?"
- **Requires:** populated `knowledge/`
- **Behavior:** scores PM artifacts against goals, pillars, and product principles

### Exec Update Generator

- **Trigger examples:** "exec update", "status update", "SLT summary"
- **Requires:** best results with Slack + Google Drive MCP
- **Behavior:** compiles a BLUF executive update from PM-OS memory and live context

### Retrospective

- **Trigger examples:** "retrospective", "what patterns do you see?", "strategy drift check"
- **Requires:** enough entries in `memory/`
- **Behavior:** reads across memory and surfaces patterns, drift, blind spots, and recommendations

---

## Runtime notes

### Cursor

- Setup deploys generated agents to `~/.cursor/agents/`
- Workflow invocation happens through Cursor chat and Cursor agent delegation

### Codex

- Setup generates or syncs workflow skills into `.agents/skills/`
- Workflow invocation happens through Codex skills, either implicitly or by explicit `$skill-name`
- Setup also generates `PM-OS-AGENTS.md` and `.codex/config.toml`

---

## Codex v1 limitation

`continual-learning` is not yet a first-class Codex workflow. It remains Cursor-first / experimental because its current transcript-ingestion logic depends on Cursor transcript paths.
