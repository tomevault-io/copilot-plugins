## Commands

Package manager is pnpm (see `pnpm-lock.yaml`).

- `pnpm dev` — start the Vite dev server with HMR
- `pnpm build` — type-check via `tsc -b` then production build via `vite build`
- `pnpm lint` — run Oxlint
- `pnpm preview` — preview the production build locally (serves under the `/portfoilo_sienna/` base path, matching production)

There is no test runner configured in this project.

## Architecture

This is a marketing/portfolio site for jewellery maker Sienna K, built with React 19 + TypeScript + Vite + Tailwind CSS v4 + React Router.

- **Routing**: `src/App.tsx` defines routes (`/`, `/process`, `/gallery`) nested under a shared `src/components/Layout.tsx` (header/nav/footer). Each route's content lives in `src/pages/` (`HomePage.tsx`, `ProcessPage.tsx`, `GalleryPage.tsx`) as one big inline-JSX component per page — there's no further component decomposition within a page. Match this style (data literals + inline Tailwind JSX in one file per page) rather than splitting into smaller components unless asked.
- Page content (jewelry pieces, process steps, gallery groups) is defined as local data literals directly inside each page file, not fetched from a CMS/JSON file.
- `Layout.tsx` also owns scroll-restoration on route change (`useEffect` on `location.pathname`/`location.hash`, using `behavior: 'instant'` — smooth scrolling elsewhere in `index.css` will otherwise race a plain `scrollTo`) and in-page hash link scrolling (nav links like `/#work` from any route).
- Styling is Tailwind utility classes inline in JSX. `src/App.css` and `src/index.css` hold only global/reset styles (custom `--font-display` theme var, scroll behavior, reduced-motion handling) — new styling should stay in Tailwind classes, not new CSS files.
- Tailwind is wired in via the `@tailwindcss/vite` plugin in `vite.config.ts` (no separate `tailwind.config.js`); theme customization happens via the `@theme` block in `src/index.css`.
- `tsconfig.json` is a solution file referencing `tsconfig.app.json` (app source, bundler resolution) and `tsconfig.node.json` (Vite config). `noUnusedLocals`/`noUnusedParameters` are enforced, so the `build` script will fail on unused code.
- Linting uses Oxlint (`.oxlintrc.json`), not ESLint. Configured plugins: `react`, `typescript`, `oxc`.
- `dist/` is gitignored build output, not committed — regenerated by `pnpm build`.

## Deployment

Deploys to GitHub Pages at `https://ai-attack-og.github.io/portfoilo_sienna/` via `.github/workflows/deploy.yml`, which builds and deploys on every push to `main` (or manual `workflow_dispatch`). The intended workflow is feature branches merged into `main`, which then auto-deploys.

Because the site is served from a subpath rather than a domain root:

- `vite.config.ts` sets `base: '/portfoilo_sienna/'`.
- `src/main.tsx` sets `<BrowserRouter basename="/portfoilo_sienna">`.
- `public/404.html` + a restore script in `index.html` work around GitHub Pages having no server-side routing, so direct loads/refreshes of `/process` or `/gallery` don't 404. If either the base path or basename ever changes, both halves of this redirect trick must be updated together (`public/404.html`'s `basePath` constant and `index.html`'s strip-trailing-slash logic) — a mismatch reintroduces a double-slash bug that breaks route matching.

If a custom domain is added later, `base` and `basename` should revert to `/`, and the 404 redirect trick can likely be removed entirely (a `CNAME` file at the domain root doesn't need it if Pages is configured to serve from root — confirm before deleting).
