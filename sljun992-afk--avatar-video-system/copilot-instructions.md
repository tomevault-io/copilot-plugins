> - **목적**: 교수가 텍스트/PPT 내용을 입력하면 AI가 강의 스크립트를 생성하고,

# CLAUDE.md — 교수용 아바타 영상 제작 시스템

## 프로젝트 개요

- **목적**: 교수가 텍스트/PPT 내용을 입력하면 AI가 강의 스크립트를 생성하고,
  HeyGen API로 아바타 영상을 만들어 다운로드까지 제공하는 웹 시스템
- **사용자**: 숭실사이버대학교 교수 약 20명 (비개발자, IT 숙련도 낮음 가정)
- **기술 스택**: FastAPI(백엔드) + HTML/JS(프론트엔드) + HeyGen API(영상) + Gemini API(LLM)
- **최종 품질 목표**: HeyGen 공식 샘플 영상 수준의 결과물
  (자연스러운 아바타 움직임, 깨끗한 음성, 정확한 립싱크, 끊김 없는 재생)

---

## 절대 규칙 (위반 금지)

1. **TEST_MODE를 임의로 다시 켜지 말 것.** 현재 실전 모드로 운영 중.
   테스트가 필요하면 별도 브랜치나 환경변수로 분리하고 사용자에게 먼저 알릴 것.
2. **API 키를 코드에 하드코딩하지 말 것.** 반드시 .env 파일로 관리하고,
   .env는 .gitignore에 포함되어 있는지 확인할 것.
3. **작동 중인 코드를 "개선" 목적으로 임의 리팩토링하지 말 것.**
   요청받은 수정 범위만 건드릴 것. 리팩토링이 필요해 보이면 먼저 제안만 할 것.
4. **HeyGen API 호출 코드를 수정할 때는 크레딧이 소모됨을 인지할 것.**
   테스트 호출 전에 반드시 사용자에게 "실제 크레딧이 소모되는 테스트입니다"라고 확인받을 것.
5. **토큰·비용을 아낄 것.** 검증은 최소한(서버 기동·임포트 확인 수준)으로 하고,
   실 API 호출 검증(Gemini 포함)은 사용자 요청이 있을 때만. 보고는 각 항목 한 줄로 간결하게.
   스크린샷·이미지 확인은 꼭 필요할 때만.

## 검증 루프 (모든 작업에 필수)

1. 코드를 수정한 후에는 반드시 직접 실행해서 에러가 없는지 확인할 것
2. 에러가 발생하면 성공할 때까지 수정을 반복할 것
3. "완료했습니다"라고 보고하기 전에 아래 체크리스트를 통과했는지 스스로 확인할 것

### 백엔드(FastAPI) 수정 시
- [ ] 서버가 에러 없이 기동되는가 (`uvicorn` 실행 로그 확인)
- [ ] 수정한 엔드포인트를 curl 또는 테스트 코드로 호출해 정상 응답(200)을 확인했는가
- [ ] 에러 케이스(잘못된 입력, API 실패)에서 500이 아닌 의미 있는 에러 메시지를 반환하는가

### 프론트엔드(HTML/JS) 수정 시
- [ ] JS/CSS 파일 버전 쿼리스트링을 갱신했는가 (`app.js?v=YYYYMMDDHHMM` 형식)
- [ ] 브라우저 콘솔(F12)에 에러가 없는가
- [ ] 3단계 폼의 전체 흐름(입력 → 스크립트 생성 → 영상 요청)이 깨지지 않았는가

### HeyGen 연동 수정 시
- [ ] 영상 생성 요청 → 상태 폴링 → 다운로드 URL 수신까지 전체 파이프라인이 동작하는가
- [ ] 아바타 유형(교수 1인칭 / 캐릭터·내레이터)에 따라 avatar_id와 voice_id가
      올바른 짝으로 전달되는가
- [ ] 폴링 실패/타임아웃 시 사용자에게 명확한 안내 메시지가 표시되는가

## 품질 기준 — "HeyGen 샘플 수준"의 정의

영상 결과물은 아래 기준을 모두 충족해야 함. 미달 시 원인을 분석하고 수정할 것.

### 스크립트 품질
- 분량: 한국어 550~600자 (약 1분 30초 영상, 상한 2분) — 2026-07-04 정책 변경 (기존 3분에서 단축)
- 아바타 유형별 화법 준수:
  - 교수 아바타 → 1인칭 화법 ("여러분, 오늘 제가 설명드릴 내용은...")
  - 캐릭터/내레이터 아바타 → 3인칭·안내자 화법
- 문어체가 아닌 구어체로 작성 (읽는 글이 아니라 말하는 글)
- TTS가 잘못 읽기 쉬운 요소 제거: 특수문자, 괄호 안 부연, 영문 약어는
  한글 발음 표기 병행 검토 (예: "AI(에이아이)")
- 문장 길이: 한 문장 40자 이내 권장 (긴 문장은 립싱크와 호흡이 부자연스러워짐)

### 영상 품질 (HeyGen API 파라미터)
- 해상도: 최소 1080p (dimension 파라미터 명시)
- 음성: 한국어 자연스러운 voice_id 사용, 속도(speed)는 0.9 적용 중 (또박또박 발음, 2026-07-04 확정)
- 배경: 3단계에서 선택 — 배경 없음 / 템플릿(폼 입력 텍스트 자동 합성) / PPT 슬라이드.
  배경 선택 시 아바타는 오른쪽 상반신 배치(heygen_client.BG_LAYOUT)
- 다운로드 영상은 ffmpeg 후처리로 조립됨: [과목명 인트로 2초 + 페이드] + [본편] + [차렷 엔딩]
  (backend/video_post.py — HeyGen 원본과 다운로드 파일이 다른 것이 정상)
- 결과 영상에서 확인할 것: 립싱크 정확도, 문장 사이 부자연스러운 침묵,
  음성 잘림(스크립트 끝부분 누락) 여부

### 품질 문제 발생 시 진단 순서
1. 스크립트 문제인가? → 스크립트만 TTS로 먼저 확인
2. API 파라미터 문제인가? → HeyGen 대시보드에서 동일 스크립트로 수동 생성해 비교
3. 둘 다 정상인데 결과가 다르면 → API 요청 페이로드를 로그로 남겨
   docs/troubleshooting/heygen-api.md에 기록 후 분석

## 작업 시작 전 인터뷰

- 요구사항이 모호하거나 여러 해석이 가능한 경우, 바로 구현하지 말고
  먼저 핵심 질문 3~5개를 던져 요구사항을 명확히 할 것
- 특히 다음 경우는 반드시 질문할 것:
  - UI 변경: 어느 화면·어느 단계인지 스크린샷이나 구체적 위치 확인
  - 품질 개선 요청: "품질"이 스크립트/음성/영상/속도 중 무엇을 뜻하는지 확인
  - 새 기능: 교수(사용자) 관점에서 어떤 문제를 해결하려는 건지 확인
- 단, 요구사항이 이미 명확한 단순 수정은 질문 없이 바로 진행할 것

## 캐싱 방지 규칙 (필수)

이 프로젝트는 브라우저 캐싱으로 수정사항이 반영되지 않는 문제를 겪었음.
재발 방지를 위해:

1. HTML에서 불러오는 모든 JS/CSS에 버전 쿼리스트링을 붙일 것
   `<script src="/static/app.js?v=202607041200"></script>`
2. 프론트 파일을 수정할 때마다 버전 문자열도 함께 갱신할 것
3. FastAPI 정적 파일 응답에 개발 중에는 `Cache-Control: no-cache` 헤더를 적용할 것
4. 수정 확인 안내 시 사용자에게 "Ctrl+F5로 새로고침하세요"를 함께 알릴 것
