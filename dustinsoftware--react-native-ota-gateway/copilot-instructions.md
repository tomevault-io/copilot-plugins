# Agent Instructions

## Use the docs folder

The `docs/` folder is the canonical reference for this repository's
architecture, strategy, and feature documentation. Before starting work on a
feature or subsystem, read the relevant document(s) in `docs/` to understand
the current design and any constraints.

## Keep the docs up to date

Documentation in `docs/` must stay consistent with the code. Whenever you make
a change that affects anything described in `docs/` -- architecture, APIs,
build/deploy flows, feature behavior, file locations, dependencies, or
strategy -- update the corresponding document(s) in the same change. If a
change makes a document obsolete, revise or remove it rather than leaving it
stale. New subsystems or significant features should get a new document in
`docs/`.
