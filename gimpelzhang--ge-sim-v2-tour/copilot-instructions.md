## What this repo is

A thin orchestration layer (in `scripts/` + `run_stage1.sh`) that drives a
**closed-loop simulation**: a video world model generates frames, a VLA policy
produces actions from those frames, and a remote VLM "World Judge" scores the
result against a task instruction. The heavy ML code lives in the **`gesim`
git submodule** (AgiBot's `GE-Sim-V2`), pinned to an upstream commit. We do
*not* modify submodule code except via a tracked patch (see "gesim submodule").

```
run_stage1.sh        one-shot entry: setup -> services -> preflight -> closed loop -> verify
scripts/             orchestration (Python + bash). ALL our code is here.
  env.sh             sourced in every shell; exports paths, CUDA, conda, MiMo config
  setup_gesim_submodule.sh   init submodule + apply our local patch (idempotent)
  launch_services.py start/probe world-model (HTTP :9000) + policy (WS :8000)
  run_stage1_eval.py 3-demo closed-loop rollout with in-loop MiMo judging
  vlm_reward_client.py MiMoRewardClient — our RewardClient impl (the World Judge)
  download_checkpoints_v2.py chunked Range downloader (resumable, anti-truncation)
  test_mimo_api.py   MiMo preflight (exit 0/1/2 semantics)
  verify_outputs.py  deliverable checks (exit 1 = fail)
  secrets.env         GITIGNORED — real API keys (HF_TOKEN, MIMO_API_KEY, GITHUB_TOKEN)
```

## The closed-loop architecture

```
EpisodeBundle.load(demo) ──► WorldModelEnv(reward=MiMoRewardClient)
        reset(bundle, conditioning="action")
            │
            ▼  (per step, ×8 per demo)
   OpenPIPolicy.infer(obs)  ──► actions (horizon,16)   [WS :8000, π0.5]
            │   compress_actions=True  ──► 25 actions/chunk (not per-frame)
            ▼
   env.step(actions)
      ├─► WorldModelEnv posts actions to HTTP :9000  ──► 25 frames  [GE-Sim 2B, 4 denoise steps]
      ├─► last frame = next obs
      └─► MiMoRewardClient.evaluate(head_frames, task) ──► RewardResult  [remote VLM, in-loop]
            │
   save_video(rollout_multiview.mp4, fps=16)
   MiMoRewardClient.evaluate_with_reasoning(...)  ──► reasoning + final score (post-rollout)
```

**Two services (started by `launch_services.py`, detached, PIDs in `outputs_stage1/logs/*.pid`):**
- **World-model server** — `gesim` env, `python -m gesim.server --model gesim_v2 --config
  configs/gesim_v2.yaml`, HTTP `:9000`, health at `GET /healthz`.
- **Policy server** — `openpi` env, `serve_policy_pi05.sh` (reads `OPENPI_CKPT`, `PORT=8000`),
  WebSocket `:8000`. **No HTTP health endpoint** — probed via a one-shot
  `WebsocketClientPolicy.reset()` round-trip (model load ~30-60s).

**Three demos**: `demo_000`, `demo_001`, `demo_002` (assets in `gesim/assets/`).

## The World Judge: MiMoRewardClient

`scripts/vlm_reward_client.py` is our realization of GE-Sim 2.0's "World Judge".
The upstream repo exposes only the `RewardClient` Protocol
(`gesim/src/gesim/rewards/base.py`: `evaluate(head_frames, task) -> RewardResult` at line 28,
with `success`/`progress` as `(T,)` float32). We supply the backend: Xiaomi **MiMo
`mimo-v2.5`** omni-modal VLM over an OpenAI-compatible API
(`MIMO_BASE_URL=https://token-plan-cn.xiaomimimo.com/v1`). It is remote → costs **no
local GPU**; the A800 only runs world-model + policy.

- `evaluate()` is the Protocol method, called **in-loop by every `env.step`**
  (3 demos × 8 steps = 24 calls) → per-frame `success`/`progress`.
- `evaluate_with_reasoning()` is a non-Protocol extension, called once per demo
  post-rollout → `{success, completion_score, reasoning, judge_source}` for the report.
- Module-load `assert isinstance(MiMoRewardClient(), RewardClient)` enforces the Protocol.
- **Fallbacks (never raises — must not abort the loop):** no `MIMO_API_KEY` →
  heuristic frame-diff (`judge_source="Heuristic-Fallback (No API Key)"`);
  network/5xx error → heuristic with `[Fallback-NetErr]` tag; 4xx API error → 0.0.
- **`max_tokens: 2048`** is deliberate and load-bearing: MiMo emits a chain-of-thought
  `reasoning_content` before the final JSON; the old 256 limit let the CoT eat the whole
  budget so `content` came back empty. Do not lower it.

## gesim submodule (reproducibility model — read before touching gesim)

`gesim/` is a git submodule pointing to **`github.com/AgibotTech/GE-Sim-V2.git`** at an
upstream-fetchable commit. We have exactly **one** local modification — disabling
`sparge_attention` (the `spas_sage_attn` kernel is not on PyPI; the model still runs
via `F.scaled_dot_product_attention`, just slower — plan risk #2). Because we cannot
push to AgiBot's repo, the fix is stored as a **tracked patch** + a setup script:

- **`patches/gesim-disable-sparge-attention.patch`** — the diff.
- **`scripts/setup_gesim_submodule.sh`** — runs `git submodule update --init --recursive`
  then applies the patch **idempotently** (skips if `sparge_attention: false` already present).
  This is `run_stage1.sh` step `[0/5]`.

**Consequences for git status:** after setup, `gesim` shows `(modified content)` —
that is the uncommitted patch in the submodule's working tree. **This is expected and
correct.** The parent repo only tracks the pointer commit, not the patched content.
Running a bare `git submodule update` reverts the patch — re-run `setup_gesim_submodule.sh`
to restore it.

When extending gesim: prefer another patch + setup-script step over committing into the
submodule. Never change `.gitmodules` to a private fork URL without confirming the fork is
pushed and durable.

Checkpoints (~12GB) are downloaded by `scripts/download_checkpoints_v2.py` into
`gesim/checkpoints/` (gitignored). It uses **chunked Range requests** (8MB) and
**appends only on HTTP 206**, rejecting 200 responses — this avoids the truncation
bug that `curl -C -` hit when the CDN ignored Range. Resumes from local file size.

## Conventions

- **Python style:** `from __future__ import annotations` first; explicit `Path` for
  filesystem; type hints on signatures; module docstrings explain *why*, not just *what*.
- **Fail-safe by design:** the closed loop must never abort on a flaky remote (MiMo).
  Catch network/5xx → heuristic fallback; only 4xx API logic → 0.0.
- **Transparency in reports:** `judge_source` always records who scored (MiMo vs heuristic
  fallback). `outputs_stage1/stage1_eval_report.md` carries a "判分透明声明" header.
- **Outputs are not version-controlled.** `outputs_stage1/`, `*.mp4`, `*.log`, `*.pid`,
  `checkpoints/`, `reward.npy` are all gitignored. They are regenerated by re-running the eval.
- **Commit hygiene:** commit messages are imperative + body explains *why*; end with
  `Co-Authored-By: Claude <noreply@anthropic.com>`. Do not commit secrets, large artifacts,
  or `.omc/` (OMC state).
- **Shell cwd gotcha:** background/parallel Bash calls here have reset the cwd to `gesim/`
  before. Use absolute paths (`/mnt/GE-Sim-V2-tour/...`) or `git -C <dir>` — do not rely on
  a cwd persisting across calls.

### Stage 2 gotchas (full detail in Complete_Stage_2.md)

- **ARK inpaint was the #1 risk.** Upstream `doubao-seededit` is deprecated; the
  fix is `doubao-seedream-5-0-pro-260628` + `response_format="b64_json"` (image
  inline, bypasses the flaky TOS CDN) + SIGALRM 150s hard timeout + size floor
  960x960 (auto upscale/downscale to preserve alignment). All in
  `patches/r2e2r-update-inpaint-model.patch`.
- **CUDA-pinned conda env is fragile.** Use libmamba + system gcc (not conda
  gcc); env is read-only after creation.
- **`no_proxy="*"` + `HF_HUB_OFFLINE=1` are load-bearing** - the local
  quickqservice proxy (127.0.0.1:10900) hangs on long ARK/aria2c calls.
- **H5 schema is nested** (`/state/joint/position: (580,14)`, `/action/{left,right}_effector/position`),
  NOT flat `(T,16)` - the original plan's errata predicted this correctly.
- **Use R2E2R's native batch** (`n_gen_per_source` + `mode: full_random`), not a
  custom 5x10 sampler loop.
- 4/50 episodes fail curobo IK under `relax_thresholds` - this is expected, not
  a bug. Threshold: ≥40 (actual: 46).
- **Video render: `pkg_resources` missing (坑 M).** `setuptools 83.x` removed
  `pkg_resources`; `imageio-ffmpeg` (via `moviepy`) imports it at load. Fix:
  `pip install --no-deps "setuptools==80.10.2"` (CUDA-safe, pure-Python).
- **Video render: writes hardcoded into the full /mnt disk (坑 N).** Redirect via
  shadow file-level symlinks to `/home/vipuser` + absolute `output_root` config.
- **Video render: OOM-kill at clip 6's save_video (坑 O).** The `save_video` step
  spikes RSS ~12GB (rearrange + clamp copy the full ~4GB video tensor) on top of the
  resident model + depth/canny - an in-process peak that `gc` after the save cannot
  prevent. Fix (patch + orchestrator): `--single_clip` mode + `render_per_clip`
  driver runs each clip in a **fresh subprocess** so the OS reclaims all memory
  between clips (resume-skip + post-save gc also added, but per-clip subprocess is
  the load-bearing fix). Driver: `render_stage2_videos.py render_per_clip`.

### The format bridge (the #1 technical risk)

gesim `WorldModelEnv.reset(episode, conditioning="action")` only accepts an
`EpisodeBundle` (Stage-1 flat `.npy` layout). R2E2R episodes use a **completely
different disk schema** (`aligned_joints.h5` nested + camera JSONs + PNGs), and
there is **no** `env.reset(episode_path=...)` API. `convert_r2e2r_to_bundle.build_bundle()`
assembles an `EpisodeBundle` in memory (intrinsic from JSON, extrinsic 4×4 from
JSON, first_frame from 3 PNGs, initial_state from H5 `/state/joint/position[0,:14]`
+ grip from **`/action/{left,right}_effector/position[0,0]`** [normalized command,
NOT `/state/` encoder counts], head_waist from H5 head+waist; `actions`/`eef_poses`
are `None`). The staging-dir disk-read caveat is documented below in 坑 A.

### Stage 3 gotchas

- **Task text feeds THREE coupled consumers (坑 B, the #1 hidden trap).**
  `SOURCE_TASK_TEXT` (in `convert_r2e2r_to_bundle.py`) is the Stage-2 **lift_box**
  task (`"Pick up the box on the table with both arms and lift it."`), NOT the
  Stage-1 kettle-pouring task. This ONE constant drives (1) the π0.5 policy prompt
  (`obs.task` -> server `"prompt"`), (2) the WM `set_task`, and (3) the MiMo judge
  criterion. The first run used the wrong (kettle) text -> 0% OSR was a
  task-criterion artifact (MiMo saw box scenes but judged kettle-pouring). If OSR
  is 0%, first check the task text matches the scene, not the model strength.
  The `pi05_gesim_g01op_test` checkpoint was trained on Stage-1 demos (kettle/
  facial-cleanser/towel), NOT lift_box - so the corrected 6.5% OSR is cross-task

### The RWR algorithm (corrected from REINFORCE)

π0.5 is flow-matching: `forward(obs, actions)` returns `F.mse_loss(u_t, v_θ)` on
the velocity field (differentiable, no log_prob). `sample_actions` is
`@torch.no_grad` 10-step Euler (no density). So RWR reuses the native loss:
```
R(τ) = MiMo completion_score (with action-smoothness penalty)
w(τ) = softmax((R - b) / temp)   over the trajectory's steps
loss = Σ w_t · model.forward(obs_t, a_t_taken).mean()   # a_t in model layout, normalized
backward -> clip_grad(1.0) -> AdamW.step (small head only) -> empty_cache
b ← 0.9·b + 0.1·R   (EMA baseline)
```
`flow_matching_loss` re-runs the policy's full transform chain (`GesimInputs` +
`Normalize` + tokenizer) on the recorded obs, reorders actions WM->model layout
(`_wm_to_model_layout`), re-normalizes via the extracted `Normalize` transform,
and calls `model.forward()` inside `disable_typechecking()`. Exploration noise
`N(0,0.05)` is added to `sample_actions` output in WM layout BEFORE `env.step`
(affects data collection only, not the loss).

### Architecture (reverse tunnel)

The agent (one per job, no GPU) connects to `ws://120.92.88.78/api/challenge/
tunnel?job=<uuid>&agent=<id>` with `Authorization: Bearer <job_token>`. Control
frames are JSON text (`warmup`/`session_open`/`session_close`/`drain`); data
frames are binary `[uint32 BE sid_len][session_id][msgpack_numpy payload]`.
Each obs is a JSON-RPC `{"method":"infer","params":{images{head,hand_left,
hand_right}, states{arm_joint_states[14],gripper_states[2],waist_joint_states[5]},
prompt, task_name}}` -> we decode JPEGs, call the shared Stage-1 policy server
over WS, reorder actions, and reply with a `JOINT_ABS` envelope (horizon 50
instruction / 30 manip, all arrays `.tolist()`).

### Stage 5 gotchas

- **T1 - gateway decodes with plain msgpack** (not msgpack_numpy): every array
  in the reply envelope must be `.tolist()`, or the platform-side decode fails.
- **T2 - warmup empty frame**: `session_id=""`, `frame=b""` must return `b""`
  without raising, before any session is open.
- **Three 16-D layouts**: policy-input grip-last `[L7,R7,Lg,Rg]`; policy-server
  output WM-interleaved `[L7,Lg,R7,Rg]` (same as Stages 1-4); envelope slice
  basis grip-last. Reorder: `acts[:,0:7]=wm[:,0:7]; acts[:,7:14]=wm[:,8:15];
  acts[:,14]=wm[:,7]; acts[:,15]=wm[:,15]`.
- **Login is POST JSON to `/api/challenge/login`** (GET -> 405; email must be
  whitespace-stripped). `/api/challenge/job/<id>/result` takes the **numeric**
  job id from `/api/challenge/jobs` `items[].id` (uuid -> 500). Quota is 99
  total (not 4/day). Jobs-list key is `items`.
- **`no_proxy` must NOT be `"*"` for Stage 5**: the tunnel gateway is dialed
  direct (`websockets proxy=None`); use precise `no_proxy="localhost,
  127.0.0.1,::1"` so localhost policy-server calls bypass the flaky
  quickqservice proxy. (Opposite of Stages 2-4 where `"*"` was load-bearing.)
- **Two agents share one policy server** (agents hold no GPU; :8000 ~10G VRAM).
  The policy client serializes with a lock + 3-retry reconnect.
- **Official SDK unpublished**: TunnelClient ported from ACoT-VLA
  `scripts/tunnel_agent.py` (branch agibot_world_challenge) - equivalent impl.
- **Security**: credentials live only in `/mnt/genesis-world-tour-docs/
  user_access_methods.txt` (never print/commit) and `~/.simubotix-challenge.env`
  (chmod 0600; password deliberately NOT persisted). `drain` -> exit 0, never
  reconnect. Kill agents by pid file; kill the policy server by real process
  name (`ps aux | grep serve_pi05`), not the conda-run wrapper pid (坑 I).
