# AGENTS.md — AMT 协作、开发与交付规范

本文件约束本仓库的分析、设计、开发、验证、Git 和发布行为。目标是在明确授权边界内，把 AMT 做成专注、可靠、可恢复的 Antigravity 多账号配额雷达与接力管理器，避免重新引入已经裁掉的网关能力、无关复杂度和高风险操作。

## 1. 项目定位与指令适用

- AMT 是 Google Antigravity 的本地桌面账号中枢：前端为 React 19、TypeScript、Vite、Zustand、Tailwind CSS 和 shadcn/ui；桌面后端为 Tauri 2、Rust、Tokio、SQLite 与原生系统凭据库。具体版本以 `package.json`、`package-lock.json`、`src-tauri/Cargo.toml` 和锁文件为准。
- 产品只围绕账号入库、真实配额、推荐接力、设备身份、原生客户端切换、后台刷新、周配额预热、数据维护与应用更新组织能力。
- AMT 不是 API 网关。不得重新加入 OpenAI、Anthropic、Gemini 兼容端点、HTTP 服务、Headless/Docker 服务端、模型路由器、协议适配器、代理池、请求日志、Token 消耗统计、IP 黑白名单、API Key 分发或 Web 管理后台。
- `network_proxy` 仅表示 AMT 访问 Google、GitHub 等外部服务时使用的出站 HTTP/SOCKS 代理，不得扩展成对外 API 反代或账号代理池。
- 本仓库 `wuyunfeng8/Antigravity-Manager` 是独立项目，不再跟随源 Fork 网络。运行时代码、安装脚本、更新地址、Cask 和发布工作流均以本仓库为权威；历史 CHANGELOG 可保留原 Issue/PR 链接，README 保留简短来源致谢。
- 遵守系统、运行环境和工具的更高优先级要求。在其允许范围内，用户当前明确指令和已批准方案优先于本文件的默认流程、Skill 建议和历史记录。
- Skill 提供完成任务的方法，不自动扩大任务范围或操作权限。旧文档、历史提交、上游实现和记忆只用于理解背景，不代表当前产品要求或已验证事实。
- 当前代码反映实际实现；Tauri 命令、Rust 数据结构、配置模型与本地持久化格式共同构成实现事实。用户明确需求决定预期行为。发生冲突时说明差异，不把历史网关逻辑视为必须恢复的兼容能力。

## 3. 自主执行、澄清与批准

### 3.1 可以直接完成的工作

在当前任务已授权范围内，可以直接：

- 阅读相关 TypeScript、Rust、配置、工作流、锁文件和 Git 状态，定位现有实现及直接调用者。
- 修复普通 UI 状态、类型、布局、Tauri 权限、配置迁移、错误处理和跨平台路径问题。
- 删除已经确认无引用、无兼容责任且属于当前目标范围的代码、依赖、翻译键和静态资源。
- 使用现有依赖和工具运行定向构建、单元测试、Clippy、格式检查、JSON/YAML/Shell 静态校验。
- 使用临时目录、测试账号结构或纯前端 Mock 验证，不接触真实 Token、Keychain、`state.vscdb` 或 `storage.json`。
- 对旧配置做向后兼容读取并在保存时规范化，前提是不破坏当前账号数据和可恢复性。
- 修正仓库内部链接、README、安装脚本、更新地址和当前独立仓库元数据。

“先说明原因”“先形成方案”“核对范围”属于沟通要求，不等于所有普通修复都必须暂停等待。

### 3.2 必须具有明确授权的事项

以下事项缺少具体授权时必须先说明并等待：

- 对真实账号发起 OAuth、提交授权码、刷新或撤销 Refresh Token。
- 将账号写入 macOS Keychain、Windows Credential、CLI Keyring、Antigravity SQLite 或其他原生凭据库。
- 切换真实账号、覆盖 `storage.json` 设备身份、写入 `state.vscdb`、结束或重新启动 Antigravity/IDE/CLI 进程。
- 删除真实账号、历史设备身份、原始备份、缓存目录或 AMT 数据目录；迁移或清理用户真实文件。
- 修改 Bundle ID、数据目录名、账号 JSON 格式、Token 存储方式或更新签名公钥，且没有明确迁移/兼容方案。
- 生成、读取、复制、上传或轮换私钥、签名密码、OAuth Client Secret 等敏感材料。用户明确授权配置时也不得在日志和回复中输出内容。
- 创建 Tag、发布 Release、上传安装包、触发会发布产物的工作流、部署网站或修改 GitHub 仓库设置。
- 引入新的第三方依赖、全局安装软件或修改任务外的本机设置；锁文件内已经声明的依赖恢复不属于新增依赖。
- 大规模改变产品定位、删除核心账号/配额/切换能力、恢复网关架构，或改变账号接力与设备身份的核心语义。
- 推送、Force Push、重写历史、删除远端分支、合并 PR；普通本地代码修改不自动包含这些动作。

### 3.3 复用授权，不重复询问

- 先检查当前任务已有明确授权和已批准方案。目标、动作、范围、接收方与环境已经明确时，不因换工具、重试或上下文恢复重复确认。
- 授权只覆盖具体内容。新的账号、仓库、数据目录、密钥、发布目标或不可逆后果超出原范围时重新确认。
- 等待用户决定时，只暂停依赖该决定的步骤；继续完成独立的只读调查、代码准备和安全验证。
- 工具要求在操作时再次确认或由用户接管敏感输入时，遵守工具要求。密码、私钥不得要求用户粘贴到聊天。

### 3.4 区分产品确认与代理批准

- 产品中的账号删除、设备身份恢复、缓存清理、数据迁移、更新安装等危险操作应保留清晰确认。
- 实现这些确认交互不等于实际点击执行；已授权的代码修复不因此需要额外批准。
- 在真实环境执行确认按钮、系统对话框或写入命令，仍须满足本节授权边界。

## 4. 开发执行方式

1. 查看 `git status --short --branch`，识别用户已有改动和未跟踪文件。不要重置、覆盖或顺手清理与任务无关的内容。
2. 读取本文件、相关依赖声明、直接相关模块和必要配置。不要每次无差别扫描整个仓库或 `target`、`node_modules`。
3. 沿实际链路检查 React 页面/Store/Service/Tauri Command/Rust Module/本地文件或系统集成，避免只修界面或只修后端一端。
4. 修改前给出简短说明：根因或目标、主要文件、实施方式、风险和最小验证集合。复杂架构或 UI 方向按对应章节执行。
5. 优先复用当前模块和 shadcn/ui primitive，保持命名、错误结构、Tauri 参数转换和跨平台逻辑一致，做最小但完整的根因修复。
6. 对持久化和进程操作优先采用可恢复、幂等和原子方式；不以硬编码路径、静默吞错或删除重建掩盖状态问题。
7. 运行定向验证并自查 diff，删除自己引入的调试输出、临时文件、无用依赖、失效翻译和未使用 import。
8. 完成目标直接需要的配置、文档和工作流配套，不在首次编译通过后提前结束。
9. 每完成一项有文件改动的任务，按第 10 节立即创建独立本地 commit，并在交付时报告提交号；不要积累多个已完成任务到推送时再拆分。

实现优先级：

- **P0：优先处理。** 构建失败、应用无法启动、账号数据丢失、凭据泄露、错误覆盖 Keychain/SQLite、更新签名失效、核心切换流程阻塞。
- **P1：默认处理。** 配额口径错误、订阅等级误判、切换后状态不同步、设备身份未应用、配置迁移失败、跨平台路径错误、危险操作缺少确认。
- **P2：小范围低风险时处理。** UI 一致性、可访问性、重复代码、命名、无用资源、包体和性能优化。

优先级只决定授权范围内的顺序，不豁免第 3 节的权限边界。

## 6. 核心架构与业务事实

### 6.1 分层职责

```text
React 页面 / 组件
      ↓
Zustand Store / services / request
      ↓ Tauri invoke
commands
      ↓
modules（账号、OAuth、配额、设备、集成、进程、配置、更新）
      ↓
本地 JSON / Keychain / SQLite / storage.json / Google API
```

- React 页面负责呈现、交互和短生命周期状态，不直接实现 Token 刷新、SQLite 注入、进程探测或系统凭据写入。
- Store 负责前端共享状态和调用编排；Service 维护稳定的命令参数转换；Tauri Command 是 IPC 边界，不堆积核心业务。
- Rust Module 承载业务规则、跨平台处理、文件原子性、外部请求和系统集成。共享逻辑不能复制到多个 Command 或前端页面。
- 新增 Tauri 命令时同步检查 `lib.rs` 注册、capability 权限、前端类型、参数命名和错误序列化。

### 6.2 账号与凭据

- 账号真实数据保存在 AMT 数据目录的 `accounts.json` 和 `accounts/*.json`；默认目录为 `~/.antigravity_tools`，可通过持久化指针迁移。
- `Account.token` 包含 Access Token、Refresh Token、ID Token、项目 ID 等敏感信息。不得写入日志、Toast、错误详情、测试快照、README 或 Git。
- 导出账号 JSON 明确包含 Refresh Token，UI 必须提示敏感性；不得自动上传或通过外部服务处理。
- 账号文件与配置使用 `utils::fs::write_atomic`；Unix 临时/目标文件保持 `0600`。不得退回普通覆盖写或在失败后删除原文件。
- 账号索引损坏时保留备份并尽力重建，不因单个账号文件读取失败静默删除索引记录。
- 测试账号和临时数据必须使用唯一临时目录，并通过 `ABV_DATA_DIR`、`ABV_DATA_DIR_POINTER_FILE` 隔离；严禁污染真实 `~/.antigravity_tools_location`。

### 6.3 配额与订阅等级

- `loadCodeAssist` 返回的订阅信息是 FREE/PRO/ULTRA 的唯一权威来源。不得根据邮箱、标签、模型目录、模型名称或剩余比例猜测账号等级。
- 模型目录对不同等级可能相同，禁止恢复“出现 Claude/GPT 即为 Pro”之类推断。
- UI 只聚合 Claude、Gemini Pro、Gemini Flash 和必要图片模型的真实配额族，不重新展示共享同一桶的大量变体噪声。
- 5 小时滑动窗口和周配额是不同口径。周配额耗尽可覆盖当前展示，但不得篡改后端用于刷新和保护的原始数据。
- 配额请求失败、429、403、需要验证和 Token 失效必须区分；缓存只能作为有时效的降级展示，不得伪装成实时成功结果。
- 推荐接力排除当前账号、禁用账号、验证受阻账号和 forbidden 账号；评分规则保持集中且可解释。

### 6.4 账号切换全链路

```text
选择目标账号
  → 校验账号与 Token
  → 定位 Antigravity 主程序
  → 保存当前进程路径与启动参数
  → 按客户端版本写入系统凭据库或兼容 state.vscdb
  → 应用账号绑定的设备身份
  → 更新当前账号记录
  → 重新启动目标客户端
  → 刷新托盘与前端状态
```

- 新版客户端优先使用原生 Keychain/Credential 方式；旧版或兼容客户端按现有 SQLite 注入流程处理，不把两套格式混写。
- 修改 `state.vscdb` 前保留已有备份；数据库路径定位沿用跨平台候选与进程快照，不写死单一用户名或安装目录。
- 切换前获取实际运行程序路径和参数，重启时优先复用快照；不能误杀 helper、其他编辑器或用户无关进程。
- 当前账号 ID 只有在凭据/状态写入链路成功后才视为有效切换；失败时返回可处理错误并保持可恢复状态。
- 1.1.0 只对外提供 Antigravity 主程序账号切换；历史 IDE/CLI 数据导入可保留兼容读取，不再作为切换目标暴露。

### 6.5 设备身份

- 设备身份限定为 AMT 当前管理的 `machineId`、`macMachineId`、`devDeviceId`、`sqmId` 及相关 service machine ID。
- 生成、绑定、应用、历史版本和恢复原始身份必须区分；预览不落盘，绑定后切换时才按契约应用。
- 写入 `storage.json` 前保存备份；恢复操作不得删除全部历史或覆盖唯一原始基线。
- 路径缺失是可解释状态，不自动创建伪造的 Antigravity 配置结构。
- 文案只描述“设备身份隔离、降低关联风险”，不得承诺防封、完全拟真、不同物理设备或规避平台风控。

## 7. 前端与 UI

### 7.1 设计系统

- 所有业务 UI 使用 `@/components/ui/*` 对应的 shadcn/ui primitive 与 Tailwind CSS。已有相同 primitive 时不得手写按钮、输入框、开关、弹窗、下拉菜单、标签、进度条或表格。
- 禁止恢复 Ant Design、DaisyUI、Lobe UI 或一次性自绘组件；不得用 `peer` hack 手写 Switch、用裸 overlay 手写 Dialog，或依赖内部 DOM 选择器覆盖组件。
- 颜色、圆角、边框、背景和语义使用设计 token。减少重阴影、多层渐变、卡片套卡片、无意义动画和彩色图标。
- 优先使用清晰的信息层级、留白和对齐解决问题，不用装饰元素掩盖结构混乱。

### 7.2 UI 设计门禁

- 新页面、实质性重构、导航变化或新的核心流程必须先完成 UI/UX 分析，并按 Product Design Skill 提供至少两套可交互 HTML 方案。
- 原型必须能实际切换页面、筛选、点击关键按钮和反馈状态，不用静态截图代替交互验证。
- 等用户选择后再修改生产 `.tsx/.css`。选定方案之外的实验文件不得进入生产代码。
- 小型 bug、原生窗口拖拽、文案错误、视觉对齐、现有组件替换和无争议的一致性修复无需制作 A/B 原型。

### 7.3 当前产品信息架构

- 主界面遵循 Relay Focus：当前主力、三类核心配额、推荐接力、账号池。不得恢复无业务价值的仪表盘、营销页脚、重复统计卡和协议代理入口。
- 账号池默认使用卡片视图；不恢复卡片/表格双模式、分页、拖拽排序和批量选择，除非有明确的新需求和实际规模证据。
- 账号卡片只显示接力判断所需信息：账号名/邮箱、等级、健康状态、三类配额、当前/推荐标识和主要切换动作。低频动作收纳到 DropdownMenu。
- 添加账号以 Google OAuth 为主入口，Refresh Token 和数据库导入为高级入口；不得重新加入 Web/Headless 登录分支。
- 设置分为基础设置、账号与配额、维护工具、关于。低频路径、缓存、数据目录、网络代理和调试能力放入维护工具，不与日常设置争夺层级。
- 迷你视图只显示当前账号核心配额、刷新、返回完整视图和推荐接力，不复制完整管理页面。
- About 页、README、安装链接和更新地址统一指向 `wuyunfeng8/Antigravity-Manager`。

### 7.4 状态、交互与可访问性

- 每个异步操作明确处理 idle、loading、success、error；提交中禁用重复操作，结束后刷新必要状态。
- 删除账号、恢复原始设备身份、清理缓存、迁移数据目录和安装更新保留确认；刷新、筛选、复制等可恢复操作不增加多余确认。
- 错误提示给出用户可继续处理的信息，不显示 Token、完整上游响应、系统路径中的隐私内容或 Rust stack trace。
- 图标按钮必须提供 `title` 或可访问文本；Dialog 具备 Title/Description；表单使用 Label；键盘焦点和 Esc/Enter 行为保持可用。
- 所有新增文案进入 i18n，只维护英文和简体中文；非中文系统语言及旧配置回退英文，所有中文地区代码归入简体中文。不在代码中散落中文业务文案。
- macOS Overlay 标题栏保留独立拖拽区域；拖拽层不得设置 `pointer-events-none` 后再依赖鼠标事件，也不得覆盖侧栏交通灯和页面按钮。
- 大型页面使用路由/组件懒加载；不为消除构建提示而制造循环 chunk。删除 UI 时同步删除依赖、组件、翻译和后端死命令。

## 8. 配置、更新、发布与安全

### 8.1 配置兼容

- `gui_config.json` 只保留当前桌面能力。旧 `proxy` 配置可迁移其 `upstream_proxy` 到 `network_proxy`，其余网关字段应在规范化保存时丢弃。
- 新配置字段使用 serde 默认值，保证旧文件可加载；删除字段时评估是否需要一次性迁移，不让未知字段永久膨胀。
- 数据目录迁移只有一个权威实现，禁止在 Command 和 Module 各维护一套复制/删除逻辑。
- Bundle ID `com.lbjlaq.antigravity-tools` 当前为升级兼容标识，不等于仓库归属。未制定已有安装、数据目录、自动启动和更新迁移方案时不得修改。

### 8.2 自动更新签名

- Tauri updater 签名不可绕过。`tauri.conf.json` 只保存公开验证公钥；私钥和密码只存放在安全本机位置与 GitHub Actions Secrets。
- GitHub Secret 名称固定为 `TAURI_SIGNING_PRIVATE_KEY` 和 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。不得输出值、提交密钥文件、写入 `.env` 或通过聊天传递。
- 本机私钥放在仓库外，例如 `~/.tauri/amt-updater.key`，Unix 权限设为 `0600`，并保留独立离线备份。
- 公钥轮换会影响已安装客户端。首次正式 Release 后，除非具备旧私钥签名的过渡方案，不得直接替换 updater 公钥。
- 使用 Tauri CLI 2.10.1 或更新兼容版本生成密钥，避免已知的 2.10.0 空密码密钥问题。

### 8.3 Release

- 版本号同步检查 `package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`、`src-tauri/tauri.conf.json` 和变更记录；使用 bump 脚本。Cask 保持上一已验证版本，拿到新版 DMG 的实际 SHA-256 后再更新版本与哈希，不得只改版本号。
- Release 工作流只从本仓库构建；安装包、Updater URL、README、安装脚本和 Cask 的仓库/文件名必须一致。
- 发布前至少通过第 9 节发布门禁，并确认两个签名 Secret 存在。不得以读取不到 Secret 值为由打印或重新生成密钥。
- Tag、Release 和产物上传是外部发布动作，必须有明确授权。普通 `main` 推送不自动打 Tag。
- 发布说明按需要感谢贡献者并准确描述其贡献；不把历史源仓库贡献归为本项目原创。

## 9. 定向验证与环境边界

### 9.1 最小有效验证集合

| 改动 | 默认验证 |
| --- | --- |
| React 页面、组件、Store、Service | `npm run build`；有定向测试时运行对应测试 |
| Rust Module、Command、模型 | 对应单元测试或 `cargo test <模块/测试名>`，再运行 `cargo check` |
| Rust 格式与常规质量 | `cargo fmt -- --check`；提交前或跨模块改动运行 `cargo clippy --all-targets --all-features -- -D warnings` |
| 账号文件、配置和迁移 | 临时目录测试；验证原子写、损坏恢复、权限与真实目录不被污染 |
| Keychain、SQLite、设备身份、进程 | 优先静态/Mock/临时副本；真实操作必须按第 3 节授权 |
| Tauri 配置、capability、插件或 bundle | `cargo check`、`npm run build`；必要时 `npm run tauri build -- --debug --no-bundle` |
| UI 重构 | 构建、选定原型对照、关键断点和实际 Tauri 窗口检查 |
| i18n JSON | 解析全部 `src/locales/*.json`，检查新增键和 fallback |
| CI/Release YAML | YAML 解析、工作流路径与 Secret 名称检查 |
| Shell/Cask/安装脚本 | `bash -n`、`ruby -c` 及关键 URL/产物名静态核对 |
| 文档与注释 | 内容检查、链接目标和 `git diff --check`，通常不运行代码测试 |
| 直接提交推送 | 暂存范围、敏感文件和 Git 结果检查，不重新启动测试矩阵 |

### 9.2 标准本地门禁

```bash
npm run build

cd src-tauri
cargo fmt -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo check
```

- `cargo fmt` 在提交 Rust 改动前必须执行；不能提交会让 `cargo fmt -- --check` 失败的代码。
- `npm audit` 结果需区分生产依赖与开发依赖；不使用破坏性升级只为清零无实际影响的提示。
- Tauri Debug 构建通过不等于 macOS/Windows/Linux 正式签名安装包均通过。多平台 Release 结果以 GitHub Actions 为准。
- 静态代码与本地测试不能证明真实 Google 服务可用、账号未受风控、Keychain 写入成功、不同 Antigravity 版本均兼容或自动更新已经端到端完成。

### 9.3 测试隔离

- 测试临时路径使用 UUID 或 `tempfile`，不能使用毫秒时间戳作为唯一标识。
- 修改进程环境变量的测试必须串行隔离、恢复原值，并避免 Mutex 中毒导致级联失败。
- 不读取、覆盖或删除真实 `accounts.json`、账号文件、Keychain、`storage.json`、`state.vscdb` 和数据目录指针。
- 网络测试不得使用真实账号 Token；需要外部服务时说明边界并优先 Mock。

### 9.4 失败处理

- 先确定失败属于本次改动、既有基线、平台环境、网络或外部服务，不把所有失败归因于当前代码。
- 修复直接相关的失败后重跑最小集合。范围外失败记录命令、错误和影响，不扩展成无授权重构。
- 同一条件失败时不无限重试；切换有依据的验证方式，或报告明确阻塞。
- 不通过关闭测试、移除断言、吞掉错误、添加大范围 allow 或降低 CI 门禁来制造通过。

## 10. Git 与仓库操作

- 修改前检查当前分支、工作区和暂存区。用户已有改动属于用户，不回滚、不覆盖、不清理，也不暂存或提交无关改动；不用 `git checkout --`、`git reset --hard` 删除用户内容。
- 完成代码、文档或配置修改后检查本次 diff 并执行 `git diff --check`。区分本次改动与用户已有改动，不借检查顺手改动任务外文件。
- 每完成一项有文件改动的任务，默认立即创建该任务的独立本地 commit；本规则即为持续的本地提交授权，无需再次询问。用户明确说“先别提交”“只分析”“先给方案”时遵守其限制。推送、创建 PR、合并、Tag、Release 和部署仍须明确要求，不因本地提交获得授权。
- 按任务拆分提交：一项任务直接相关的实现、配套文件和验证放在同一个 commit；不同任务不混为一个 commit，不按文件或工具调用机械拆分。已完成任务后的新修正另建 commit，默认不 amend、squash 或重写已有记录。
- 提交标题和说明正文使用清晰中文。标题概括解决的问题或实现的功能；正文说明原因、主要改动、实际验证结果，以及必要的兼容或迁移边界。避免“更新”“优化”“修复问题”等无法识别任务的空泛信息。
- 本地提交前完成本任务必要的定向验证和 diff 检查，只精确暂存目标改动。共用文件含用户或其他任务改动时，按差异块暂存或使用等效安全方式拆分；不得覆盖工作区内容。私钥、Refresh Token、OAuth 凭据、`.env`、账号导出 JSON、真实数据库、日志、无关备份和临时产物不得进入 Git。
- 只读分析、无文件改动和仅操作真实数据而未形成仓库改动的任务，不创建空 commit，也不为了提交而额外修改文件。
- 延续当前任务的“提交推送代码”默认推送本轮已完成任务的独立 commits，并按任务补齐遗漏的目标改动；不得把已有独立记录重新合并。“把所有改动全部提交推送”才包括用户明确纳入的完整范围，仍排除凭据和无关备份。
- 直接提交推送先核对提交记录、目标范围和敏感文件；已有独立提交则直接普通推送当前正确分支，遗漏改动按任务分别提交后再推送。不重复启动已完成的测试，不额外增加版本号、CHANGELOG、文档更新或 PR 流程。
- 工作区干净时不创建空提交，但要检查本次授权范围内是否有待推送 commit；存在则继续普通推送。没有目标改动且没有待推送提交时，报告无新内容。
- 推送被拒时先 fetch 并检查分歧；必要时保护其他改动后安全 rebase，恢复并核对保留内容。不得 Force Push；无法确定冲突取舍时暂停该步骤并说明。
- 不以推送后整个工作区干净为目标；本次目标提交和推送结果确认即可，用户其他改动保持原样。
- 仓库已独立，默认不添加源仓库为 GitHub Fork。需要参考时可使用本地只读 `reference` remote，不自动合并上游。创建 PR 后附加到当前任务；没有用户要求时不为直接推送额外创建 PR。

## 11. 完成与交付

实现任务完成前确认：

- 用户目标已实现，不只给方案或完成单个局部。
- 直接调用链、配置、错误状态、i18n 和删除后的引用已同步处理。
- 没有遗留调试输出、临时服务器、原型文件、无用依赖或失效资源进入生产代码。
- 必要验证通过；未运行或无法运行的验证有明确原因。
- 真实账号、真实设备、生产 Release 和跨平台结果没有被静态检查冒充验证完成。
- 有文件改动的任务已有独立本地 commit，除非用户明确禁止提交；未获推送授权时保留本地提交，不操作远端。

最终回复应简洁说明：

1. 完成了什么以及关键行为变化。
2. 主要文件或入口。
3. 实际运行的验证及结果。
4. 未验证边界、剩余风险或用户需要执行的后续动作。
5. 有文件改动时给出本地 commit 和分支；若获授权推送，再报告远端结果及保留的其他改动。

不要把工具调用过程、无关探索和重复状态堆进最终回复；也不要把“构建通过”描述为真实账号切换、生产签名发布或全平台验收完成。
