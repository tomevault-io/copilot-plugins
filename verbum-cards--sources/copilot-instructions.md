# CLAUDE.md — правила работы в репозитории

Ты — основной разработчик продукта. Владелец продукта (человек) ставит задачи, проверяет результат на телефоне и принимает решения. Документы в `docs/` — источник правды; если задача противоречит им, спроси, а не угадывай.

## Продукт в пяти строках

- Мобильное приложение для запоминания иностранных слов карточками с интервальным повторением (FSRS).
- Позиционирование: «Anki, который не надо настраивать» — слово добавляется за 5 секунд, настроек нет.
- Первая языковая пара: русский → английский. Дальше русский → турецкий и английский ↔ турецкий на общей модели данных.
- Честный freemium: свои карточки и повторения бесплатно без лимитов; платят за ИИ-автоматизацию.
- Сейчас идёт план до закрытой беты на 12 недель (`docs/plan.md`).

## Неизменные правила

1. **Local-first.** Повторения и FSRS считаются на устройстве; сервер только синхронизирует. Приложение полностью работает без сети.
2. **Уровень CEFR — у значения (sense), а не у слова.** Карточка ссылается на значение или выражение, а не на лемму.
3. **Все пользовательские данные привязаны к `user_id`.** Идентификаторы создаёт клиент (UUID v7).
4. **Контент словаря общий и неизменяемый пользователями.** Личные правки — отдельная надстройка над карточкой.
5. **Цвета, отступы, радиусы, шрифты — только из `@cards/tokens`.** Никаких hex-значений в компонентах.
6. **Типы, общие для нескольких приложений, живут в `@cards/contracts`.** Не дублировать их в приложениях.
7. **Никаких секретов в коде и в коммитах.** Ключи — только в `.env` (есть `.env.example`).
8. **Тексты интерфейса — через i18n с первого дня**, даже если язык пока один.
9. **Каждый комментарий агента в GitHub начинается со служебной метки** `<!-- роль -->` (`triage`, `design`, `plan`, `implement`, `review`, `pm`). По ней воркфлоу отличают комментарии агентов от ответов владельца и не запускаются по кругу.

## Как работать над задачей

1. Прочитай задачу в `docs/backlog/` и связанные разделы документов.
2. Сначала предложи план: какие файлы изменишь, как проверить. Жди подтверждения, если задача затрагивает модель данных, протокол синхронизации или контракты.
3. Делай небольшими шагами, каждый шаг — рабочее состояние.
4. Пиши тесты для логики: планировщик повторений, очередь новых карточек, синхронизация, нормализация слов.
5. Перед завершением: `npm run typecheck --workspaces`, тесты, краткое описание изменений и как проверить их на телефоне.
6. Если меняешь решение из `docs/decisions.md` — добавь новую запись, не переписывай старую.

## Определение «готово»

- Выполнены критерии приёмки задачи.
- Нет ошибок типов, тесты проходят.
- Работает в светлой и тёмной теме и без сети (для мобильного приложения).
- Тексты вынесены в i18n, цвета — из токенов.
- Документы обновлены, если поменялось поведение или модель данных.

## Чего не делать

- Не менять стек и крупные библиотеки без записи в `docs/decisions.md`.
- Не добавлять функции вне объёма беты (`docs/product.md`, раздел «Не входит в бету»).
- Не удалять данные пользователя физически, кроме удаления аккаунта (FR-27).
