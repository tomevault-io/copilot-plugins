# AGENTS.md — 跨宿主规则

## 目录职责（不可混淆）

| 目录 | 职责 | 谁可以写 |
|------|------|---------|
| `01-原始素材区/完整副本/` | 原文只读副本 | 仅初始化时写入，之后只读 |
| `02-内容单元库/` | 从原文抽取的最小语义对象 | Agent 写入，人工可修正 |
| `03-处理状态/` | 来源注册、待处理、已处理、去重、矛盾 | 脚本生成 + Agent 更新 |
| `05-主题地图/` | 跨单元聚合 | Agent 写入，人工可调整 |
| `06-选题装配/` | 重组单元生成的内容草稿 | Agent 写入，人工可编辑 |
| `07-脚本与工具/` | 自动化脚本 | 初始化时写入，后续按需 |

## 处理纪律

1. **先分类，再抽取。** 每份原始素材必须先判定：跳过 / 归一化 / 抽取。不允许不经判断全部送入抽取。
2. **不跳过来源注册。** 每一个被纳入的源文件必须在来源注册表中有记录。
3. **不伪造关系。** 关系只能从内容单元的实际语义中建立，不允许为了密度强行连。
4. **去重先于抽取。** 新抽取前先检查是否与已有单元重复（完全重复/同义重复 → 合并，近似重复 → 标记）。
5. **原文永不改。** 原始副本不可修改。发现原文有误，在内容单元中标注，不回写原文。

## 内容单元 ID 规范

- 格式：`{TYPE}-{NNN}`
- TYPE：`QST`（问题）、`CON`（概念）、`OPI`（观点）、`CAS`（案例）、`SOL`（方案）
- NNN：三位数字，按类型独立编号（如 QST-001、CON-001 互不冲突）
- ID 一旦分配不可更改，内容迭代通过 `version` 字段管理

## Obsidian 兼容

- 正文引用统一用 `[[文件名]]` 格式
- frontmatter 中的 `id`、`relationships.target` 保留结构化 ID（如 `QST-001`）
- 文件名：`{ID}_{标题}.md`
