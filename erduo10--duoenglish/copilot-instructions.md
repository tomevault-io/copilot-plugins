# 代码分析严格规则

1. **基于事实原则**
   - 只描述确实存在于代码中的功能和结构
   - 明确引用代码行号或代码片段作为证据
   - 如需推测，必须明确标记为"推测"并说明理由

2. **验证流程**
   - 每个功能描述必须通过对源码的直接引用来支持
   - 对组件功能的描述必须基于其实际实现的方法和属性
   - 在结论段落前增加验证步骤，确认所有描述都有代码支持

3. **分析结构化**
   - 先列出文件结构和基本组件关系
   - 逐个分析组件的确切实现，包括WXML结构和JS逻辑
   - 使用代码块直接引用关键部分，如：
     ```
     文件：/path/to/file.js:12-15
     实际代码片段
     ```

4. **明确不确定性**
   - 当代码功能不明确时，使用"代码暂未明确实现X功能"
   - 可能的意图应使用"代码可能是为了实现X，但需要更多上下文确认"
   - 避免使用确定性语言描述不确定功能

5. **迭代验证**
   - 分析完成后，回顾每个功能描述并检查源码支持
   - 当分析多个相关组件时，交叉验证它们之间的交互是否与代码一致
   - 在提供完整分析前进行自检，确保没有无根据的假设
