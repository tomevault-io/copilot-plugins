# FAOUZI-47 — Agent Architecture Guide

> Read this file first when working in this repository. It describes the
> project layout, conventions, and non-obvious design decisions.

## 1. What this project is

FAOUZI-47 is a **single-page, fully static** dashboard that simulates an
Autonomous AI SOC (Security Operations Center) &amp; Threat Intelligence
console. There is **no backend, no database, no build step, and no
dependencies**. Everything ships from a single `index.html`.

All "data" (attack arcs, telemetry lines, incidents, key-pool state) is
generated by a client-side simulation loop in vanilla JavaScript. Nothing
is persisted; refreshing the page resets all state.

## 2. Key files

| Path | Purpose |
|---|---|
| `index.html` | The entire application — HTML + inline `<style>` + inline `<script>`. |
| `netlify.toml` | Netlify deploy config: publish dir, redirects, security headers, caching. |
| `README.md` | Human-facing project page with badges & architecture diagram. |
| `docs/BOOK.md` | Bilingual (EN/AR) long-form documentation. |
| `AGENTS.md` | This file. |

There is intentionally **no `package.json`**, no bundler, no framework. This
keeps the deploy trivially simple and the surface area for security review
tiny.

## 3. Architecture

```
Browser
  └─ index.html
       ├─ <style>      → cyberpunk dark theme (CSS variables in :root)
       ├─ <body>       → semantic panels: header, stats, map, log, AI, keys
       └─ <script>    → IIFE "FAOUZI-47 simulation engine"
            ├─ Clock + toasts
            ├─ Canvas attack-map renderer (requestAnimationFrame loop)
            ├─ Telemetry log generator (setInterval)
            ├─ AI incident summarizer (DOM-driven, 1-click)
            ├─ API key pool state + toggle/rotate handlers
            └─ Stat drift updater
```

### Modules inside the IIFE

- **Clock / Toasts** — minimal UI helpers (`toast()`, `tickClock`).
- **Map renderer** — `NODES` (honeypots) and `THREATS_POOL` (origins) are
  normalized 0..1 coordinate arrays. `spawnArc()` queues an animated
  quadratic-bezier arc every ~900ms. `drawMap()` is the rAF render loop.
  Continents are stylized as density dot clusters (not geographically exact).
- **Telemetry log** — `pushLog(sev, msg)` appends a line with a severity
  tag and random IP. `autoLog()` runs every 700ms; log caps at 80 lines.
- **AI Incident Summarizer** — `newIncident()` injects a "loading" card,
  then after 1.3s replaces it with a synthesized summary + 3 random
  mitigation recommendations. `btn-scan` triggers a fake deep-correlation
  step then spawns two incidents.
- **API Key Rotation** — `KEYS` is an in-memory array of 4 key entries.
  `renderKeys()` re-renders the pool. Toggles flip `state`; the Rotate
  button walks each key through `rotating` → `active` with quota refresh.
- **Stat drift** — `driftStats()` jitters the four KPI numbers every 2.5s.

## 4. Conventions

- **No external dependencies.** Do not add npm packages, CDN scripts, or
  web fonts that require network fetches. The CSP in `netlify.toml`
  forbids external script/style origins.
- **No comments in production JS** unless requested. (The IIFE header
  block is the only comment — kept for orientation.)
- **Single file.** Keep all CSS and JS inline in `index.html`. Do not
  split into separate files; the simplicity is intentional.
- **Color tokens** live in `:root` CSS variables — reuse them; avoid
  hardcoding hex values in component CSS.
- **Naming** — IDs are `kebab-case`, JS helpers are `camelCase`,
  CSS classes are `kebab-case`.
- **Accessibility-lite** — keep semantic landmarks (`header`, `main`,
  `footer`), and ensure interactive controls are real `<button>` /
  `<input>` elements.

## 5. Non-obvious decisions

- **Equirectangular stylized map, not a real geo projection.** The map
  uses dot-density pseudo-continents because (a) we ship zero assets and
  (b) a real projection library would violate the "no dependencies" rule.
  Nodes are placed by eye on normalized coords.
- **Simulated, not persisted.** The task is a UI/UX demonstration; real
  persistence would require a Netlify Function + Database. The current
  architecture deliberately avoids that to keep the deploy instant and
  the security surface minimal. If persistence is ever needed, use the
  `netlify-database` skill (Drizzle + `@netlify/database`) and a
  `netlify/functions/` endpoint — do not use localStorage for shared
  state.
- **CSP allows `'unsafe-inline'`** for script & style because the app
  is a single self-contained HTML file. If the app ever moves to
  external JS/CSS, tighten the CSP to use nonces or hashes.
- **`force = false` on the SPA redirect** so `index.html` itself is
  served directly at `/` (the explicit `/` → `/index.html` rule handles
  the canonical path).

## 6. Local dev

```bash
netlify dev --port 8889   # Netlify CLI emulation on port 8889
# or just open index.html in a browser
```

Do **not** run `npm run build`, `vite build`, `tsc`, etc. — there is no
build pipeline and these commands will fail. The Netlify platform
validates the static deploy automatically.

## 7. Where to extend

- **Add a backend** → `netlify/functions/` + the `netlify-functions` skill.
- **Add persistence** → `db/schema.ts` + the `netlify-database` skill.
- **Add real AI summarization** → `netlify-ai-gateway` skill (server-side).
- **Add auth** → `netlify-identity` skill (run `scripts/enable.cjs`).
