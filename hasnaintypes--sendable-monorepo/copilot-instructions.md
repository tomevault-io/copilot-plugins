## Repo Layout

```
sendable-monorepo/          ← Turborepo root (pnpm workspace)
├── apps/
│   ├── web/                ← ONLY implemented codebase (Next.js 16 + Convex)
│   └── api/                ← Planned FastAPI backend; currently empty — do not touch
├── docs/                   ← Canonical architecture/feature reference — read before significant changes
├── turbo.json              ← Turborepo task pipeline
├── pnpm-workspace.yaml      ← workspace globs (apps/*, packages/*)
└── package.json            ← root workspace scripts (delegate to turbo)
```

**Commands run from the repo root via Turborepo** (`pnpm dev`, `pnpm build`, etc. delegate to `turbo run …` which filters to the right workspace). App-specific tooling (e.g. `convex`) still runs inside `apps/web`. The web app is the `@sendable/web` workspace package; `apps/api` is not yet wired into the workspace or the Turbo graph.

## Commands

```bash
# All commands run from the repo ROOT and delegate to Turborepo.
# Primary dev command — starts 3 processes in parallel (in apps/web)
pnpm dev

# Correctness check (no tests exist — this is the substitute)
pnpm typecheck        # turbo -> apps/web: tsc --noEmit && tsc -p convex --noEmit

pnpm lint             # turbo -> eslint src convex
pnpm format           # turbo -> prettier write
pnpm format:check     # turbo -> prettier check (CI)
pnpm build            # turbo -> production Next.js build

# App-specific commands still run inside apps/web (not in the turbo graph):
#   pnpm --filter @sendable/web build:codegen   # convex codegen then next build
```

`pnpm dev` runs three parallel processes via `npm-run-all` (inside `apps/web`):
- `dev:frontend` — `next dev --webpack --experimental-https` (HTTPS on localhost:3000)
- `dev:backend` — `convex dev --typecheck-components`
- `dev:build` — chokidar watcher; on every `.ts`/`.tsx`/`tsconfig` change it runs a **full `next build`** (not a separate dist build — it produces a Next.js production build each time)

The `predev` hook runs `convex dev --skip-push` first (Convex init only, no push) and creates `dist/` if absent.

**No `pnpm test` script exists.** `pnpm typecheck` is the only automated correctness check.

The `--webpack` flag on `dev:frontend` overrides the `turbopack` block in `next.config.ts` — Turbopack is not active in dev.

## Environment Variables

Variables must be set in **two separate places** — missing either breaks things:

1. `apps/web/.env.local` (Next.js)
2. Convex dashboard → Settings → Environment Variables (for Convex actions)

**Critical — `.env.local`:**
| Variable | Notes |
|---|---|
| `CONVEX_DEPLOYMENT` | Generated by `npx convex dev` |
| `NEXT_PUBLIC_CONVEX_URL` | Convex WebSocket URL (`*.convex.cloud`) |
| `NEXT_PUBLIC_CONVEX_SITE_URL` | Convex HTTP actions URL (`*.convex.site`) |
| `SITE_URL` / `NEXT_PUBLIC_SITE_URL` | Must be `https://` in dev (server runs HTTPS); affects auth origins and email links |
| `NEXT_PUBLIC_API_URL` | `apps/api` (FastAPI) base URL (e.g. `http://localhost:8000`) |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | For Gmail OAuth inbox flow only (not sign-in OAuth — see below) |

**Critical — Convex dashboard:**
| Variable | Notes |
|---|---|
| `BETTER_AUTH_SECRET` | `openssl rand -base64 32` |
| `EMAIL_PROVIDER` | `"smtp"` for local dev with Mailpit; `"resend"` for production |
| `SITE_URL` | Same value as `.env.local` — must be set in **both** places |
| `RESEND_API_KEY` | Required when `EMAIL_PROVIDER=resend` |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | **Sign-in OAuth goes here (Convex dashboard), not `.env.local`** |
| `ENCRYPTION_KEY` | AES-256-GCM key for inbox token encryption (32 bytes, base64-encoded) — not in `.env.example` |
| `LOGTAIL_SOURCE_TOKEN` | BetterStack logging; omit to fall back to console |

If `SITE_URL` is missing from Convex env vars, auth throws `INVALID_ORIGIN` errors.

**Google OAuth distinction:** Sign-in OAuth credentials live only in the Convex dashboard (auth runs in Convex). Gmail inbox OAuth credentials go in `.env.local`. Both local dev and prod redirect URIs must be registered in Google Cloud Console as `https://<deployment>.convex.site/api/auth/callback/google`.

For local email: run Mailpit on port 1025; set `EMAIL_PROVIDER=smtp`, `SMTP_HOST=localhost`, `SMTP_PORT=1025` in Convex dashboard env vars.

## Architecture Quirks

### Auth lives entirely inside Convex
`src/app/api/auth/[...all]/route.ts` is a proxy to Convex HTTP actions — no auth logic in Next.js. Auth is configured in:
- `convex/auth/helpers.ts` — Better Auth instance, all plugins, email hooks
- `convex/betterAuth/auth.ts` — static instance for schema generation only

**Active OAuth providers:** Google sign-in is active (uncommented). GitHub and Slack are commented out — require env vars and uncommenting to enable.

### Two-layer route guarding
1. `proxy.ts` (project root) — Next.js middleware file; optimistic cookie check only; **not the security gate**
2. `src/app/(auth)/layout.tsx` and `src/app/(unauth)/layout.tsx` — real server-side `isAuthenticated()` checks

> **Note:** The middleware file is named `proxy.ts`, not `middleware.ts`. Next.js only auto-picks up `middleware.ts`. If middleware stops working, this is the likely cause.

### Tailwind v4 — no config file
There is no `tailwind.config.ts`. Tailwind v4 is configured entirely via CSS in `src/app/globals.css` using `@theme inline { ... }` with `oklch` color tokens. Dark mode uses class strategy via `@custom-variant dark (&:is(.dark *))`. Default theme is `"dark"`.

### `@typescript-eslint/no-explicit-any` is off
The ESLint config disables this rule project-wide — `any` is permitted.

### `reactStrictMode` is disabled
Set to `false` in `next.config.ts`. Effects do not double-invoke in dev.

### Convex schema is composed from submodules
`convex/schema.ts` only spreads table definitions from per-feature files. When adding a new table: define it in the relevant submodule (e.g. `campaigns/schema.ts`), export it, and spread it into `convex/schema.ts`.

### Generated files — never edit manually
- `convex/_generated/` — regenerated by `convex dev` / `pnpm build:codegen`
- `convex/betterAuth/_generated/` — regenerated by Better Auth

Run `pnpm build:codegen` after any schema changes.

### Node.js runtime required for some Convex files
Files that call Node APIs must start with `"use node"`. Current files requiring this:
`convex/auth/helpers.ts`, `convex/emails/email.tsx`, `convex/lib/logger.ts`, `convex/inboxes/actions.ts`

### Credentials are stripped server-side
`convex/inboxes/queries.ts` removes `encryptedAccessToken`, `encryptedRefreshToken`, `accessTokenExpiresAt`, and `scopes` before returning data to the client. Only `internalGetInbox` (server-only) returns the full record.

### Next.js runs with `--experimental-https`
Dev server is HTTPS on localhost:3000. Certificates are in `apps/web/certificates/`. Browser will show a self-signed cert warning — expected.

### `dev:build` triggers a full `next build` on every source change
The chokidar watcher runs `pnpm build` (full production Next.js build) on every `.ts`/`.tsx`/`tsconfig` change. This is slow by design — it runs separately from `dev:frontend`.

## Convex Function Patterns

All Convex queries/mutations use `authComponent.safeGetAuthUser(ctx)` from `convex/auth/helpers.ts`. Always check for `null` before proceeding.

Email sending goes through `convex/emails/email.tsx` — never call Resend or Nodemailer directly from other files.

Role checking: use `requireRole(ctx, "admin")` or `getUserRole(ctx)` from `convex/lib/requireRole.ts`. Built-in roles: `"admin"` and `"member"` (default).

`convex/http.ts` currently only registers Better Auth routes. The FastAPI write-back HTTP endpoints documented in README do not yet exist in this file.

## What Is and Is Not Implemented

**Implemented (code exists):**
- Full auth flow (email/pass, email verification, password reset, 2FA TOTP, magic link, OTP, Google OAuth)
- Dashboard, campaigns/new, settings page
- Marketing landing page + in-app docs (Nextra at `/docs`)
- Gmail OAuth inbox connection (initiation + callback routes; `testConnection` + `revokeGmailToken` actions)
- Convex schemas for all planned tables (campaigns, prospects, drafts, jobs, sequences, usage, notifications, inboxes, userPreferences)

**Schema-only (no queries/mutations yet):**
- `convex/jobs/`, `convex/drafts/`, `convex/sequences/`

**Not yet built:**
- Leads, analytics, inbox management pages
- `apps/api` FastAPI backend
- Convex HTTP endpoints for FastAPI write-backs
- Neon PostgreSQL / AI agent orchestration / Inngest jobs
