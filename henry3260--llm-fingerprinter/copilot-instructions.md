# AGENTS.md

## Project Overview

LLM-Fingerprinter is a Python package and CLI for black-box LLM model-family identification. It fingerprints a target model by sending a fixed prompt suite, extracting semantic/linguistic/behavioral features from responses, and classifying the resulting vector.

Core runtime flow:

- `simulate` collects labeled fingerprints for known models into `fingerprints/training/`.
- `train` trains the ensemble classifier and writes `model/classifier_model.joblib`.
- `build-templates` builds family-level nearest-template detection and writes `model/templates.joblib`.
- `build-model-templates` builds specific model-version templates and writes `model/model_templates.joblib`.
- `identify` fingerprints an unknown model and reports ensemble, family-template, and model-template results.

Key technologies:

- Python 3.9+
- Click CLI
- scikit-learn, NumPy, SciPy, joblib
- sentence-transformers and NLTK for feature extraction
- requests/httpx/OpenAI/Gemini clients for providers

## Repository Layout

- `llm_fingerprinter/cli.py`: CLI commands and user-facing workflows.
- `llm_fingerprinter/config.py`: model families, paths, dimensions, default endpoints, and env-var names.
- `llm_fingerprinter/classifier.py`: ensemble classifier, currently RandomForest + SVM + MLP.
- `llm_fingerprinter/template_classifier.py`: nearest-template classifier for open-set family/model matching.
- `llm_fingerprinter/fingerprinter.py`: prompt execution, fingerprint creation, and identify flow.
- `llm_fingerprinter/fingerprint_store.py`: fingerprint JSON persistence and export helpers.
- `llm_fingerprinter/providers/`: provider-native backend implementations.
- `tests/`: pytest suite, mostly provider and prompt-generation tests.
- `model/`: binary `.joblib` model artifacts shipped or generated by training.
- `fingerprints/`: runtime fingerprint data; `fingerprints/training/` is the training source.
- `plots/`: generated visualizations; outputs are ignored except `.gitkeep`.

## Setup Commands

Preferred editable install:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -e ".[all,dev]"
```

Alternative install from requirements:

```bash
pip install -r requirements.txt
pip install -e ".[dev]"
```

CLI entry point:

```bash
llm-fingerprinter --help
python -m llm_fingerprinter.cli --help
```

## Environment Variables

Use env vars rather than committing secrets:

```bash
export OPENAI_API_KEY="..."
export GROK_API_KEY="..."
export GEMINI_API_KEY="..."
export DEEPSEEK_API_KEY="..."
export OLLAMA_CLOUD_API_KEY="..."
export LOG_LEVEL="INFO"
```

Use `LLM_FINGERPRINTER_DATA` to redirect runtime data away from the repo root:

```bash
export LLM_FINGERPRINTER_DATA=/path/to/data
```

## Development Workflow

Inspect current state before editing:

```bash
git status --short
```

Common CLI checks:

```bash
llm-fingerprinter info
llm-fingerprinter list-fingerprints
llm-fingerprinter list-models -b ollama
llm-fingerprinter test -b openai --model gpt-4o-mini
llm-fingerprinter test -b grok --model grok-4.3
```

Collect training fingerprints:

```bash
llm-fingerprinter simulate -b openai --model gpt-4o-mini --family gpt --num-sims 10
llm-fingerprinter simulate -b grok --model grok-4.3 --family grok --num-sims 10
```

Train and rebuild derived artifacts:

```bash
llm-fingerprinter train
llm-fingerprinter build-templates
llm-fingerprinter build-model-templates
```

Identify a model:

```bash
llm-fingerprinter identify -b openai --model gpt-4o-mini
llm-fingerprinter identify -b grok --model grok-4.3
llm-fingerprinter identify -b custom -r example/grok_request.txt
```

Create plots:

```bash
llm-fingerprinter plot --input fingerprints/training --output plots/fingerprint_projection.png
```

## Testing Instructions

Run all tests:

```bash
pytest
```

Run a focused subset:

```bash
pytest tests/providers/test_grok_provider.py
pytest tests/providers
pytest tests/promptgen
pytest -k openai
```

CI is defined in `.github/workflows/ci.yml` and runs on push and pull request:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install -e ".[dev]"
pytest
```

Add or update tests for provider behavior, CLI contracts, model-family support, or serialization changes. Avoid tests that require real API keys unless they are explicitly gated or mocked.

## Code Style

- Follow the existing Python style in nearby files.
- Prefer provider-native implementations under `llm_fingerprinter/providers/`.
- Keep CLI behavior in `llm_fingerprinter/cli.py` and reusable logic in package modules.
- Use structured JSON/path handling instead of ad hoc string parsing when reading fingerprints or request templates.
- Keep comments concise and only add them where they explain non-obvious behavior.
- Do not introduce unrelated refactors in feature patches.

## Provider Guidelines

Supported backend names are configured through CLI/backend specs and providers:

- `ollama`
- `ollama-cloud`
- `openai`
- `deepseek`
- `gemini`
- `grok`
- `custom`

When adding or changing a provider:

- Update `llm_fingerprinter/providers/registry.py` and provider exports if needed.
- Update `llm_fingerprinter/cli.py` backend handling only when the CLI surface changes.
- Add tests under `tests/providers/`.
- Avoid depending on legacy client classes outside `providers/`.

For xAI/Grok, use backend `grok` and `GROK_API_KEY`:

```bash
llm-fingerprinter simulate -b grok --model grok-4.3 --family grok --num-sims 10
```

## Model and Training Caveats

Treat `model/*.joblib` as binary model artifacts. Do not modify or commit them casually.

Important behavior:

- `train` performs a full retrain from the currently available fingerprints and overwrites `model/classifier_model.joblib`.
- `build-templates` rebuilds `model/templates.joblib` from current fingerprints.
- `build-model-templates` rebuilds `model/model_templates.joblib` from current fingerprints.
- `add-family` updates template classification only; it does not add a class to the ensemble classifier.

Do not assume old families are preserved if their training fingerprints are missing. If `fingerprints/training/` only contains `gpt` and `grok`, then a new `train` run only has effective training signal for `gpt` and `grok`.

Before experiments that overwrite model artifacts, back up current files:

```bash
mkdir -p model/backup_$(date +%Y%m%d_%H%M%S)
cp model/*.joblib model/backup_$(date +%Y%m%d_%H%M%S)/
```

For a reliable new classifier, keep or regenerate fingerprints for every family that should remain identifiable, then retrain with all families present.

## Adding a New Family

Checklist:

- Add the family to `MODEL_FAMILIES` in `llm_fingerprinter/config.py`.
- Ensure `simulate --family` accepts the new family.
- Ensure the backend/provider supports the target model.
- Collect enough fingerprints, preferably at least 10 samples per model/family.
- Run `train`, `build-templates`, and `build-model-templates`.
- Add or update tests and documentation.

Recommended validation:

- Hold out at least one model per family from training when possible.
- Compare old classifier, new classifier, and template-only results.
- Track family accuracy, OOD rate, and confusion pairs such as `gpt` vs `grok` or `gemini` vs `gemma`.

## Security and Data Hygiene

- Never commit API keys, `.env` files, token files, request logs containing secrets, or `.venv/`.
- `fingerprints/` can contain generated model outputs. Confirm whether data is safe to commit before adding it.
- `logs/`, generated plots, caches, build outputs, and virtualenvs should stay untracked.
- Custom request templates may contain auth headers; scrub them before committing examples.

## Build and Packaging

Build package artifacts:

```bash
python -m build
```

Package metadata lives in `pyproject.toml`; `setup.py` delegates to setuptools. `MANIFEST.in` includes model artifacts and example request templates in source distributions.

## Pull Request Guidelines

Before opening a PR:

```bash
git status --short
pytest
```

PR descriptions should include:

- What changed.
- Why it changed.
- Tests run.
- Whether `model/*.joblib` or training fingerprints were updated.

Avoid mixing unrelated code refactors, generated model artifacts, and documentation-only edits in one PR unless the change explicitly requires them together.

## Troubleshooting

- If CLI output cannot find data where expected, check `LLM_FINGERPRINTER_DATA` and the current working directory. `config.py` resolves runtime paths from that env var or the project root.
- If `simulate --family <name>` rejects a family, update `MODEL_FAMILIES`.
- If CI does not run, verify the branch was pushed, the PR exists, and `.github/workflows/ci.yml` is present on that branch.
- If Windows PowerShell shows mojibake for UTF-8 text, verify file content with Python using `encoding="utf-8"`.
