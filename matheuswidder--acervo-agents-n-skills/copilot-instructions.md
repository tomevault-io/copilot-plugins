## Frontmatter Format

All agent/skill/workflow files include YAML frontmatter:

```yaml
---
name: agent-name
description: |
  Use this when...
  
  <example>
  Context: [Situation]
  user: "[Request]"
  assistant: "[Response]"
  <commentary>[Why trigger]</commentary>
  </example>

mode: subagent                    # primary or subagent
tools:                            # Allowed tools
  read: true
  write: true
  bash: true
allowed-tools: Read, Write, Grep  # Alternative format
---
```

## Code Style Guidelines

### YAML Frontmatter
- 2-space indentation
- Use `|` for multi-line descriptions
- Quote strings with special characters
- Lowercase booleans (`true`/`false`)

### Markdown Content
- Maximum line length: 100 characters
- Use semantic line breaks
- Code blocks specify language
- Tables for structured data

### Naming
- **Directories/Files**: kebab-case
- **Variables**: camelCase (content), UPPER_SNAKE_CASE (templates)

---

## Best Practices

1. **Be Concise**: Keep under 150 lines
2. **Use Examples**: 2-4 `<example>` blocks in descriptions
3. **Clear Triggers**: Explicit when-to-use guidance
4. **Tool Limits**: Only specify needed tools
5. **Versioning**: Semantic versioning for skills
