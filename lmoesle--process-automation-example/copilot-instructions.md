# AGENTS.md

## Repo Shape
- The root `pom.xml` is only a Maven aggregator for `apps/backend`; the Vite frontend in `apps/frontend` is a separate npm package and is not built by Maven.
- Backend entrypoint: `apps/backend/src/main/java/de/lmoesle/miravelo/processautomationexample/ProcessAutomationExampleApplication.java`.
- Frontend entrypoint: `apps/frontend/src/main.tsx`; routing uses `HashRouter` in `AppRoutes`.
- Domain and API vocabulary is German (`Urlaubsantrag`, `Benutzer`, `Vorgesetztenentscheidung`); keep new backend names and UI labels consistent with that.

## Commands
- Backend full verify from repo root: `./mvnw clean verify`.
- Backend focused test: `./mvnw -pl apps/backend -Dtest=ClassName test`; method filter: `-Dtest=ClassName#methodName`.
- Run local infrastructure: `docker compose -f stack/docker-compose.yml up -d`; it starts PostgreSQL 18 on `localhost:5432` and MailHog on `localhost:8025`.
- Run backend app after infrastructure is up: `./mvnw -pl apps/backend spring-boot:run`.
- Frontend commands run from `apps/frontend`: `npm ci`, `npm run lint`, `npm run test:coverage`, `npm run build`. CI runs them in that order.
- Frontend focused test: `npm test -- --run src/components/tasks/TaskList.test.tsx`.

## Tooling Gotchas
- Use JDK 25 for backend compile/verify. `apps/backend/pom.xml` sets `maven.compiler.source` and `target` to `25`; README and `.github/workflows/build.yml` still say Java 21, and Java 21 fails at compile with `Ungültiges Zielrelease: 25`.
- Maven wrapper downloads Maven 3.9.12; the backend POM has an enforcer config under `pluginManagement`, so `validate` alone does not catch the Java-level mismatch.
- Surefire uses random test order. Do not add order-dependent backend tests.
- Backend tests use `apps/backend/src/test/resources/application.yml`, which disables datasource, Flyway, Camunda REST, and Camunda webapp autoconfiguration. Current tests do not need Docker unless you add real DB/process integration tests.

## Generated Files
- `apps/backend/src/main/java/de/lmoesle/miravelo/processautomationexample/bpmn/VacationApprovalProcessApi.java` is generated from `apps/backend/src/main/resources/bpmn/*.bpmn`; do not edit it by hand.
- Regenerate BPMN constants explicitly with `./mvnw -pl apps/backend io.github.emaarco:bpmn-to-code-maven:generate-bpmn-api`; `generate-sources` does not run that goal in this checkout.
- `apps/frontend/src/api/api-generated.ts` is generated by `openapi-typescript`; do not edit it by hand.
- Regenerate frontend API types only while the backend is serving `/v3/api-docs`: from `apps/frontend`, run `npm run generate:api`.

## Backend Architecture
- ArchUnit enforces package boundaries: `domain` must not depend on `application` or `adapter`; use cases live in `application/usecases`; ports live in `application/ports/in` and `application/ports/out`; adapters live in `adapter/in` and `adapter/out`.
- `ProcessAutomationExampleApplication`, `shared/tasklist/*`, and generated `bpmn/*` are excluded from the hexagonal ArchUnit rule.
- REST DTOs under `adapter/in/rest/dto` and adapter models must be records or interfaces; JPA entities under `adapter/out/persistence/entities` must be classes.
- Do not introduce MapStruct; `MapstructArchitectureTest` forbids it. Lombok is configured and currently used despite the placeholder `LombokArchitectureTest`.

## Frontend Notes
- Vite dev server is strict on port `3000` and proxies `/api` and `/v3/api-docs` to `http://localhost:8080`.
- Runtime API base defaults to `/`; override with `VITE_API_BASE_URL` only when the proxy is not appropriate.
- Components should consume normalized app types from `src/api/client.ts`, not generated OpenAPI types directly.
