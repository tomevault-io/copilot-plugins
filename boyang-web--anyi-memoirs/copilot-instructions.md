# 支教队总结网页：项目级约束

## 项目目标

- 制作一个适合 GitHub Pages 托管的支教队总结网页。
- 核心内容包括支教地地图、照片、Bilibili 视频、团队经历与支教故事。
- 整体主题围绕支教、成长、远方、记忆与星光。

## 必须实现的体验

- 使用合适且易理解的方式呈现支教地点；地图不可用时必须提供文字地址或外部地图链接。
- 支持普通图片和 Bilibili 视频嵌入；视频加载失败时提供前往 Bilibili 的备用链接。
- 提供“星星点点”交互场景：每颗可交互星星对应一张照片和一段描述，点击或键盘操作后打开详情。
- 页面必须兼容 GitHub Pages 的静态托管和仓库子路径。
- 手机、平板和桌面端均可正常浏览。

## 内容维护

- 照片、视频、地图点位和文案使用清晰的数据文件统一管理。
- 媒体资源按用途放入明确目录；增删内容不应要求修改复杂组件逻辑。
- 示例内容必须明确标记，避免被误认为真实支教信息。
- 公开部署前检查学生肖像、姓名、学校位置等隐私信息是否获得授权。

## 技术与质量

- 仅采用兼容静态托管的前端技术，不依赖常驻后端。
- 优先使用许可证清晰、体积适当、维护状态良好的社区方案，避免重复实现地图、灯箱、轮播等通用能力。
- 图片应压缩、懒加载并提供替代文本；动画应尊重 `prefers-reduced-motion`。
- 动效应高级但克制，不牺牲可读性、可访问性或低性能设备体验。
- 所有交互均应支持键盘操作，并保持清晰的焦点样式。

## 用户审核机制

- 不得一次性自主锁死全部视觉决策。
- 每个重要阶段先交付可运行、可点击的 Demo，再由用户基于实际效果审核。
- 评审应优先展示页面、交互和不同屏幕效果，不用长篇技术文字代替视觉 Demo。
- 地图方案、整体视觉方向、星空交互和真实素材接入均需作为独立审核点。

## 默认工作流程

1. 创建最小可运行页面和内容目录。
2. 交付视觉方向 Demo，等待用户选择或提出调整。
3. 交付地图与星空相册交互 Demo。
4. 接入经授权的真实照片、文案与视频。
5. 完成响应式、性能、无障碍和隐私检查。
6. 配置并验证 GitHub Pages 线上访问。
