# Dev-Cut Kit — คู่มือสำหรับ AI Agent

ชุด skills ตัดต่อวิดีโอกึ่งอัตโนมัติสำหรับ CapCut Desktop อ่านไฟล์นี้ก่อนเริ่มงานทุกครั้ง

## เมนูฟีเจอร์ — ใช้ตอนผู้ใช้ทักมาแบบกว้าง ๆ

เมื่อผู้ใช้ยังไม่ระบุชัดว่าจะทำอะไร (เช่น "ช่วยตัดคลิปหน่อย", "เริ่มยังไง") ให้แสดงเมนูนี้แล้วให้เลือก**เป็นตัวเลข** อย่าอธิบายยาว:

```
Dev-Cut พร้อมทำงาน — เลือกได้เลย:
1. ตัดช่วงเงียบ + ใส่ซับ → ส่งเข้า CapCut   (ยอดนิยม)
2. ใส่ซับอย่างเดียว (ไม่ตัด)
3. ทำกราฟิก: title / แถบชื่อ / ไอคอน / end card
4. หา b-roll รูป หรือเสียงประกอบ
5. ไดคัท (ลบพื้นหลัง)
6. สรุปงานส่งต่อ editor (handoff)
```

**กติกาการถาม: ถามให้น้อยที่สุด** — สูงสุด 1 คำถามต่อครั้ง และถามเฉพาะที่จำเป็นจริง:
- ข้อ 1-2: ถามแค่ "คลิปไฟล์ไหน + ลงแพลตฟอร์มไหน (TikTok แนวตั้ง / YouTube แนวนอน)" จบ — สไตล์ตัดให้เดาจากแพลตฟอร์ม (TikTok = กระชับ jump cut, YouTube = ธรรมชาติ) แล้วบอกผู้ใช้ว่าเลือกให้แบบไหน ปรับได้ทีหลัง
- อย่าถามเรื่องที่มีค่า default ดีอยู่แล้ว (ฟอนต์, สี, พารามิเตอร์ตัด) — ทำไปเลยแล้วบอกว่าใช้อะไร

## Pipeline หลัก

```
ไฟล์ดิบ → analyze → transcribe → clean-cut → capcut → (ผู้ใช้รีวิวใน CapCut) → export
                                     ↑
        cutout / gen-assets / find-assets / sfx-pack เสริมตามงาน
                                     ↓
                                  handoff (optional)
```

ทุก skill เขียนผลลัพธ์ลง **work dir** เดียวกัน (แนะนำ `work/<ชื่อโปรเจกต์>/`) เพื่อให้ skill ถัดไปอ่านต่อได้:
`analysis.json`, `transcript.json`, `captions.srt`, `cutplan.json`, `assets/`

## กติกาการทำงาน (สำคัญมาก)

1. **ไม่แตะไฟล์ต้นฉบับเด็ดขาด** — ทุกอย่างเป็น non-destructive ผ่าน cutplan และ CapCut draft
2. **รายงานก่อนทำ ยืนยันก่อนเสียเงิน** — ขั้นตอนใดที่ใช้ API เสียเงิน/เครดิตภายนอก ให้บอกผู้ใช้ก่อนรันเสมอ (มาตรฐานของ kit คือทุกอย่างฟรีในเครื่อง)
3. **นี่คือ workflow kit ไม่ใช่ปุ่มวิเศษ** — ผลลัพธ์คือ rough cut ที่ผู้ใช้ต้องรีวิวใน CapCut เสมอ บอกผู้ใช้แบบนี้ตรง ๆ
4. ตอบภาษาเดียวกับผู้ใช้ สรุปตัวเลขให้เห็นภาพเสมอ (ตัดออกกี่วินาที เหลือกี่นาที)
5. ถ้า dependency ไหนยังไม่ติดตั้ง ช่วยติดตั้งให้เลย (ดู requirements.txt / INSTALL/)
6. **ซับต้องตรงเวลาเสมอ**: โปรเจกต์ที่ตัดด้วย cutplan ให้ capcut_build จัดการ srt (มัน remap ให้) — ห้ามเอา captions.srt ต้นฉบับไปใส่เอง
7. **ฟอนต์มาตรฐานของ kit คือ LINE Seed Sans TH** (ซับ + กราฟิก) — ตัวติดตั้งลงให้อัตโนมัติ ถ้าไม่พบให้รัน `INSTALL/fonts/install_lineseed.ps1` (Windows) / `.sh` (mac) ให้ผู้ใช้เลย
8. **ความสวยเป็น default**: capcut_build เลือก style ให้อัตโนมัติ (แนวตั้ง=bold, แนวนอน=clean) — คลิปพูดคนเดียวแนะนำ `--style vlog` (ซูมสลับท่อน) รายละเอียดใน skill `style`
9. **คลิปแนวนอน → โปรเจกต์แนวตั้ง**: ระบบจัดการเองอัตโนมัติ (ซูมเบา ๆ ถ้าพอไหว / เกิน 1.6x จะใช้ฉากหลังเบลอแทน — ห้ามซูมแรงจนภาพแตก) ผู้ใช้อยากได้แบบเจาะจงใช้ `--fit-mode zoom|blur|fit`
10. **ตรวจซับก่อนสร้างโปรเจกต์เสมอ**: แก้คำ ASR ผิด + บรรทัดตัดกลางคำใน captions.srt ก่อนรัน capcut_build (ดู skill transcribe)
11. **ห้ามรันงานเบื้องหลัง (background) แล้วสัญญาว่าจะแจ้งผลทีหลัง — เด็ดขาด**: session จบเมื่อไหร่ process เบื้องหลังถูกฆ่าทันที ทุกงานต้องรันตรง ๆ (foreground) จนจบภายในคำตอบเดียว งานที่นาน (ถอดเสียง/ไดคัท) ให้บอกเวลาประมาณการก่อนเริ่ม แล้วรันรอจนจบ
12. งานยาวให้ประเมินเวลาบอกผู้ใช้ก่อนเริ่มเสมอ เช่น "ถอดเสียงคลิป 5 นาทีบนเครื่องนี้ ~7-10 นาที"
13. **เมื่อต้องถามผู้ใช้** ให้จบข้อความด้วยบรรทัดสุดท้ายรูปแบบ `❓ <คำถามสั้น กระชับ คำถามเดียว>` — โปรแกรม Dev-Cut จะแสดงเป็นแถบแดงเด่น (ถามทีละคำถาม อย่ายิงหลายคำถามพร้อมกัน)

## ข้อควรระวังบน Windows

- รัน Python ทุกครั้งให้ set `PYTHONIOENCODING=utf-8` หรือใช้สคริปต์ของ kit (มี fix ในตัวแล้ว) กัน error ภาษาไทยจาก codepage
- ดิสก์ C: ใกล้เต็ม: โมเดล Whisper ลง cache ที่ C: — ย้ายได้ด้วย env `HF_HOME` ไปไดรฟ์ที่ว่าง ก่อนรัน transcribe เช็คพื้นที่ว่างถ้าจะโหลดโมเดลครั้งแรก (~1.5GB)

## เริ่มงานทั่วไป (ตัวอย่าง)

ผู้ใช้: "ตัดคลิปนี้ให้หน่อย ใส่ซับด้วย ลง TikTok"

1. `analyze` → รายงานความยาว ช่วงเงียบ
2. `transcribe` (elevenlabs ถ้ามี key, ไม่มีใช้ whisper ไทย)
3. `clean-cut` → รายงานผล ปรับพารามิเตอร์ถ้าจำเป็น
4. `capcut` ด้วย `--width 1080 --height 1920` → ซับถูก remap + ใช้ฟอนต์ LINE Seed อัตโนมัติ → บอกผู้ใช้เปิด CapCut รีวิว
