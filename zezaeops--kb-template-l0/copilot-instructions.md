# AGENTS.md — 이 지식베이스의 운영 규칙

> 이 저장소는 주인(사람)의 **개인 지식베이스**다. 회사 org 의 업무 지식베이스와 별개로, 주인 개인 계정이 소유한다 — 회사를 옮겨도 같이 간다.
> 주인은 말로 다스리고, Claude 가 문서를 쓰고 구조를 관리하고 저장(commit·push)까지 스스로 한다.
> 이 규칙은 이 저장소를 만지는 **모든 AI 세션·에이전트에 공통 적용된다** — 노트북의 Claude Code 세션, 상주 에이전트, 그 외 어떤 런타임이든.

## 1. 역할 분담

- **주인은 살면서 말한다.** 문서를 직접 쓰거나 git 을 다룰 필요가 없다.
- **Claude 는 대화에서 알게 된 것을 문서로 이식한다.** 절차·결정·맥락 중 다음에 또 쓸 것을 골라 남긴다.
- **확인은 diff 가 아니라 대화로.** 무엇을 바꿨는지 한두 문장으로 말해준다. 주인이 "그거 아니야, 이렇게 해" 라고 하면 즉시 고친다. 저장 전에 허락을 구하지 않는다 — 대신 바꾼 사실을 숨기지 않는다.
- **찾는 것도 Claude 의 일이다.** 주인이 파일이나 노트를 지칭해 주기를 기대하지 않는다. 얘기를 받으면 먼저 README 지도와 `areas/`·`context/` 를 훑어 관련 노트를 찾아 읽고 시작하며, 무엇을 참고했는지 한 줄로 밝힌다.
- **KB 가 아직 비어 있으면 인터뷰로 삶 지도부터 그린다.** README 지도가 "아직 없음"인 첫 세션에서는 일을 시키기를 기다리지 말고 10분쯤 인터뷰한다 — ① 삶에서 챙기는 영역을 큰 덩어리(축)로 나누면 어떤 3–6개인가 (예: 일·커리어 / 돈 / 건강 / 배움 / 관계·가족 / 취미) ② 축마다 반복되는 일과 리듬(주간·월간·연간) ③ 자주 쓰는 도구·서비스 ④ 요즘 신경 쓰이는 것·계획 ⑤ 그중 가장 귀찮은 반복 작업 하나. 질문은 한 번에 하나씩, 대화로. 답은 [_meta/templates/life-map.md](_meta/templates/life-map.md) 형식의 `areas/삶-지도.md` 로 이식하고, ⑤는 그 자리에서 첫 절차 노트로 만든다. 이 지도가 이후 모든 노트의 분류·회수 기준이다.

## 2. 구조 — 무엇이 어디에 사나

```
CLAUDE.md   ← 세션마다 자동으로 읽히는 입구 (이 규칙 + 진행 중인 일)
AGENTS.md   ← 이 파일. 운영 규칙.
README.md   ← 사람용 입구이자 지도 — Claude 가 항상 최신으로 유지.
ACTIONS.md  ← 진행 중인 일 보드 — Claude 가 등록·체크·정리.
areas/      ← 주제별 지식 노트 (반복 절차·결정과 이유·참고 정보)
context/    ← 세션 기록 — 긴 작업을 다음에 이어가기 위한 박제
```

- **`areas/` = "다음에 또 쓸 것".** 파일명은 한국어로 알기 쉽게: `연말정산-절차.md`, `운동-루틴.md`, `이사-체크리스트.md`. **한 주제 = 한 파일.** 새 사실이 오면 옛 문장을 **치환**한다 — 이 노트들은 변경 이력이 아니라 "지금 맞는 것"을 담는다. 모든 노트의 frontmatter 첫 tag 는 `삶-지도.md` 의 축 이름 — 분류가 자동으로 선다.
- **`context/` = "하다 만 일의 상태".** 작업이 세션을 넘어가면 `YYYY-MM-DD-제목.md` 로 남긴다. 주인이 "지난번 그거 이어서" 라고 하면 여기부터 본다. 끝난 기록도 지우지 않는다 — 검색 자산이다.
- **`ACTIONS.md`** — 대화에서 할 일이 나오면 바로 등록하고, 끝나면 완료 로그로 내린다. 세션 시작 때 훑고, 밀린 일이 있으면 먼저 알려준다.
- **`README.md`** — "지금 담겨 있는 것" 목차를 노트가 생기고 지워질 때마다 갱신한다. 노트가 많아지면 목차를 삶 지도의 축별 섹션으로 묶는다.
- **절차가 익으면 skill 로.** 같은 절차 노트를 여러 번 반복 실행하게 되면, Claude 가 그 절차를 skill(한 마디로 부르는 실행 절차, `.claude/skills/`)로 만들자고 제안한다 — 문서는 설명하고, skill 은 실행한다.

## 3. 노트 형식

- **형식 규약의 SOT 는 [_meta/schema.md](_meta/schema.md).** 새 노트는 [_meta/templates/](_meta/templates/) 의 템플릿에서 시작한다 (areas 노트 = `area-note.md`, context 박제 = `context-note.md`).
- 요약: frontmatter `updated`(필수)·`tags`(선택), 표준 마크다운 링크 + 상대 경로 (wikilink `[[ ]]` 금지).
- **관련 노트는 서로 링크한다.** context 박제 ↔ 그 작업이 건드린 areas 노트, areas 노트 ↔ 관련 노트. 이 연결이 쌓여야 Obsidian 그래프도, Claude 의 회수도 산다.
- 같은 내용을 두 곳에 쓰지 않는다 — 한 곳에 쓰고 링크한다.
- 내용 없는 빈 파일을 미리 만들지 않는다. 지식이 생겼을 때 파일이 생긴다 (템플릿의 섹션도 내용 없으면 뺀다).

## 4. 무엇을 남기나

- **남긴다**: 반복되는 절차(연말정산·보험 청구·정기 점검), 내린 결정과 그 이유, 알아본 것의 결론(비교·조사), 계획과 진행 맥락, 자주 쓰는 정보.
- **남기지 않는다**: 일회성 잡담, 시점이 지나면 틀리는 숫자(꼭 필요하면 날짜와 함께 기록).
- **회사 것은 반입 금지.** 회사 업무 지식은 회사 지식베이스에 산다 — 특히 **고객 정보·미공개 지표·사내 문서는 여기에 절대 옮겨 적지 않는다** (필요하면 "어디에 있는지" 링크·포인터만). 회사 절차 메모가 섞여 들어온 걸 발견하면 회사 KB 로 옮기자고 제안한다. 다만 방향의 무게는 비대칭이다 — 개인사가 회사 저장소에 남는 쪽이 진짜 사고이므로, 어디에 둘지 애매한 개인적 내용은 여기가 기본값이다.

## 5. 저장 (git) — 여러 세션·여러 기기 전제

이 저장소는 한 사람의 것이지만 **여러 곳에서 동시에 쓰일 수 있다** — 노트북의 Claude Code 세션 여러 개, 상주 에이전트, 다른 기기. 그래서:

- **시작할 때 받는다**: 작업 시작 시 `git pull --rebase --autostash`.
- **끝나면 바로 남긴다**: 의미 있는 변경마다 commit 하고 **즉시 push 한다**. 미커밋·미푸시 변경을 남겨두면 다음 세션·다른 기기와 엉킨다.
- push 가 거절되면 `git pull --rebase` 후 다시 push 한다. 로컬이 최신이라고 가정하지 않는다.
- **충돌이 나면** 양쪽 의도를 다 보존하는 쪽으로 병합하고, 무엇을 어떻게 합쳤는지 주인에게 말해준다. 확신이 없으면 병합 결과를 먼저 보여주고 묻는다.
- 커밋 메시지는 한국어 한 줄로, 무엇이 왜 바뀌었는지.

## 6. 워크스페이스 안에서 (선택)

이 저장소는 부모 폴더 `~/KB/` 아래에 회사 지식베이스와 나란히 놓일 수 있다 (`~/KB/회사/` + `~/KB/개인/`). 그 경우:

- **가르는 것도 Claude 의 일이다.** 어느 저장소에 남길지는 부모 워크스페이스의 CLAUDE.md 라우팅 규칙이 정한다 — 주인이 외울 것은 없다.
- 이 폴더만 직접 열어도 그대로 동작한다 — 그 세션은 개인 KB 전용이 될 뿐이다.
- 저장할 때 목적지를 말해준다: "개인 KB 에 남겼어요."

## 7. 금지 (반드시)

- **비밀번호·API 키·계좌번호·주민등록번호 같은 비밀값은 절대 저장하지 않는다.** 필요하면 "어디에 있는지"(예: "1Password 의 ○○ 항목")만 적는다.
- **타인의 식별 가능한 사적 정보·민감한 의료 기록은 신중하게** — 의심스러우면 쓰기 전에 주인에게 묻는다.
- **force push 금지. 히스토리를 지우지 않는다.** 잘못 저장한 건 새 커밋으로 고친다.
