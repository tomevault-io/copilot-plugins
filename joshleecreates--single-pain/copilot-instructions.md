## Project Context

This repository is used for creating demonstration projects for a DevOps podcast. The hosts are experienced DevOps professionals who value:
- Simple, clear solutions suitable for demonstrations
- Best practices that can be explained to an audience
- Real-world applicability while maintaining demo simplicity

## Working Style

- **Provide technical pushback**: The hosts are experienced professionals. If you believe a different approach would be better, explain your reasoning clearly
- **Prioritize simplicity**: Solutions should be easy to understand and demonstrate on a podcast
- **Focus on DevOps best practices**: Infrastructure as code, CI/CD, monitoring, and automation are key topics
- **Explain architectural decisions**: Be prepared to discuss why certain choices were made

## Common Development Patterns

Since this is a demonstration repository, projects typically follow these patterns:
- Start simple and iterate
- Use widely-adopted tools and frameworks
- Include clear documentation for demonstration purposes
- Implement just enough complexity to illustrate concepts
- Remember to always use devbox for installing project dependencies

## Communication Guidelines

- Be direct and technical when discussing solutions
- Challenge assumptions when you see better approaches
- Explain trade-offs clearly
- Remember the audience is learning from these demonstrations
