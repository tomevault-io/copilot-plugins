## shreeji-mp-online-point

> This project is a real client website for:

# AGENTS.md — Shri Ji M.P. Online Point

## 1. Project Identity

This project is a real client website for:

**श्री जी M.P. ऑनलाइन पॉइंट**  
**Shri Ji M.P. Online Point**

This is a local MP Online / digital service center located in a village area of Madhya Pradesh.

The website is a digital presence for the **specific physical shop shown in the provided client photographs**.

This is NOT:
- A fictional business
- A SaaS startup
- A generic "AI business website"
- The official Government of Madhya Pradesh website
- The official MPOnline government portal

The final result must feel like a website personally designed for this particular shop.

---

# 2. Primary Objective

Build a trustworthy, simple, professional and mobile-first website that helps local customers:

- Understand what services the shop provides
- Contact the shop quickly
- WhatsApp the shop
- Call the shop
- Find the shop on Google Maps
- Understand basic service information
- Recognize the physical shop from its real photographs

The website should work equally well for:

1. Village customers who primarily read Hindi
2. Customers from nearby towns/cities
3. Students
4. Working people
5. Customers comfortable with English
6. Customers with limited technical knowledge

---

# 3. Core Design Principle

## "Make the real shop look good digitally."

Do NOT redesign the business into something it is not.

The physical shop already has an identity:
- Red and yellow service board
- Hindi-first communication
- Practical service-oriented messaging
- Local and approachable appearance
- Large list of useful services

The website should preserve this identity while making it cleaner, easier to navigate and more professional.

Do NOT create a completely unrelated premium/SaaS visual identity.

---

# 4. Client Authenticity Rules

The website must look custom-made for this client.

Use real client information wherever available:
- Actual shop name
- Actual address
- Actual village/town
- Actual phone number
- Actual WhatsApp number
- Actual opening hours
- Actual services
- Actual shop photographs
- Actual branding/signboard

Do NOT invent business information.

Never invent:
- Customer counts
- Years of experience
- Reviews

- Awards
- Certifications
- Prices
- Service availability
- Branches

If information has not been provided, leave it out or use a clearly marked placeholder during development.

Do not silently make up content to fill empty sections.

---

# 5. Target Audience

## Primary

Village and semi-rural customers in Madhya Pradesh.

Many users may:
- Use a phone rather than a laptop
- Prefer Hindi
- Have limited technical knowledge
- Want to call rather than fill a web form
- Want to send a WhatsApp message
- Need help understanding an online service

## Secondary

Customers from nearby towns/cities who expect:
- Clean design
- English terminology
- Easy service discovery
- Professional presentation
- Fast mobile experience

---

# 6. Language Strategy

Hindi is a PRIMARY language.

English is a SECONDARY/supporting language.

Do NOT build an English-only website and translate a few labels into Hindi.

Important content should naturally show both languages.

Preferred pattern:

    जाति प्रमाण पत्र
    Caste Certificate

    आय प्रमाण पत्र
    Income Certificate

    सरकारी सेवाएं
    Government Services

    हमारी सेवाएं
    Our Services

Hindi should normally appear first for customer-facing service names.

Do not make Hindi text tiny.

Use a Unicode-safe Devanagari font such as:
- Noto Sans Devanagari

For English:
- Inter or another clean sans-serif font

Do not use decorative Hindi fonts that reduce readability.

---

# 7. Tone of Voice

Use natural, straightforward Indian Hindi/Hinglish/English.

The website should sound like a genuine local business.

GOOD:

- "आपके ऑनलाइन काम, एक ही जगह।"
- "ऑनलाइन फॉर्म भरवाना है? हमसे संपर्क करें।"
- "हमारी सेवाएं"
- "WhatsApp पर पूछें"
- "रास्ता देखें"
- "कॉल करें"

AVOID:

- "Empowering your digital journey"
- "Transforming rural digital ecosystems"
- "Seamless next-generation solutions"
- "Revolutionizing citizen experiences"
- Corporate startup jargon
- AI-generated motivational marketing copy

Do not over-explain simple services.

---

# 8. Visual Identity

The client's physical signboard strongly uses:

- Red
- Yellow
- White
- Dark blue/purple accents

Use these as the visual inspiration.

IMPORTANT:
Do not blindly reproduce the physical signboard's crowded layout.

Instead:
- Use red as the primary brand accent
- Use yellow selectively
- Use neutral/white backgrounds for readability
- Use dark text
- Use strong contrast
- Keep the interface clean

The exact digital palette should be sampled/refined from the client's real signboard where practical.

Do not introduce random neon gradients.

Do not use a generic "AI purple/blue gradient" theme.

---

# 9. Anti-AI / Anti-Template Rules

This is a real client project.

The website must NOT look like a generic AI-generated template.

Avoid:
- Excessive gradients
- Glassmorphism
- Excessive blur
- Floating decorative blobs
- 3D illustrations
- Generic AI illustrations
- Excessive card grids
- Excessive pill-shaped UI
- Huge rounded corners everywhere
- Excessive shadows
- Excessive animations
- Parallax effects
- Fake dashboard elements
- Fake statistics
- Fake testimonials
- Generic stock photos
- Repetitive icon-card layouts
- "Startup landing page" patterns

Do not make every section look identical.

Use visual hierarchy and varied layouts.

Prefer:
- Real shop photography
- Real service information
- Simple typography
- Clean spacing
- Familiar buttons
- Subtle borders
- Small shadows only where useful
- Clear hierarchy
- Practical navigation

The website should look like a skilled human designer made it for a local client.

---

# 10. Real Photography Rules

The supplied client photographs are the primary visual reference.

Prefer real shop photographs over stock photography.

Use the actual:
- Shop interior
- Counter
- Computer setup
- Printer
- Signboard
- Exterior/shopfront

Do NOT replace the real shop with:
- Generic cyber cafe photos
- Generic Indian office photos
- AI-generated people
- Stock businessmen
- Fake "happy customer" photos

If an image is not needed, do not add one merely to fill space.

Optimize/crop images appropriately for mobile.

Do not distort the shop photographs.

---

# 11. Logo / Branding

The existing shop board should be treated as the source of truth for the business identity.

Primary business name:

**श्री जी M.P. ऑनलाइन पॉइंट**

English representation:

**Shri Ji M.P. Online Point**

Do not invent a completely new logo unless explicitly requested.

If a clean logo asset is not available:
- Use a clean text-based treatment
- Or carefully crop/extract the existing shop branding
- Do not fabricate an unrelated logo

The website logo should be recognizable to the shop owner.

---

# 12. Government Branding Safety

This is an independent local service center.

Do NOT make the website appear to be the official:
- Government of Madhya Pradesh website
- MPOnline government portal
- CSC government portal

Do not use government seals/emblems as the site's own branding.

Do not write misleading statements such as:
- "Official Government MPOnline Website"
- "Government of Madhya Pradesh Official Center" unless specifically verified and legally appropriate
- "Official MPOnline Portal"

The business may provide assistance with government/online services, but the website represents the local shop.

If needed, use a small clear statement such as:

"Independent local digital service center."

---

# 13. Mobile-First Requirement

Mobile is the PRIMARY platform.

Design for approximately:
- 360px
- 375px
- 390px
- 414px

Then support:
- 768px
- 1024px
- 1280px+
- 1440px

Do NOT design desktop first and merely shrink it.

Every important action must work comfortably on a phone.

Minimum requirements:
- No horizontal scrolling
- No tiny text
- No cramped buttons
- No overlapping content
- No broken Hindi characters
- No oversized desktop navigation
- Images must crop correctly
- Service cards must remain readable
- Buttons must be touch-friendly

---

# 14. Mobile Primary Actions

The three most important customer actions are:

1. Call
2. WhatsApp
3. Directions / Google Maps

Consider a fixed mobile bottom action bar:

    📞 Call    💬 WhatsApp    📍 Directions

It should not cover important content.

Ensure there is enough bottom padding when the bar is present.

---

# 15. Contact Forms

Do NOT create a complicated contact form by default.

This business is local and phone/WhatsApp communication is more practical.

Primary CTAs:
- Call
- WhatsApp
- Google Maps

If a form is ever added, it must have a strong business reason.

Do not add:
- Email signup
- Newsletter
- Lead-generation popup
- Unnecessary login
- Unnecessary account creation

---

# 16. Homepage Direction

The homepage should immediately answer:

1. What is this shop?
2. What services are available?
3. Where is it?
4. How do I contact them?

Suggested structure:

1. Header
2. Hero
3. Main service categories
4. Popular services
5. About the shop / real shop photo
6. How it works
7. Location and opening hours
8. Contact CTA
9. Footer

Do not make the homepage unnecessarily long.

---

# 17. Hero Section

The hero should be simple.

Possible direction:

    आपके ऑनलाइन काम, एक ही जगह।

    Your Local Digital Service Center

    MP Online • ऑनलाइन फॉर्म • सरकारी सेवाएं
    प्रमाण पत्र • प्रिंटिंग • डिजिटल सेवाएं

    [ WhatsApp ] [ Call Now ]

Do not use generic startup slogans.

Do not make the hero consume the entire screen on mobile.

A customer should be able to see useful services without excessive scrolling.

# 19. Service Cards

Service cards should be simple.

Example:

    जाति प्रमाण पत्र
    Caste Certificate

    ऑनलाइन आवेदन में सहायता

    [ WhatsApp पर पूछें ]

Use icons only when they improve recognition.

# 20. WhatsApp Behavior

WhatsApp is a primary conversion channel.

Where possible, use pre-filled messages.

Example:

    Hello, I want information about Caste Certificate service.

For Hindi-friendly users:

    नमस्ते, मुझे जाति प्रमाण पत्र की जानकारी चाहिए।

The message should identify the service.

Do not expose the client's private information unnecessarily.

---

# 21. Google Maps

The site should have a clear:

**📍 रास्ता देखें / Get Directions**

button.

It should open the actual business location.

Do not invent coordinates.

The exact map location must be supplied/confirmed by the client.

# 22. Business Information

Show clearly:

- Shop name
- Address
- Village/town
- District
- Phone
- WhatsApp
- Opening hours
- Weekly closing day if applicable
- Google Maps

Do not invent missing details.

---

# 23. Reviews

Do NOT create fake reviews.

Only add testimonials if the client supplies genuine customer reviews and approves their use.

If no genuine reviews exist:
- Omit the section
- Do not replace it with fake quotes

---

# 24. Pricing

Do NOT invent service charges.

If pricing is not provided:
- Do not display prices
- Use "Contact us for service charges" only if useful

Government fees and shop service charges must not be mixed together without clarification.

---

# 25. Accessibility

Ensure:
- Strong text/background contrast
- Readable Hindi
- Keyboard accessibility on desktop
- Visible focus states
- Alt text for meaningful images
- Buttons have understandable labels
- Touch targets are sufficiently large
- Do not rely only on color to communicate meaning

---

# 26. Performance

The website should be lightweight.

Prefer:
- Static frontend
- Optimized images
- Lazy-loaded below-the-fold images
- Minimal JavaScript
- No unnecessary dependencies
- No unnecessary API calls
- No heavy animation libraries unless genuinely needed

Target a fast experience on normal Indian mobile networks.

---

# 27. Technical Architecture

Preferred initial stack:

- React
- Vite
- JavaScript
- CSS or Tailwind CSS
- React Router only if multiple routes are genuinely required
- Lucide or another lightweight icon library if needed

Version 1 should NOT require:
- Backend server
- Database
- Authentication
- Redis
- Docker
- Express
- PostgreSQL
- MongoDB

Use static data for services unless the client later needs an admin system.

---

# 28. Deployment Architecture

Preferred:

GitHub
    ↓
Cloudflare Pages
    ↓
Production Website

The website should be static and should not depend on an always-running backend.

The objective is:
- ₹0 hosting cost for the initial version
- No server sleep/wake dependency
- HTTPS
- CDN delivery
- Automatic deployment from GitHub

Do not add backend infrastructure unless there is a real requirement.

# 32. Data Rules

Business data should be centralized.

For example:

    src/data/shop.js

If a phone number changes, it should be possible to update it in one place.

# 36. Final Authenticity Review

Before calling the website complete, ask:

### Does this look like the actual client's shop?

### Does the red/yellow identity feel connected to the real signboard?

### Does the website work naturally for a Hindi-speaking village customer?

### Can someone find Call, WhatsApp and Directions immediately?

### Are the client's real photos being used?

### Did we invent anything?

### Does any section look like an AI-generated SaaS template?

### Are there unnecessary animations or decorative elements?

### Does the website remain useful if the user only spends 20 seconds on it?

If any answer is wrong, fix it before completion.

---

# 37. Most Important Rule

## Specific beats fancy.

A simple website containing:
- the actual shop
- actual services
- actual photos
- actual location
- actual phone number
- natural Hindi
- easy WhatsApp

is better than a visually impressive generic website.

Build for the customer's real needs, not for design-award screenshots.
