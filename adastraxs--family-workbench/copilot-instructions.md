# 家庭工作台协作约定

本文件保存跨任务长期有效的项目约定。阶段进度、临时结论和可变任务放在
`docs/pending-tasks.md`，不要写入本文件。

## 沟通与产品取向

- 默认使用中文沟通。先说明结果和页面/数据会发生什么变化，再补充必要的技术细节。
- 面向家庭日常使用设计，页面文案应直白、可核查；普通成员能安全完成的查看操作，
  不应只藏在 Django 管理后台或命令行。
- 新增后台命令或自动任务时，同时判断是否需要网页入口、运行状态、错误提示和审计记录；
  管理员按钮不能替代正式的 NAS 定时任务。
- 需求存在小范围歧义时，优先依据现有模型、页面和数据查证后继续；会改变财务口径、
  生产数据或部署范围的选择必须先向用户确认。
- 不主动扩大需求范围。第五阶段分析功能以及其他新模块，只有用户明确选择后才开始。

## 财务数据与业务口径

- 交易流水是可审计事实，当前持仓是由有效流水重建的派生状态，快照是某一时点的估值结果；
  不以展示字段或汇总投影反向替代交易事实。
- 金额、数量、价格和汇率使用 `Decimal` 及明确精度，不使用二进制浮点数承载财务计算。
- 缺少价格、汇率或存在过期手工价格时必须明确列出，不得用 `1:1`、当天日期或其他猜测伪造
  “完整快照”。
- 同一估值日期的每日命令必须幂等：重复执行更新当日快照及明细，不新增重复记录。
- 历史回补先生成只读试算报告，经用户确认日期范围后，备份生产数据库，再仅对符合完整性要求
  的日期写入。
- 投资目标以 2025-12-31 正式资产快照为期初值；参数 `C` 是每半年新增投入，
  `R` 是预期半年收益率，`N` 是期数。参数修改只重算未来目标，已经过去的目标时点保持不变。
- Excel 中资产趋势图的示例数字不作为导入数据；家庭成员归属始终使用系统内成员 ID。
  用户本人和“徐总”视为同一系统成员。

## 生产数据安全

- NAS PostgreSQL 是生产数据源。除非用户明确要求数据库迁移或恢复，否则部署只更新代码和迁移，
  绝不使用本地数据库、dump、`postgres/` 或演示数据覆盖生产数据库。
- 任何生产写入、迁移、回补或部署前都先创建可验证的数据库备份，并记录备份文件、校验值和
  恢复点；操作前后核对关键表计数和最新快照日期。
- 优先先做只读检查。修改生产数据前必须明确目标日期、账户和影响范围；遇到异常停止并报告，
  不盲目试错。
- `.env`、密码、API Key、Futu 状态、数据库 dump、部署包、`backups/`、`postgres/` 和本地
  `outputs/` 报告均不得提交或在回复中泄露。用户临时提供的密码不得写入文件、命令历史或文档。
- 未跟踪文件默认属于本地数据或备份。提交前逐项检查，只暂存本次明确修改的源码和文档。

## NAS 部署

- 任何 NAS 访问、部署、备份、回滚、任务计划或生产验证，都必须先读取并遵循
  `$deploy-family-workbench-nas` 技能。
- 使用专用长期 SSH 公钥和权限受限的 root 部署包装器；不要重复搭建临时权限、索要已配置的
  密码或改用不受限 root/docker 权限。
- 部署应基于已提交的精确 commit 制作源码包，保留生产 `.env`、数据库卷、上传文件和 OpenD
  状态。部署完成后记录实际运行 commit。
- NAS 镜像源恢复前，若依赖清单没有变化，可按技能说明使用既有镜像配合新源码；如果 Python
  依赖发生变化，必须先解决镜像构建/拉取能力，不得把“源码已挂载”误当成“新依赖已安装”。
- 定时任务使用 Django 管理命令加 DSM Task Scheduler；在确有复杂编排需求前，不引入
  Celery、Redis 或独立任务系统。

## 开发与验证

- 修改前检查工作树并保护用户已有改动。使用 `rg` 搜索，使用补丁方式编辑文件。
- 数据模型变化必须包含迁移、服务层处理、页面/后台展示和针对性测试；GET 页面不得隐式抓行情
  或写数据库。
- 投资组合相关改动至少运行：

  ```text
  docker compose exec -T web python manage.py test ipo portfolio --keepdb
  docker compose exec -T web python manage.py check
  git diff --check
  ```

- 根据风险补充迁移检查、幂等性测试、权限隔离测试和浏览器页面验证。不能只以“命令成功”代替
  财务结果核对。
- 部署后检查容器健康、迁移状态、内部与外部访问、任务日志、关键数据基线和目标日期快照；
  定时任务失败应返回非零状态并保留日志。

## Git 与交付

- 功能修改在 `codex/` 前缀分支完成。未经用户明确要求，不改写历史、不强推、不删除本地备份。
- 提交只包含相关源码、迁移、测试和长期文档。推送失败时可按用户约定使用
  `127.0.0.1:7897` 代理，但不要把代理配置永久写入仓库。
- 完成部署后，应确保 NAS 运行 commit 已推送到 GitHub，避免生产代码只存在于本机和 NAS。
- 最终交付说明应包括：完成内容、测试结果、是否部署、生产数据库是否改动、当前运行 commit、
  已知限制和仍待确认事项。
