## Branch-Specific Setup

This is a **multi-branch boilerplate** with environment-specific configurations:

- **`main` / `cloudflare` (current)**: Cloudflare Workers API + D1 (SQLite) + KV (cache) + R2 (storage) + React SPA
  - API: Wrangler-based Hono workers (`apps/api/wrangler.jsonc`)
  - Database: Cloudflare D1 (SQLite) with migrations in `packages/db/drizzle/migrations`
  - Cache/Sessions: Cloudflare KV namespace
  - Storage: Cloudflare R2 bucket
  - Ideal for: Serverless projects, cost-effective deployments

- **`railway`**: Traditional backend + Postgres + Redis + Hono API
  - API: Hono on Node.js with Better Auth, Redis, and BullMQ
  - Database: Postgres (via Turso/libSQL)
  - Cache/Queues: Redis + BullMQ
  - Ideal for: Projects needing persistent workers, complex queuing, or traditional infrastructure

Both branches share:
- Frontend: React 19 + Vite (same `apps/client`)
- Shared packages: `packages/db`, `packages/ui`, configs
- Authentication: Better Auth with email/password + GitHub OAuth
- Billing: Stripe integration (via `@better-auth/stripe`)

## Commands

### Development

```bash
# Install dependencies (root)
pnpm install

# Run all (API + client) in dev mode
pnpm dev

# Run only API
pnpm dev:api

# Run only client
pnpm dev:web
# or
pnpm dev:client
```

### Database

```bash
# Generate Drizzle types from schema
pnpm db:generate

# Apply D1 migrations locally
pnpm db:migrate

# Apply D1 migrations to production
pnpm db:migrate:prod

# Open Drizzle Studio (local introspection)
pnpm db:studio

# Create D1 database (one-time local setup)
pnpm db:create
```

### Authentication

```bash
# Generate Better Auth schema types and routes
# Outputs to packages/db/src/schema/auth.ts
pnpm auth:generate
```

### Build & Lint

```bash
# Build all packages
pnpm build

# Lint all packages
pnpm lint

# Format code (Prettier)
pnpm format
```

### Stripe (development)

```bash
# Login to Stripe CLI (sets up project context)
pnpm login:stripe

# Forward Stripe webhooks to localhost:8787
pnpm dev:stripe
```

### Cloudflare Resources Setup (one-time)

```bash
# Create D1, KV, R2 resources locally
pnpm setup:local
```

## Path Aliases

All applications use these aliases (configured in `vite.config.ts` for client, `tsconfig.json`, and Hono):

- `@client` → `apps/client/src`
- `@api` → `apps/api/src`
- `@ui` → `packages/ui/src`
- `@workspace/db` → `packages/db/src`
- `@workspace/ui` → `packages/ui/src` (exported via package.json)

Use these consistently when importing across the monorepo.

## Key Architectural Patterns

### API Structure (Hono)

1. **Bindings Injection** (`middlewares/bindings.ts`): Cloudflare bindings (DB, KV, R2) are attached to Hono context via middleware
2. **Auth Middleware** (`middlewares/auth.ts`): Extracts and validates session from request (via KV or Better Auth)
3. **Rate Limiting** (`middlewares/rate-limit.ts`): Per-IP rate limiting (100 req/min default)
4. **Controllers**: Handle route logic, accept Hono context `c`, return responses
5. **Services**: Encapsulate business logic (Stripe payments, S3/R2 operations)
6. **Better Auth Integration** (`/auth/*` routes): All auth flows routed through Better Auth handler

### Client Structure (React Router)

- **Route-based pages**: `pages/` organized by route segment (`auth/`, `protected/`)
- **Layouts**: `AuthLayout` and `ProtectedLayout` wrap route groups
- **Providers**: Context providers (theme, notifications) at app root
- **React Query**: TanStack Query for server state management (API caching/synchronization)
- **i18n**: `i18next` with locale files in `locales/`
- **Services**: Axios-based API client to call backend routes

### Database (Drizzle)

- Single schema per branch (managed in `packages/db/src/schema/`)
- Migrations auto-generated by `drizzle-kit` and stored in `drizzle/migrations/`
- On Cloudflare branch: D1 (SQLite) migrations applied via `wrangler d1 migrations apply`
- Schema is typed (full TypeScript support for queries)

## Environment Variables

### API (`apps/api/.env`)

**Cloudflare Workers specific:**
- `ENVIRONMENT` - "development" or "production"
- `ALLOWED_ORIGINS` - CORS whitelist (comma-separated)
- `API_URL` - API base URL (for docs)
- `CLIENT_URL` - Frontend URL (CORS origin)

**Better Auth / Stripe:**
- `BETTER_AUTH_SECRET` - Random secret for auth signing
- `STRIPE_SECRET_KEY` - Stripe API key
- `STRIPE_WEBHOOK_SECRET` - Stripe webhook signing secret

**Social Auth (optional):**
- `GITHUB_CLIENT_ID` - GitHub OAuth app ID
- `GITHUB_CLIENT_SECRET` - GitHub OAuth app secret

**Email (optional):**
- `RESEND_API_KEY` - Resend email service key
- `NO_MARKETING_EMAIL_FROM` - Email sender address

### Client (`apps/client/.env`)

- `VITE_API_URL` - Backend API URL (used by Axios client)

## Common Development Tasks

### Running Locally

```bash
# Terminal 1: API (Cloudflare Workers)
pnpm dev:api
# Runs on http://localhost:8787

# Terminal 2: Client (Vite dev server)
pnpm dev:web
# Runs on http://localhost:5173
```

### Adding a New API Route

1. Create a **controller** in `apps/api/src/controllers/` (e.g., `my-feature.controller.ts`)
2. Import in `apps/api/src/index.ts` and register route:
   ```typescript
   app.get('/my-feature', async (c) => {
     const db = c.get('db');
     const controller = new MyFeatureController(db);
     return controller.handle(c);
   });
   ```
3. Restart API dev server

### Adding a Database Table

1. Edit `packages/db/src/schema/index.ts` (add table definition)
2. Run `pnpm db:generate` (generates types)
3. Run `pnpm db:migrate` (applies locally)
4. Commit both schema changes and generated migrations

### Adding a New Page

1. Create file in `apps/client/src/pages/` (e.g., `pages/protected/my-page.tsx`)
2. Add route in `apps/client/src/App.tsx`:
   ```typescript
   <Route path="/my-page" element={<MyPage />} />
   ```
3. Restart client dev server

### Switching to Railway Branch

To work with the `railway` branch setup (Postgres + Redis backend):

```bash
git checkout railway
pnpm install
# Environment setup differs; see apps/api/.env.example on that branch
pnpm dev
```

Key differences on `railway` branch:
- API uses Node.js Hono, not Workers
- Database is Postgres (via Turso/libSQL)
- Redis/BullMQ for persistent job queues
- No D1/KV/R2 bindings; use environment variables instead

## Quick Debugging

- **API logs**: Running `pnpm dev:api` shows Hono logs in terminal
- **Client errors**: Check browser dev tools console
- **Database issues**: Run `pnpm db:studio` to inspect D1 tables
- **Stripe webhooks**: Use `pnpm dev:stripe` to replay events locally

## Performance Notes

- Turbo caches build outputs; delete `.turbo/` if builds seem stale
- Vite handles hot module reloading for the client
- Cloudflare Workers have cold-start limitations; keep startup logic minimal
- D1 queries are serverless; consider caching frequently-accessed data in KV

## Type Safety

- API requires `better-auth-schema.ts` to be run via `pnpm auth:generate` when auth config changes
- Database schema changes require `pnpm db:generate` to update TypeScript types
- Client Vite config aliases must match `vite.config.ts` and `tsconfig.json`
