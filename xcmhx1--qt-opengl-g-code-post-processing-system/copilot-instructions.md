# AGENTS.md

本文件是修改本仓库时必须遵守的简短工作协议。
项目入口见 [README.md](./README.md)，详细文档导航见 [docs/index.md](./docs/index.md)。

## 1. 理解任务

- 开始修改前先理解用户目标。
- 明确用户动作、输入和预期结果。
- 不猜测不明确的业务需求。
- 无法从仓库确认的高风险歧义应先说明。
- 优先检查相关源码和文档。
- 使用 CodeGraph 时，结果必须结合源码确认。
- 不根据文件名、提交信息或目录名单独判断现状。

## 2. 保持简单

- 使用满足需求所需的最少代码。
- 不实现未要求的功能。
- 不增加无必要的抽象层。
- 不为单一辅助逻辑建立公共框架。
- 不保留新旧实现并行运行。
- 如果简单方案已经满足要求，不引入复杂方案。

## 3. 控制修改范围

- 只修改当前任务需要的内容。
- 不顺手重构、改格式或清理其他模块。
- 不覆盖用户已有修改。
- 遇到冲突的意外修改时停止并说明。
- 不使用破坏性 Git 命令。
- 不擅自修改或重写提交历史。
- 第三方代码默认不修改，除非问题明确位于其中。

## 4. 沿真实数据流工作

- 从用户动作或输入开始。
- 找到实际状态或数据变化。
- 找到最终用户可见结果或输出文件。
- 验证输入确实经过生产路径到达结果。
- Bug 应修复在最早产生错误的位置。
- 不在末端伪造或补偿错误结果。
- 不以日志文字代替实际业务状态。

## 5. 文档使用

- `README.md` 是项目入口。
- `docs/index.md` 是详细文档导航。
- 需求变化同步更新 `docs/requirements/`。
- 架构和实现文档将在后续阶段建立。
- 文档与源码冲突时，以当前生产源码和实际行为为准，并修正文档。
- 文档只记录可确认的当前事实，不写理想化能力。
- 文档直接陈述能力和边界，优先使用“仅”或“仅是”，避免先否定再强调。

## 6. 修改原则

- 保持现有代码风格。
- 新文件进入明确职责目录。
- 文件移动时同步项目文件和筛选器。
- 不提交本机缓存、生成文件、凭据和个人信息。
- 不声称执行了实际没有执行的操作。
- 不用无关修改掩盖问题。

## 7. 最终汇报

只汇报：

- 用户可见变化；
- 主要修改范围；
- 未解决问题；
- 是否创建提交。
