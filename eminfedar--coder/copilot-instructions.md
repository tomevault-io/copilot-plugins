# AGENTS.md

VSCode-like code editor in terminal. Rust + ratatui + tokio. Elm Architecture (Model / Msg / Cmd / update / view). **Code comments and UI text are in English.**

## Running

```bash
cargo run [dir]          # opens cwd if no dir is given
cargo build              # dev
cargo test               # unit tests (core/buffer, services/git)
cargo clippy             # lint (kept warning-free)
```

Environment: `CODER_ASCII=1` uses ASCII instead of Nerd Font icons. `CODER_EXTENSIONS` overrides extensions dir (default `~/.config/coder/extensions`).

## Architecture (Elm Architecture)

Single unidirectional loop, `src/main.rs::run()`:

```
event / async result  ->  Msg  ->  update(model, msg) -> Vec<Cmd>  ->  cmd::execute -> Msg (via tx)
                                        |
                                     Model changes  ->  ui::view(frame, model)
```

- **Model** (`app/model.rs`): all state. Pure data, no IO.
- **Msg** (`app/msg.rs`): input events + async results. Only input to `update`.
- **update** (`app/update/`): takes `Msg`, mutates `Model`, returns side-effect `Cmd`s. Synchronous, no IO.
- **Cmd** (`app/cmd.rs`): description of side effect. `execute()` runs on tokio, sends result back as `Msg` via `tx`.
- **view** (`ui/mod.rs`): draws `Model` with ratatui. Read-only.

Rule: IO and async live only inside `cmd::execute`. `update` never blocks (exception: `ReplaceDone` reads open buffers from disk with short synchronous `std::fs::read_to_string`).

### Layout sharing
`ui::compute_areas(model, area) -> Areas` computes layout once; both `view` and mouse hit-testing (`update::handle_mouse`) use same `Areas`. Mouse coordinate mapping always goes through it.

## Core concepts

- **Focus** (`Editor` / `Terminal` / `Sidebar` / `SearchInput` / `GitCommit` / `Find`): target of keyboard events. `keymap::resolve` branches on focus. `GitCommit` = commit-message input in git panel. `Find` = editor-embedded find/replace widget.
- **Tab**: open file = `Buffer` + `Highlighter` + `diff_mode`. `active_tab: Option<usize>`. `diff_mode` (opened from git panel) appends `(diff)` to tab title (`Tab.title()`) and paints line backgrounds in editor. Same file can open as two separate tabs, normal + diff: `tab_index_for` matches only **non-diff** tab (normal open never hijacks diff tab), `diff_tab_index_for` matches diff tab; `all_tabs_for` returns all tabs of a file (HEAD/save/replace updates apply to all). When new tab opens, highlighter set to active theme (`FileLoaded` → `set_theme(current_theme_name())`), so files opened after theme change color correctly too.
- **Config (persisted preferences)**: theme and settings written/read as TOML via `services::config`. On startup `Model::new` → `config::load()` + `apply_config()`. When theme or setting changes (`apply_theme`/settings toggle — keyboard nav, Enter, mouse) `Cmd::SaveConfig(model.config_snapshot())` sent.
- **Highlight cache**: `Model.active_hl`, keyed by `(tab_idx, buffer.version)`. `refresh_highlight()` called before render. When you change buffer externally (`ReplaceDone`, external reload, closing tab) call `model.invalidate_highlight()` — else goes stale (new buffer resets to version 0). `invalidate_highlight()` also resets git-mark cache.
- **Change-gutter cache**: `Model.active_git_marks` (line → `GutterKind`), `active_git_marks_key = (tab, version)`. `refresh_git_marks()` called before render (main loop), comparing live buffer against `Tab.head_text` (HEAD content) via `gutter_marks` — pure, no IO. For diff tab also fills `Model.active_deleted` via `deleted_blocks`. `head_text` loaded async (`Cmd::LoadHeadText` → `Msg::HeadTextLoaded`): refreshed for all open tabs when file opens and on every `GitStatusLoaded` (HEAD may have moved after commit/revert).
- **Buffer selection**: `anchor: Option<Cursor>`. `pre_move(extend)` — if extend true and no anchor, puts anchor at cursor. `set_cursor(c, extend)` used for mouse selection.
- **DragTarget**: `SidebarBorder` / `TerminalBorder` (resizing) / `EditorSelect` (mouse text selection) / `Scrollbar` (scrollbar thumb drag). Set on `Down`, cleared to `None` on `Up`.
- **Language extensions / LSP** (`Model.extensions`, `Model.lsp`, `Model.diagnostics`, `Model.completion`, `Model.pending_format`): `extensions` is `ExtensionRegistry` loaded once in `Model::new`. `lsp: LspState` holds `sessions` (language id → `LspHandle`), `starting`, `initialized` sets. Each running server is one async owner task (`services::lsp::start`, the `pty.rs` pattern) that Model reaches through handle's `to_server` channel — routed via `Cmd::LspSend` so `update` stays IO-free. Results come back as `Msg::Lsp*`. **Staleness** guarded everywhere by `Token = (tab, buffer.version)` (same idea as highlight cache): completion/format responses whose token no longer matches buffer are discarded. **UTF-16**: LSP positions count UTF-16 code units; rope uses char indices. Convert only in `update` via `Buffer::char_col_to_utf16`/`utf16_to_char_col`/`lsp_pos_to_char` (unit-tested with emoji) — never in async task.

## Features (implemented)

- **Language extensions (LSP + formatter + linter)**: per-language support declared as TOML manifest at `~/.config/coder/extensions/<name>/extension.toml` (`$CODER_EXTENSIONS` override) plus built-in defaults for Rust (`rust-analyzer`/`rustfmt`) and Python (`pyright-langserver`/`black`). Manifest lists `[[languages]]`, each with `extensions`, `[languages.lsp]` server, optional `[languages.formatter]` (stdin→stdout) and `[languages.linter]`. User installs binaries; editor orchestrates. Extensions panel (`ui/sidebar/extensions.rs`) lists installed extensions + capabilities and running servers (status glyph + diagnostic count).
  - **Diagnostics**: `textDocument/publishDiagnostics` → `Msg::LspDiagnostics` → `lsp::store_diagnostics` converts UTF-16 ranges to char cols, stores in `Model.diagnostics[path]`. Rendered in `ui/editor.rs`: severity-colored line number + colored underline squiggle (`overlay_diagnostics`, drawn before selection overlay); diagnostic under cursor shows in status bar (`Model::diagnostic_at_cursor`). Documents synced full-text: `didOpen` on `FileLoaded`/`LspInitialized`, **debounced** `didChange` (`edit()` → `Cmd::ScheduleDidChange` → `Msg::DidChangeDue`, sent only if buffer version still matches — so typing pauses coalesce), `didSave` on `FileSaved`, `didClose` when last tab of file closes.
  - **Autocomplete**: auto-triggered while typing identifier / after `.` (and `Ctrl+Space`); `lsp::request_completion` flushes current text then requests `textDocument/completion`. **Client filters, not server**: rust-analyzer (like most servers) returns every candidate at position and expects client to match against typed prefix — `filter_items` scores each item's `filterText` in tiers (exact-case prefix → case-insensitive prefix → substring → subsequence, non-matches dropped) and breaks ties with server's `sortText`. Filtered list opens `Model.completion` (guarded by token). Popup is **editor sub-mode**, not `Focus`: while `model.completion.is_some()`, `update` routes keys to `lsp::completion_key` first (Up/Down select, Enter/Tab accept, Esc dismiss; identifier keys/Backspace fall through and re-request; other keys dismiss). Accept selects typed prefix `[anchor, cursor]` and `insert_str` replaces it.
  - **Formatting**: `Ctrl+Alt+F` (`Action::Format`) or format-on-save. `lsp::request_format` prefers LSP server (`textDocument/formatting` → `Msg::LspFormatEdits` → `apply_text_edits`, applied end-first as one undo step), else standalone formatter tool (`Cmd::RunFormatterTool`, stdin→stdout → `Msg::FormatterOutput`). Format-on-save **defers** `WriteFile` until edits apply (`Model.pending_format.save_after`); formatter failure still writes original text so save not lost. Standalone linters run on save for LSP-less languages (`Cmd::RunLinterTool`, parsed as `line:col: message`).
- Tab close: `✕` on each tab, click to close (`TabHit::Close` -> `close_tab`). **Middle-click** anywhere on tab bar also closes that tab (`MouseButton::Middle` → `tab_at` → `close_tab`).
- Search + replace (sidebar SEARCH panel): `SearchState.field` (Query/Replace, switch with `Tab`), `use_regex` (`Ctrl+R`), `match_case`, `search_hidden`, `Enter` in Replace field = replace across all files. Regex mode supports `$1` group references; plain mode uses `NoExpand` literal. No icons in input boxes; dim placeholder when empty (`Find...`/`Replace...`). Below replace box are **Replace/Replace All** buttons (`two_button_line`/`two_button_hit`, split in half). Replace = replace in selected result's **file** (`Cmd::RunReplaceFile` → `search_replace_one`), Replace All = all files (`Cmd::RunReplace` → `search_replace_all`). Three checkboxes: **RegExp** (`Ctrl+R`), **Match Case** (`match_case` → `build_regex` `case_insensitive(!match_case)`), **Search Ignored & Hidden** (`search_hidden` → walker `hidden`/`git_ignore`/`git_exclude`/`ignore` all `!search_hidden`; when off, `.gitignore` + `.`-prefixed hidden files skipped). Checkbox click re-runs search live via `rerun_search`. Mouse target in one place: `ui::sidebar::search_hit` (`SearchHit`) → `update` Panel::Search arm. Body row layout (`base` = `panel_area().y`, first body row): query(0) blank(1) replace(2) blank(3) replace-btn(4) blank(5) regex(6) match-case(7) search-hidden(8) count(9) results(`base+SEARCH_HEADER_ROWS`, `SEARCH_HEADER_ROWS=10`). Each result spans **two rows**: file path `rel:line_no` (dim) then matched line (bright); selected result gets `th.selected_bg()` (bg_alt darkened 30%) on both rows. `per_page = list_h/2`; click maps `(y-start)/2` to result index.
- Mouse range selection: drag in editor (`DragTarget::EditorSelect`).
- Git branch: `⎇ {branch}` in git panel (`services/git.rs` `head().shorthand()`).
- Git diff tab: clicking file in git panel (or `Enter`) opens not separate diff view but `diff_mode=true` tab (`open_diff` → reuses existing diff tab or loads fresh one flagged via `pending_diff` with `Cmd::ReadFile`; flag set in `FileLoaded`). Title is `"name (diff)"`. In this tab changed lines highlighted with background: added/modified green (`theme.diff_add_bg`), deletion boundary red (`theme.diff_del_bg`); source is `active_git_marks`. Cursor line **not** background-filled (only its line number brightens); line background drawn only on changed lines of diff tab. Normal (non-diff) tab never paints line background — only left gutter bar shows (`active_is_diff()` distinguishes them). Render: `ui/editor.rs::render`. **Removed lines shown in diff tab as inline red virtual rows**: `git::deleted_blocks(old,new)` returns each hunk's removed old lines as `(anchor, lines)` (`anchor=Some(r)` → after line r, `None` → before first line; modification includes old line too). `refresh_git_marks` writes these into `Model.active_deleted` for diff tab. `Model::diff_rows()` weaves real buffer lines with `DiffRow::Deleted` rows; editor render, cursor position, selection overlay (`real_display_index`) and mouse mapping (`screen_row_to_line`/`editor_cursor_at`) all operate over these display rows. `scroll_y` stays in buffer-line units; `diff_start` converts to display offset. Removed line: empty line number + `-` marker + `theme.diff_del_bg` background (`deleted_row`). When diff tab first opens it scrolls first change to **top** of viewport: `FileLoaded` writes `pending_diff_scroll` flag, and in `HeadTextLoaded` (git marks computable once HEAD arrives) `refresh_git_marks` + move cursor to min line of `active_git_marks` via `goto_line` + `scroll_cursor_to_top` (`buffer.scroll_cursor_to_top`: `scroll_y=cursor.line`), then flag cleared (once only).
- Editor change gutter: 1-column marker left of line number (when file tracked by git, `git_gutter()`). Added/modified line = green bar (`▍`/ASCII `|`), deletion boundary = red (`▁`/`_`). `gutter_width` adds +1 for this column; `editor_text_x` and mouse mapping adjust automatically. Shows on every tab (even non-diff).
- Editor scrollbar: 1 column at far right of editor (`compute_areas` `Areas.scrollbar`). Thumb represents visible portion (`buf.scroll_y`/`line_count`). By mouse: click/drag thumb (`DragTarget::Scrollbar` → `scrollbar_jump`, centers clicked line), wheel over scrollbar also scrolls editor. Git changes drawn as marks at proportional rows on scrollbar (`active_git_marks` → line ratio): addition green, deletion red `─`/ASCII `-` (`render_scrollbar`).
- Git staging (VSCode-style): panel has `STAGED` and `CHANGES` headers. Changed files shown as **tree** like file explorer: each section (`tree_rows`) sorts entries by path and emits `GitRowKind::Dir { name, depth }` header rows for shared directory components (`▾` + indent); file rows show only base name (`entry_line`, indented by `depth`). `GitRowKind::Staged/Unstaged` now `{ idx, depth }`. On unstaged row last 4 columns are `↺` (revert, width-4) · space · `+` (stage, width-2); on staged row `-` (unstage, width-2). Under each header a bulk-action row: `Stage All +` for unstaged (`Cmd::GitStageAll` → `git add -A`), `Unstage All -` for staged (`Cmd::GitUnstageAll` → reset to HEAD); `Separator` line sits between action row and file list. Buttons by mouse: `git_hit` treats these columns as targets; bulk rows are `GitHit::StageAll`/`UnstageAll`. `GitStatus.selected` navigates combined `[staged..., unstaged...]` list (`nav_len`/`entry_at`). **Panel layout** (`git_layout`, top to bottom): branch row (`branch_y`, fixed at top; no `GitRowKind::Branch`, `render_git` draws it directly) · blank · fetch/pull/push row (`actions_y`) · commit message box (`input_top`, `COMMIT_INPUT_H`=4) · `Commit` button (`button_y`, no check icon) · blank · scrollable change list (`content_y`/`list_h`, runs to bottom of panel). Committing happens only on button click (`GitHit::CommitButton` → `git_commit`); in commit box **Enter does not commit**, inserts newline (`Action::GitCommitSubmit` → `commit_msg.push('\n')`), and `render_commit_box` draws message across multiple rows split on `\n`. Button active when message non-empty and something staged. Stage/unstage/commit `Cmd`s call `git.rs` functions on `spawn_blocking`, then refresh status.
- Git fetch/pull/push buttons: 3-cell button row directly above commit message box (`git_layout.actions_y`, `render_git_actions`). Left to right Fetch · Pull · Push; width split into thirds (`action_at_col` uses same thirds for hit-testing, `GitHit::Fetch/Pull/Push`). Enabled state: Fetch `has_remote`, Pull `has_upstream`, Push `can_push()` (= remote exists **and** (ahead>0 **or** no upstream)). Push label shows `Push ↑{ahead}`, Pull label `Pull ↓{behind}`. Disabled button dim (`fg_dim`/`tab_inactive_bg`), click is no-op; enabled button has `accent` background. `Cmd::GitFetch/GitPull/GitPush` → `git.rs` network functions on `spawn_blocking`, then status refreshes; result shown as transient toast (`Msg::Toast`).
- New file/folder: every directory row in file tree ends with two right-pinned buttons (new file at `width-4`, new folder at `width-2`, like git panel's stage/revert). Click opens `Dialog::input` name prompt (`DialogAction::NewFile`/`NewFolder`); confirm validates name (no `/`, `\`, `.`, `..`) and sends `Cmd::CreatePath`, which creates entry and re-scans parent dir into `Msg::DirScanned`.
- Revert confirmation: clicking `↺` does not run directly; `Dialog::ask` confirmation opens, on confirm `Cmd::GitRevert` sent (`DialogAction::GitRevert`).
- Theme picker: button in activity bar just below Extensions (`Panel::Themes`, part of `Panel::ALL`; drawn/hit-tested like normal icon). Clicking lists loaded themes in sidebar (`ThemesState { names, selected }`). Arrow keys (`nav`) and mouse click (`sidebar_click` → `theme_row_at`) call `Model::apply_theme(idx)`: `model.theme = highlight::theme_for(name)` (UI palette) + `highlighter.set_theme(name)` for every tab (syntax) + `invalidate_highlight()`. Change is live; UI immediately, active tab immediately, other tabs re-color when selected. Choice saved to TOML (`persist_config` → `Cmd::SaveConfig`) and restored on startup; with no saved value startup theme is `DEFAULT_THEME` (`base16-eighties.dark`). Theme sources: syntect defaults + embedded palettes (Dracula/Gruvbox/Nord/One Dark/Monokai/Tokyo Night/Catppuccin) + `.tmTheme` files under `~/.config/coder/themes`, `CODER_THEMES_DIR`, `assets/themes`.
- Settings panel (editor preferences): gear button in activity bar below Themes (`Panel::Settings`, part of `Panel::ALL`). `SettingsState` (`app/model.rs`) holds boolean preferences: `format_on_save`, `trim_trailing_whitespace`, `insert_final_newline` (`COUNT`/`label`/`value`/`toggle` helpers, `sidebar.settings`). Panel draws checkbox list (`render_settings`); arrow keys (`nav`) select row, `Enter`/click (`activate_selection` / `sidebar_click` → `settings_row_at`) `toggle`s it. On save (`Action::Save`) `apply_format_on_save` runs: when `format_on_save` on, `format_text` trims trailing whitespace and/or adds single trailing newline, applied via `Buffer::replace_all` (single undo step, no-op when nothing changed, bumps version and refreshes highlight cache). Shortcut: `Ctrl+,`. Setting change saved to TOML (`persist_config` → `Cmd::SaveConfig`), restored on startup.
- Double-click word selection: double-clicking word in editor selects it (`Model.last_click` = last left-click time/position, 400ms + same-cell threshold; `Buffer::select_word_at`, word = letter/digit/`_`). Double-click does not start drag selection.
- Editor-embedded find/replace (`ui/find.rs`, `FindState`/`FindField` in `app/model.rs`): `Ctrl+F` opens find, `Ctrl+H` opens find&replace widget top-right of editor; `Focus::Find`. Widget: find row `[query] {cur}/{total} ‹ › ✕`, in replace mode a `[replace] Replace Replace All` row below. `Esc` closes, `Enter` next (`Shift+Enter`/`↑` previous, `↓` next), `Tab` switches field. Matches ASCII case-insensitive, non-overlapping literals in active buffer (`find_matches`, `[start,end)` char indices in `FindState.matches`); current match selected and **vertically centered** in viewport (`center_cursor_in_view` → `buffer.center_cursor`; `recompute_find`/`find_select_current`/`find_step`). Prev/Next/Close and Replace/Replace All buttons by mouse (`ui::find::hit` → `handle_find_hit`); Replace replaces single match (`find_replace_one`, select then `insert_str`), Replace All replaces all in single undo step (`replace_all_text` + `Buffer::replace_all`). On open single-line selection pre-fills query. `recompute_find` runs when query/buffer changes.
- External change reload: filesystem watcher (`main.rs::spawn_watcher`, `notify` crate, recursive over workspace root) sends `Msg::DiskChanged(path)` on file modify/create. `update`: `reload_if_clean` reloads only if file open and its buffer has **no unsaved edits** (`!dirty`), issuing `Cmd::ReloadFile` → `Msg::FileReloaded`. `apply_reload` replaces content of every clean tab of that file (`Buffer::new`, cursor/scroll restored and clamped, `mark_saved`), refreshes HEAD via `Cmd::LoadHeadText`, invalidates highlight of active tab. Dirty tabs keep live text (never clobbered), and no-op reload (equal content — e.g. our own save) skipped so undo history preserved. When changed path inside `.git` (external `git commit`/stage/checkout, or embedded terminal), `update` also issues `Cmd::LoadGitStatus` so git panel's branch, ahead/behind counts and fetch/pull/push buttons refresh instead of going stale.
- Input caret blink: `█` caret in text inputs blinks via `Modifier::SLOW_BLINK`, terminal-driven (find widget, search-panel query/replace, git commit box). No timer/tick.
- Modal dialog (`ui/dialog.rs`): `Model.dialog: Option<Dialog>`. While open, `update` routes all keyboard/mouse to `dialog_key`/`dialog_mouse` (keymap/focus skipped). Three kinds: `Ask` (Yes/No), `Info` (OK), `Input` (OK/Cancel + text). Confirm → runs `dialog_confirm` action; cancel → `dialog_cancel`. `view` draws it on top.

## Shortcuts

Global: `Ctrl+Q` quit · `Ctrl+B` sidebar · `Ctrl+J` terminal · `Ctrl+W` close tab · `Ctrl+S` save · `Ctrl+F` find in editor · `Ctrl+H` replace in editor · `Ctrl+Shift+E/F/G/X` panel · `Ctrl+,` settings · `Ctrl+Tab` / `Ctrl+Shift+Tab` cycle tabs.
Find widget: `Esc` close · `Enter`/`↓` next · `Shift+Enter`/`↑` previous · `Tab` switch field.
Editor: arrows/Home/End/PageUp-Down (+Shift select) · `Ctrl+←/→` word jump (+Shift word select) · `Ctrl+C/X/V/Z/Y/A` · `Ctrl+Space` completions · `Ctrl+Alt+F` format · `Esc` clear selection.
Completion popup: `↑`/`↓` select · `Enter`/`Tab` accept · `Esc` dismiss (other keys keep typing and refresh list).
Search input: `Tab` switch field · `Ctrl+R` regex · `Enter` search/replace · arrows navigate results.
Git commit input: click commit box (`Focus::GitCommit`) · type · `Enter` inserts newline · click `Commit` button to commit · `Esc` to leave.

## When making changes

- New `Msg` -> add variant to `msg.rs` + match arm in `update/mod.rs`.
- New side effect -> `Cmd` variant in `cmd.rs` + `execute` arm; never do IO inside `update`.
- New shortcut -> `Action` in `keymap.rs` + `resolve_*`; handle in `update::apply_action`.
- Adding mouse target: get layout from `compute_areas`, add field to `Areas`. If you change render row layout, also update corresponding `*_row_at` hit-test offsets (`ui/sidebar/`).
- After changing buffer externally, call `invalidate_highlight()`.
- LSP: talk to server only through `Cmd::LspSend` (never IO in `update`). Convert LSP UTF-16 positions to/from char columns only in `update` via `Buffer` helpers; guard every response with its `Token`.
- **Keep this file current**: when architecture, directory map, or feature changes, edit AGENTS.md too.
