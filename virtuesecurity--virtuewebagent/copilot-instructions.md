## Shell Tools

The following tools are available and preferred over their standard equivalents:

- `rg` (ripgrep) — fast recursive content search; prefer over `grep -r`.

  **rg vs grep syntax differences** — never copy grep patterns into rg without adapting them:

  | Feature | grep (BRE/ERE) | rg |
  |---|---|---|
  | Alternation | `\|` (BRE) or `|` with `-E` | `|` always |
  | Literal `(` `)` | `(` `)` unescaped | `\(` `\)` |
  | Literal `{` `}` | `{` `}` unescaped | `\{` `\}` |
  | Word boundary | `\b` | `\b` (same) |
  | Case-insensitive | `-i` | `-i` (same) |
  | Line numbers | `-n` | `-n` (same) |
  | Ignore `.gitignore` | never | always (add `--no-ignore` to disable) |
  | Restrict to file glob | `--include=GLOB` | `-g GLOB` (`--include` is **not** an rg flag) |

  `grep -n "path:\|route:"` → `rg -n "path:|route:"` (alternation)  
  `grep -n "lazy("` → `rg -n "lazy\("` (literal paren)

  **rg parsing gotchas — these cause rg to dump `--help` or error instead of matching:**

  - **Pattern starts with `/` or `-`** (e.g. `/api/admin`, clumped short flags like `-iEn`): rg parses it as a flag and prints `--help` or `error parsing flag`. Fix: pass the pattern with `-e`, or put it after `--`:  
    `rg -n -e "/api/admin" app/`  or  `rg -n -- "-->" file`
  - **Large `{n,m}` quantifiers on minified bundles** raise `exceeds complexity limits` / invalid-UTF8 errors on long single-line or binary-ish files. Fix: fall back to binary-safe grep — `grep -aoE 'pat'` (regex) or `grep -aoF 'literal'` — or extract with a small inline Python `re.finditer` + slice.
  - Prefer **long flags** (`--only-matching --no-line-number`) over clumped short flags when a pattern or filename could be mistaken for an option.
- `fdfind` — fast file finder; prefer over `find` (Ubuntu package installs as `fdfind`, not `fd`)
- `batcat` — syntax-highlighted file viewer; prefer over `cat` when output is for reading (Ubuntu package installs as `batcat`, not `bat`)
- `jq` — JSON processor for filtering and transforming JSON output
- `yq` — YAML/JSON processor; prefer over manual YAML parsing
- `parallel` — run shell commands concurrently across inputs; prefer over sequential loops
- `sqlite3` — query SQLite databases directly from the shell
- `xmllint` — XML querying and formatting; prefer over regex-parsing XML
- `xxd` — hex dump; useful for binary and encoded data analysis
- `openssl` — TLS inspection, certificate parsing, and encoding/decoding

## Python Scripts

Python scripts have a shared virtual environment at `scripts/.venv`.

**Setup** — create the venv if it does not exist, then install the required packages:

```bash
python3 -m venv scripts/.venv
scripts/.venv/bin/pip install -r scripts/requirements.txt
```

**Installing additional packages** — install via the venv pip directly and update the requirements file:

```bash
scripts/.venv/bin/pip install <package>
echo "<package>" >> scripts/requirements.txt
```

**Running scripts** — use the venv Python directly; do not rely on `source activate` because shell state does not persist between tool calls:

```bash
scripts/.venv/bin/python scripts/<script>.py
```

If activation is needed for a multi-step shell chain, keep it in a single call:

```bash
source scripts/.venv/bin/activate && python scripts/<script>.py
```

## Phase 3 Reporting & Triage
Reports are generated by a **deterministic builder** — the report tasks just run it, they do not hand-author output.
- **Builder:** `scripts/build_phase3_report.py` — reads `findings/phase3/vulns/*.json`, `probe-results/*.json`, `test-results/*.json`, `findings/phase2/waf/*.json`, `project.json`, `crawl-results.json`, and the triage overlay. Modes: `--type confirmed` and `--type manual_validation` each emit a self-contained HTML dashboard + a Markdown projection; `--type audit` emits the reconciliation. Template: `scripts/report_template.html`. Run: `scripts/.venv/bin/python scripts/build_phase3_report.py --phase3-dir findings/phase3 --type confirmed` (stdlib only; images linked by default).
- **Report artifacts:** `findings/phase3/report-confirmed.{html,md}`, `report-manual-validation.{html,md}`, and `report-omissions.{md,json}` (reconciliation — lists any finding that did NOT reach a report and why).
- **False-positive / triage overlay:** `findings/phase3/false-positives.json` — **user-owned**, keyed by finding ID; the builder only READS it, so marks persist across regeneration and full re-runs. Never overwrite it from the pipeline. Statuses: `false_positive`/`duplicate` (excluded from counts, shown dimmed/struck + badge), `accepted_risk`/`confirmed_override` (counted + badge). Finding numbers are never reassigned when an item is triaged. Edit via `scripts/mark_false_positive.py --id <id> --reason "..." [--status ... --duplicate-of ...]` / `--remove` / `--list`, by asking the agent, or by hand. The HTML reports have an All / Hide triaged / Only triaged filter.
- **Pipeline tasks:** `report-confirmed`, `report-manual-validation`, `report-reconciliation` in `prompts/phase3/tasks.json` (run near the end, in that order).
