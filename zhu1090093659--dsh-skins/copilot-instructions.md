# dsh-skins Repository Instructions

This repository owns the skin center plugin and the built-in skin assets. A skin
is a pure asset directory under `skins/<id>/`: a v2 `skin.json` manifest plus
the CSS and asset files it references. Nothing in a skin executes.

## Common Commands

```sh
pnpm install
pnpm build
pnpm test
pnpm typecheck
pnpm skin-center:check   # validate every skin against the v2 contract
pnpm skin-hooks:check    # reviewed hook identities
```

## Rules

- New skins go in `skins/<id>/`, with a bilingual `README.md` + `README.zh.md`
  and `preview/light.jpg` + `preview/dark.jpg`. See [CONTRIBUTING.md](CONTRIBUTING.md).
- Only `skins/blue-fantasy` is in the npm `files` whitelist; every other skin is
  content built into the market and installed on demand.
- `src/reviewed-hooks.generated.ts` and `lib/index.js` are generated by
  `scripts/skin-hooks-registry.mjs` and must be regenerated when a skin's
  `skin.json` changes. The `pnpm build` + `git diff --exit-code -- lib` CI step
  is the gate.
- Use Conventional Commits (`feat(skins): add <name>`, `fix(skin-center): ...`).
  No emoji in code, comments, documentation, or commit messages.
- The integration branch is `main`. The renderer / Wallpaper Engine domain is
  owned by its own workflow; see `.github/pr-review-routes.json`.

## Agent Notes

Decision records live in [.agents/notes](.agents/notes/README.md). Read it before
changing how skin submissions are reviewed and merged.
