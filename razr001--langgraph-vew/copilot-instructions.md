# Repository Guidelines

## Project Structure & Module Organization

The package is under `cli/`. Production Python code lives in
`cli/langgraph_cli/`; `cli/langgraph_cli/cli.py` defines the Click command
surface, while modules such as `config.py`, `docker.py`, and `deploy.py` keep
their domain logic separate. Unit and integration tests are in
`cli/tests/unit_tests/` and `cli/tests/integration_tests/`. JSON schemas belong
in `cli/schemas/` and are regenerated by `cli/generate_schema.py`. The
`examples/`, `js-examples/`, `uv-examples/`, and monorepo example directories
are fixtures and runnable demonstrations; avoid changing them unless the
feature affects that packaging scenario.

## Build, Test, and Development Commands

Run commands from `cli/`:

- `uv sync` installs locked development, lint, and test dependencies.
- `uv run langgraph --help` runs the CLI directly from the checkout.
- `make test` runs unit tests; use `TEST=tests/unit_tests/test_config.py make test`
  for a focused run.
- `make test-integration` runs the slower CLI integration suite.
- `make lint` checks Ruff formatting/imports, Ruff rules, and `ty` types.
- `make format` applies Ruff formatting and import sorting.
- `make update-schema` regenerates committed JSON schemas after config-model
  changes.
- `uv build` creates source and wheel distributions through Hatchling.

## Coding Style & Naming Conventions

Target Python 3.10 and use four-space indentation. Ruff enforces pycodestyle,
Pyflakes, pyupgrade, bugbear, and isort rules; line length is not enforced.
Use `snake_case` for modules, functions, and variables, `PascalCase` for
classes, and `UPPER_SNAKE_CASE` for constants. Add type annotations to new
public and internal APIs, and keep Click wiring thin by moving reusable logic
into focused modules.

## Testing Guidelines

Tests use pytest with automatic async support and strict marker/config
validation. Name files `test_<area>.py` and test functions `test_<behavior>`.
Place isolated logic tests in `unit_tests`; reserve `integration_tests` for
subprocess, Docker, or end-to-end CLI behavior. Add regression coverage for
bug fixes and test both successful and invalid configuration paths where
applicable. No numeric coverage threshold is configured.

## Commit & Pull Request Guidelines

This checkout does not include Git history, so use concise, imperative commit
subjects, for example `Fix validation for uv workspaces`. Keep commits scoped
to one concern. Pull requests should explain the motivation and user-visible
effect, link relevant issues, list commands run, and note schema or example
updates. Include terminal output for CLI behavior changes; screenshots are
only useful for documentation or Studio-facing changes.

## Security & Configuration

Never commit API keys, `.env` files, or generated credentials. Treat Docker
command construction and config parsing as security-sensitive: validate
untrusted input and add negative tests for shell metacharacters and path
handling.
