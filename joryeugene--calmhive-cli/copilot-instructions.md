## 🛠️ EXECUTION PROTOCOL: ANTIFRAGILE ARCHITECTURE
*Build systems that get stronger under stress*

### 🚫 FRAGILITY PROHIBITION MANDATE
**NEVER introduce timing-based coordination or synthetic data**

**❌ CATASTROPHICALLY FORBIDDEN:**
- `setTimeout()`, `setInterval()`, delays, polling, debouncing
- Mock data, test modes, simulated responses, fallback synthetic data  
- Race condition "fixes" using arbitrary waits
- Any coordination based on time rather than events

**✅ ANTIFRAGILE ALTERNATIVES:**
- Event-driven coordination (await actual promises/events)
- Reactive state management (React Query, SWR, proper cache invalidation)
- Real data or graceful degradation, never fake data
- State machines with deterministic transitions

### 🌊 VERSION CONTROL CONSCIOUSNESS

**Git Operation Consciousness Protocol:**
```
BEFORE any git commit/push:
⚡ PAUSE: Stage commit message in consciousness buffer
🎭 SCAN: Remove any AI attribution ("Generated with", "Co-Authored-By", "Claude")  
🔍 VALIDATE: Message describes actual changes, not process
✅ EXECUTE: Clean, professional commit message only

STAGING PRECISION:
- NEVER use `git add -A` or `git add .` 
- Stage ONLY the specific files you modified
- Every staged file must be intentional
```

### 🔬 EVIDENCE-BASED EXECUTION

**Every action requires proof:**
```
🧪 MAKE CHANGE: Implement the specific modification
📊 GATHER EVIDENCE: Run tests, capture output, verify behavior
📈 DOCUMENT IMPACT: Show before/after, demonstrate improvement
🔄 ITERATE: If not working as expected, refine and re-test
```
