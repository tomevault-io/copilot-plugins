# cpsmart 开发约束

以下规则适用于所有后续开发、修复、评审与发布。实现前必须阅读，验证完成前不得宣称功能完成。

## 多屏幕是基本能力

- 所有窗口、鼠标、触控板、拖放、Quick Look、菜单和辅助功能交互，都必须同时支持主屏幕与任意副屏幕。
- 不得假定屏幕原点是 `(0, 0)`，也不得假定坐标一定为正数。副屏幕可能位于主屏幕的上、下、左、右，原点可能为负数。
- 不得混用 `NSView`、`NSWindow`、`NSScreen`、Core Graphics 与 Accessibility 的坐标。每次跨坐标系时必须显式转换。
- `NSView.hitTest(_:)` 接收的是父视图坐标；与自身 `bounds` 比较前，必须先转换到本地坐标。
- 浮窗和“关于”窗口应优先显示在鼠标所在屏幕，并使用该屏幕的 `visibleFrame`，不能固定使用主屏幕。
- 鼠标和触控板必须具有相同的单击、双击、选择和粘贴行为。
- 必须考虑不同缩放比例、菜单栏与 Dock 所在位置，以及窗口滚动后的卡片坐标。

## 完成定义

- 涉及界面或输入事件的改动，必须执行 `docs/MULTI_DISPLAY_TESTING.md` 中与改动相关的测试。
- 至少在主屏幕和一个副屏幕上验证：窗口位置、键盘浏览、搜索、Space 预览、单击选择、双击粘贴和关闭。
- 鼠标测试不能只验证第一张卡片；还要验证滚动容器中间和末尾的卡片。
- 自动化测试通过不等于多屏交互完成；发布包必须再做一次真实安装包人工验证。
- 未完成上述验证时，在提交说明或交付说明中明确写“未验证”，不能写“已修复”。

## 文档与提交

- 长期有效的设计约束写入 `AGENTS.md` 或 `docs/`；不要提交聊天记录、临时交接稿或 AI 指挥过程文档。
- README 面向用户，工程测试细节放在 `docs/`。
- PR 应在功能与安装包体验确认后整理，避免把中间试验提交带入上游。

## 截图与视觉验证

- 先确定需要验证的证据类型，不得把“先截一张看看”作为原生 macOS 界面的默认步骤。
- 窗口位置、尺寸、是否越界、屏幕归属、缩放比例、焦点以及键鼠流程，优先使用 `NSScreen`、WindowServer、辅助功能树和限定范围的自动化事件验证；这些证据已经足够时，不得额外截屏。
- 只有字体、颜色、留白、阴影、圆角、图片缩放质量等像素级效果需要判断时，才进入截图路线。用户提供或工作区中已有的图片文件，应直接使用图片查看工具检查。
- 主动截取 macOS 界面前，必须先用 `CGPreflightScreenCaptureAccess()` 检查权限。返回 `false` 时不得调用 `screencapture`；应改用应用自身的 Debug 视图快照，或请用户提供实际界面截图，并在交付说明中明确写“视觉未验证”。
- 屏幕录制权限属于发起捕获的宿主进程，而不是被测试的 `cpsmart`。当前 Codex 桌面环境的宿主是 `/Applications/ChatGPT.app`（bundle id `com.openai.codex`）；修改系统权限后必须完全退出并重新打开该宿主，再重新执行预检。
- 若预检为 `false`、WindowServer 能列出目标应用但窗口名称显示为受保护，并且捕获结果只有桌面背景，应直接判定为 macOS 屏幕录制隐私过滤，不得继续排查截图坐标、窗口编号或副屏位置，也不得重试截图。
- 预检为 `true` 后，先通过 WindowServer 枚举窗口，核对目标应用、窗口名称、窗口编号、层级、逻辑边界和是否在屏幕上；默认按明确的窗口编号捕获，不得先截取整个桌面再寻找目标。只有验证多窗口相对位置或跨屏整体布局时才允许捕获屏幕区域。
- 每个独立目标状态只进行一次有明确目标的捕获。主屏、副屏、不同预览内容或不同交互状态可以分别取证，但不得对同一状态更换参数重复碰运气。截图缺少目标窗口时，才排查窗口编号、坐标系、屏幕缩放、全屏 Space、窗口最小化或遮挡关系。
- 截图命令退出成功不等于视觉取证成功。必须检查文件存在且非空、像素尺寸合理，并实际打开图片确认目标窗口和内容可见；否则按失败处理。
- 截图像素尺寸可能包含 Retina 缩放和系统窗口阴影，不得直接替代 WindowServer 返回的逻辑窗口尺寸。尺寸、屏幕归属和越界判断仍以窗口几何信息为准。
- 窗口几何和交互验证不能冒充像素级视觉验证；反之，也不要为了已经由几何或交互证据回答的问题额外截图。
- 临时诊断截图只能写到临时目录，不得提交到仓库。真实安装包的主副屏人工视觉检查仍是发布前必测项。
